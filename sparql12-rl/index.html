摘要

本文档定义了 SPARQL-RL，一种 面向 RDF 的 Datalog 风格规则语言。

SPARQL-RL 通过针对输入 RDF 图对一组声明式 规则进行求值来生成新的 RDF 数据。规则使用一种 类似 SPARQL 的文本语法编写。

1. 引言

本文档介绍 SPARQL-RL。它是一种通过声明式规则 从现有 RDF 数据派生新 RDF 三元组的机制。 本文档定义了基于规则的推理的语法和语义。

SPARQL-RL 的实现提供以下一种或两种操作： 推理和查询。 推理操作将规则应用于给定的 基础图，并生成一个推理图，其中包含 由规则求值派生且未出现在基础图中的 RDF 三元组。 是否将推理图与基础图合并是可选的，并 由用户决定。 查询操作确定给定的 目标模式是否可以以及如何使用规则 从基础图派生出来。

SPARQL-RL 允许创建新的 RDF 术语，包括空白节点， 这些术语可以用于规则头中的三元组模板。

SPARQL-RL 还支持失败即否定，这可能导致 根据规则求值顺序的不同而产生 不同的推理图。为避免这种情况，规则使用 分层技术进行求值，该技术在规则之间建立顺序， 从而确保始终生成相同的推理图。

当上下文明确时，SPARQL-RL 可以称为 SRL。

3. SPARQL-RL 概述

本节为非规范性的。

给定一个 基础图和一个 规则集，SPARQL-RL 会推理出新的三元组。 求值的输出是一个 推理图，其中包含派生出的 未出现在基础图中的三元组。

每个 规则都有一个模式，称为主体，以及一个结果 模板，称为头部。 执行规则时，会查找主体中变量的值 使主体与合并后的基础图以及 到当前执行阶段为止的所有推理三元组相匹配。 然后使用这些值实例化 规则头中的三元组模板，以生成新的推理三元组。

规则会一直执行，直到不再推理出新的三元组， 并且随着新的推理三元组 可用，规则可能会执行多次。

SPARQL-RL 的执行定义确保规则执行顺序 在创建新的 RDF 术语时不会导致不同结果， 包括新的空白节点，或在测试某个 模式是否不存在时。换言之，都会生成相同的推理图， 无论规则执行顺序如何。

SPARQL-RL 具有受 SPARQL 1.2 查询语言启发的易于人类使用的语法。 规则集求值包含与 SPARQL 类似的元素，但在 细节上有所不同，以确保生成相同的推理图， 无论规则执行顺序如何。

本节中的示例描述软件组件及其 依赖关系：一个前端调用应用服务器，而 应用服务器查询一个存在已知 漏洞的数据库。

3.1 三元组模式

一个 三元组模式 与三元组数据进行匹配，以便为 变量赋值。该模式具有 三个元素，每个元素都是一个 RDF 术语、一个变量， 或者是一个 三元组术语 的包含变量的模式。

在第一个示例中，基础图和规则集中包含以下数据：

示例 1: 基本示例 
:frontend :callsService :app .
:app      :queriesDatabase :db .
:db       :hasVulnerability :vuln1 .
RULE { ?x :dependsOn ?y } WHERE { ?x :callsService ?y }
RULE { ?x :dependsOn ?y } WHERE { ?x :queriesDatabase ?y }
:frontend :dependsOn :app .
:app      :dependsOn :db .

将上述规则应用于数据，将得出以下结论： :frontend 依赖于 :app，而 :app 依赖于 :db，无论依赖关系的类型如何。

随后，我们可以通过添加一条依赖于 其他规则所生成的 :dependsOn 三元组的规则来推导 :exposedTo 关系 （另见下文的 4.3 规则 依赖）：

示例 2: 依赖于推断出的三元组 
:frontend :callsService :app .
:app      :queriesDatabase :db .
:db       :hasVulnerability :vuln1 .
RULE { ?x :dependsOn ?y } WHERE { ?x :callsService ?y }
RULE { ?x :dependsOn ?y } WHERE { ?x :queriesDatabase ?y }
RULE { ?x :exposedTo ?v } WHERE { ?x :dependsOn ?y . ?y :hasVulnerability ?v }
:app      :exposedTo :vuln1 .
:frontend :dependsOn :app .
:app      :dependsOn :db .

3.2 递归

上一节中的 :exposedTo 规则仅涉及直接 依赖：:frontend 并不直接依赖于 :db，因此 不会为 :frontend 推断出 :exposedTo 三元组。 为了沿任意长度的依赖链传播暴露关系，我们 将该规则替换为两条规则：组件暴露于其自身具有的 漏洞，并且组件也暴露于任何 其直接依赖项所暴露的漏洞：

示例 3: 规则递归 
:frontend :callsService :app .
:app      :queriesDatabase :db .
:db       :hasVulnerability :vuln1 .
RULE { ?x :dependsOn ?y } WHERE { ?x :callsService ?y }
RULE { ?x :dependsOn ?y } WHERE { ?x :queriesDatabase ?y }
RULE { ?x :exposedTo ?v } WHERE { ?x :hasVulnerability ?v }
RULE { ?x :exposedTo ?v } WHERE { ?x :dependsOn ?y . ?y :exposedTo ?v }
:db       :exposedTo :vuln1 .
:app      :exposedTo :vuln1 .
:frontend :exposedTo :vuln1 .
:frontend :dependsOn :app .
:app      :dependsOn :db .

与前一个示例相比，这里增加了 :db :exposedTo :vuln1 — 数据库暴露于其 自身的漏洞 — 以及 :frontend :exposedTo :vuln1： 暴露关系通过依赖链到达 :frontend ，无论该依赖链有多长。

最后一条规则是一条递归规则：规则体 依赖于规则头。

3.3 过滤

我们可以在规则体中使用表达式来限制变量的值 ，这些变量用于规则体的匹配。 例如，给定每个漏洞的严重程度， 我们可以为暴露于严重 漏洞的组件赋予一个状态：

示例 4: 过滤 
:app1 :exposedTo :vuln1 .
:app2 :exposedTo :vuln2 .
:vuln1 :severity 9.1 .
:vuln2 :severity 4.3 .
RULE { ?x :status :criticallyExposed }
WHERE {
    ?x :exposedTo ?v .
    ?v :severity ?s .
    FILTER(?s >= 9.0)
}
:app1 :status :criticallyExposed .

FILTER 对表达式求值，并保留当前的 变量绑定集合（如果表达式求值为真），而它会丢弃 当前的变量绑定集合（如果表达式求值为假）。 这与 FILTER 这一 SPARQL 操作相同 ，并且 SPARQL-RL 提供了许多与 SPARQL 相同的函数和运算符。

3.4 否定

否定用于指定一个不得匹配的模式。 这称为“失败即否定”。

为了对否定元素求值，规则集求值算法 确保所有可能生成与该模式匹配的三元组的规则 都已执行完毕，该模式位于否定元素中。这称为 分层，并确保否定所依据的是 所有相关的可能三元组，无论它们来自数据还是 来自其他规则。包含否定的规则 被称为依赖于生成这些三元组的规则 （参见下文的 4.3 规则 依赖）。

示例 5: 失败即否定 
:app rdf:type :Component ;
    :status :criticallyExposed .

:logger rdf:type :Component .
RULE { ?x :status :safeToDeploy }
WHERE {
    ?x rdf:type :Component .
    NOT { ?x :status :criticallyExposed }
}
:logger :status :safeToDeploy .

3.5 赋值与创建 RDF 术语

赋值允许规则将表达式的结果赋给一个变量 ，该变量位于规则体中。这可用于创建新的 RDF 术语，其依据 是数据。

示例 6: 赋值 
RULE { ?v :riskScore ?r }
WHERE {
    ?v :severity ?s .
    ?v :exploitLikelihood ?p .
    SET ( ?r := ?s * ?p )
}

空白节点可以用于规则头，并且每个空白节点都会生成一个全新的空白节点 ，每当规则求值生成三元组时都是如此。

示例 7: 规则头中的空白节点 
RULE { [] rdf:type :Notification ; :concerns ?x }
WHERE { ?x :status :criticallyExposed }

涉及 赋值 的规则、创建空白节点的规则 （通过对 规则头 求值），以及具有模板的规则 （该模板涉及一个 三元组术语，其中包含 变量） 都是 仅运行一次的规则。 此类规则在所有可能生成其所依赖数据的规则之后运行， 并且在任何依赖于其所生成数据的规则之前运行。

此条件确保此类规则不会循环回到自身 ，从而导致创建无界数量的 RDF 术语。

注

一个常量 RDF 术语 位于一个 规则头 中，并不会 使规则成为 仅运行一次的规则，即使该术语未出现在 基础图 中：该规则每次都会贡献相同的术语，当它被 求值时，因此它只能添加有界数量的术语。

如果对某个 赋值 中的表达式求值导致错误， 则当前解映射会被该 赋值 拒绝。

3.6 分组与聚合

议题 840: 扩展 SRL 以纳入聚合 需要工作组意见/决定SPARQL-RL

提供 GROUP BY 和 聚合函数。 这至少涵盖 COUNT、COUNT DISTINCT、MIN、MAX，以及 SUM。

具有 聚合元素 的规则是 仅运行一次的规则。 此类规则在所有可能生成其 所依赖数据的规则之后运行，并在任何依赖于其所生成数据的规则之前运行。 一个 聚合元素 消费完整的 解序列 集合，这些序列来自前面的 规则元素 ，它们位于 规则体 中，并将这些序列分组，依据的是 分组键，然后求值

输出是一个 解序列，其中每个 [解映射=] 包含 分组键 和 聚合赋值。

3.7 导入规则集

一个 SPARQL-RL 规则集 可以纳入其他规则集，方式是 将其 URL 包含在该规则集的 规则集导入 中。 这允许将规则组织成可在规则集之间共享的库。

规则集的 IMPORTS 语句会先被处理，然后才会对 规则集中的任何规则求值。在导入步骤中，如果导入的规则集 自身也有导入项，则这些导入项也会被递归处理。 在处理规则集期间遍历 IMPORTS 语句时，可能 遇到循环导入。一个规则集只会被导入一次； 导入语句图中的环不会导致无限循环。

对导入规则集的支持是可选的，对于 SPARQL-RL 处理器 而言。 参见 4.5 处理 导入 以了解更多详细信息。

3.8 数据块

数据块直接为规则集求值提供 RDF 三元组。 数据块中的三元组会被添加到推断图中，并可用于 规则体中的匹配。

例如，规则集可以附带已知事实，这些事实是直接 断言的，而非从数据中推导出的：

示例 8: 在规则集中包含数据 
DATA {
    # 2.0.0 及更早版本存在一个已知漏洞
    # 并被假定为处于严重暴露状态。
    :appV2 rdf:type :Component ;
           :version "2.0.0" ;
           :status :criticallyExposed .
}
注

数据块等价于规则体为空的规则： 其三元组是推断图的一部分，无需对任何规则 求值。

3.9 匹配基础数据

在 规则集求值 期间，可能 需要仅对原始的 基础图 进行模式匹配， 而不对任何推断出的三元组进行匹配。

设置默认值就是一个例子。 规则必须测试基础图是否已包含某个值，如果没有， 则该规则可以计算一个默认值。

示例 9: 使用 NOT 的基础数据 
:A :distanceMiles 5 .
:A :distanceKilometers 8 .
:B :distanceMiles 10 .
RULE  { ?x :distanceKilometers ?kilometers }
WHERE {
    ?x :distanceMiles ?miles .
    NOT DATA { ?x :distanceKilometers ?km }
    SET ( ?kilometers := xsd:integer(?miles *  1.60934))
}
:B :distanceKilometers 16 .

使用 NOT DATA 允许规则体的其他部分匹配推断出的三元组。 也可以执行所有 规则体 匹配，针对 基础图，方法是 使用 WHERE DATA。 此类规则便仅依赖于来自基础图的匹配。

示例 10: 使用 WHERE 的基础数据 
RULE  { ?x :distanceKilometers ?kilometers }
WHERE DATA {
    ?x :distanceMiles ?miles .
    NOT { ?x :distanceKilometers ?km }
    SET ( ?kilometers := xsd:integer(?miles *  1.60934))
}
注

本节中的匹配针对的是 基础图。 它不包括由 规则集求值 从 规则集 DATA 块添加的三元组 （3.8 数据块）。

3.10 规则集求值

规则被组织成 规则集。 一个规则集和一个数据图（即 基础图）是求值的输入。 输出是一个图，称为 推断图， 它是求值过程生成的三元组的集合 ，这些三元组未出现在 基础图 中。

在求值期间，基于一条规则推断出的三元组 可用于其他规则中的匹配。 规则集求值持续进行，直到 无法再推断出更多三元组 ，这些推断以 规则集 和 基础图 为输入。

求值首先执行以下步骤来 准备规则集 ，然后才对规则本身求值：

  1. 在支持导入的情况下，解析输入规则集的导入项，以形成一个 规则集，其中包含所有 导入的规则集中的全部规则。 如果任何导入项不可被接受，处理器会发出错误信号 ，由处理器判定（4.5 处理导入）。
  2. 检查每条规则是否都是 良构规则。
  3. 计算 依赖图。
  4. 一个 分层 被计算出来 （4.4 分层） ，使得 否定元素 和 仅运行一次的规则 产生一致的、 可预测的结果。分层 涉及检查 依赖关系 ，这些关系存在于规则之间 （4.3.1 依赖 图）。

一旦一个 规则集 准备完毕，求值便继续进行 ，依次取出每个 层，按分层中的顺序， 对该层中的规则求值直至完成， 然后继续处理下一层。 当执行规则推断出三元组时，这些三元组会立即 可供其他规则在执行时使用。

4. SPARQL-RL 抽象语法

SPARQL-RL 抽象语法是 SPARQL-RL 的逻辑结构。 它用于定义 SPARQL-RL 的执行算法。

4.1 抽象语法的元素

变量
一个 变量 表示一个可能的 RDF 术语，位于三元组模式中。 变量也用于 表达式。
表达式
一个 表达式 是一个 RDF 术语、一个 变量， 或者是将函数或函数形式应用于实参， 其中每个实参本身都是一个 表达式。 表达式相对于一个 解映射 求值，得到 一个 RDF 术语 作为结果，或者求值导致 错误。 表达式 兼容 SPARQL 表达式。
数据块
一个 数据块 是一组三元组。 这些三元组作为附加事实被添加到推断图中，并被 纳入推断过程。
三元组模式
一个 三元组模式 是一个三元组，其中每个元素都是 一个 变量、一个 RDF 术语，或者是一个模式，用于 三元组术语，其中含有 变量。 该元组的第二个元素必须是一个 IRI 或一个 变量。 三元组模式 出现在 规则体 中，该规则体属于一条 规则 ，并用于匹配 RDF 三元组。
三元组模板

一个 三元组模板 是一个三元组，其中每个元素都是 一个 变量、一个 RDF 术语，或者是一个模板，用于 三元组术语，其中含有 变量。 该元组的第二个元素必须是一个 IRI 或一个 变量。 三元组模板 出现在 规则头 中，该规则头属于一条 规则，并且 用于生成 RDF 三元组。

注

一个模式或模板，用于 三元组术语，其中没有 变量 出现，则它是一个 三元组术语，因此也是 一个 RDF 术语。

过滤元素
一个 过滤元素 是一个 表达式 ，它作为一个 规则元素 出现。 它用于限制变量的值 ，用于模式匹配时。
三元组模式元素
一个 三元组模式元素 是一个 三元组模式 ，它作为一个 规则元素 出现。
否定元素
一个 否定元素 是一个 规则元素。 它具有一个 否定元素体 ，由一个序列组成，其中包含 三元组模式元素 和 过滤元素。 一个 否定元素 具有 一个 标志， .evaldata， 用于指示使用哪个图来匹配 该 否定元素体。
赋值 元素
一个 赋值元素 是一个 规则元素，它是 一个有序对，组成部分 为一个 变量，称为 赋值变量， 以及一个 表达式，称为 赋值表达式。
聚合元素
一个 聚合元素 是一个 规则元素 ，具有 聚合键、 一个 聚合模式 和一组 聚合赋值。 每个 聚合赋值 都是一个有序对，其组成部分为 一个 变量，称为 聚合变量， 以及一个 聚合函数。 该 聚合模式 由一个序列组成 ，其中包含 三元组模式元素 和 过滤元素。
规则元素
一个 规则元素 是以下任意一种： 三元组模式元素、 过滤元素、 否定元素、 赋值元素，或 聚合元素。
规则头
一个 规则头 是一个序列，其中包含 三元组 模板。
规则体
一个 规则体 是一个序列，其中包含 规则元素； 也就是说，每个序列元素是以下之一： 一个 三元组模式元素、 一个 过滤元素、 一个 否定元素、 一个 赋值元素，或 一个 聚合元素。
规则集导入
规则集导入（通常简称为“导入”）是 URL 的集合 ，来自 IMPORTS 语句 ，指向将在求值期间纳入的其他规则集。
规则
一条 规则 包含一个 规则头（通常简称为 “头”）、 一个 规则体（通常简称为“体”）， 以及 一个标志 .evaldata ，用于指示使用哪个 图来匹配 三元组模式，这些模式位于规则体中。 可以为规则指定一个 URI 或空白节点，以帮助标识它。
仅运行一次的规则

一条 仅运行一次的规则 是恰好运行一次的规则，运行于 规则集求值过程中的某个特定时点。 一条 规则 是一条 仅运行一次的 规则，如果以下任一条件成立：

  • 该 规则体 具有一个 赋值元素；
  • 该 规则体 具有一个 聚合元素；
  • 一个 三元组模板，属于该 规则头，具有一个 空白节点；
  • 一个 三元组模板，属于该 规则头，具有一个模板，用于 三元组术语，其中有一个 变量 出现。
一般规则
一条 一般规则 是一条不属于 仅运行一次的规则 的规则。 一般规则在规则集求值期间可以运行多次。
规则集
一个 规则集 是零条或多条 规则 的集合、 零个或多个 数据块 的集合， 以及零个或多个 规则集导入 的集合。 一个 已解析 规则集 是一个 规则集 ，其中没有导入项。 一个 已解析规则集 是从另一个 规则集 创建的 ，通过应用 导入过程。
基础图
一个 基础图 是一个 RDF 图，作为输入提供给 求值过程。
推断 图
一个 推断图 是一个 RDF 图，由 一次 规则集求值 生成。 它包含所有未出现在 基础图 中的推断三元组 ，这些三元组通过应用 规则集 于 基础图 而推断出。
规则集 求值
一次 规则集求值 是应用一个 规则集 于一个 基础图 以生成一个 推断 图 的过程。 一次 规则 求值 是对一条规则求值一次的过程。 对规则求值会生成由 规则头 给出的所有三元组 ，通过对 规则体 求值，无论某个 三元组是否位于 基础图 中、已在 规则集求值 期间推断出， 还是一个新推断出的三元组。 在 规则集求值 期间，一条规则可以被求值 多次。

SPARQL-RL 提供两个操作，推断 和 查询。

推断
推断 是将一个 规则集 应用于给定的 基础图 并生成一个 推断图 的操作，该图包含推断出的 三元组。它应用完整的 规则集求值。
查询

查询 是确定给定模式是否 可从一个 基础图 推导出的操作，使用该 规则集，并 返回一个 解序列，其中每个 解映射 为变量给出 RDF 术语。

查询 的效果相当于执行一次 推断 操作， 然后将目标模式与合并后的 基础图 和 推断 图 进行匹配。

该 查询 操作可以不对所有规则求值；而是，它 可以只对回答查询所必需的规则求值 ，以满足查询目标。

SPARQL-RL 处理器
一个 SPARQL-RL 处理器 是一个实现了 SPARQL-RL 规范的系统，能够对 规则集 求值，并提供一个或两个 操作，即 推断 和 查询。

在一个 三元组模式 或一个 三元组 模板 中， 元组的位置 1 非正式地称为主语， 位置 2 非正式地称为谓语，而 位置 3 非正式地称为宾语。

4.2 良构性条件

良构性 是对抽象语法的一组条件，适用于 一个 规则集。这些条件共同确保 一个 变量，位于 规则头 中，其值已在 规则体 中定义； 每个变量，位于一个 过滤元素 或 赋值表达式 中， 在求值时都有一个值； 并且每个 赋值变量 和 聚合变量 在规则中都是新的，且此前未在规则体中使用过。

令 elti 为一个序列的第 i 个元素，该序列由 规则元素 组成，并令 N 为该 序列的长度。

令 V0 为该序列的初始变量。

令 Vi，其中 i 从 1 到 N， 为变量的集合，这些变量在作用域内，位于元素 elti 之后。

令 Vall 为以下变量的值： VN。

归纳定义 Vi：

  • 如果 elti 是一个 三元组模式元素 且 X 是出现在该 三元组模式元素 中的变量集合， 则
    • Vi 是集合 X ∪ Vi-1。
  • 如果 elti 是一个 赋值元素 ，其 赋值变量 为 avar，则
    • Vi 是集合 { avar } ∪ Vi-1。
  • 如果 elti 是一个 聚合元素 ，其中 aggGroupKeys 是出现在 聚合键 中的变量集合 ，且集合 aggVar 是 聚合变量 的集合， 则
    • Vi 是集合 aggGroupKeys ∪ aggVar。
      注

      聚合会替换变量集合，这些变量 在作用域内。

  • 否则，
    • Vi 等于集合 Vi-1。

一个由 规则元素 组成的序列 是一个 良构序列， 给定变量集合 V0， 如果以下条件对每个 i 均成立， 其中 i 从 1 到 N：

  • 如果 elti 是一个 过滤 元素，则
    • 每个 变量，若在该 过滤元素 中提及， 都是 Vi-1 的元素。
  • 如果 elti 是一个 赋值元素，则
    • 每个在该 赋值表达式 中提及的变量 都是 Vi-1 的元素
    • 该 赋值变量 不是 Vi-1 的元素。
  • 如果 elti 是一个 否定元素，则
    • 由 规则元素 组成的序列，位于 否定元素 体 中，是一个 良构 序列， 将 V0 设置为 Vi-1 的值。
  • 如果 elti 是一个 聚合元素，则
    • 由 规则元素 组成的序列，位于 聚合模式 中，是一个 良构 序列， 将 V0 设置为 Vi-1 的值。
    • 这些 聚合键 都是以下集合的元素： Vall，属于该 聚合模式。
    • 没有任何 聚合 变量 出现在变量集合 Vi-1 中。
    • 没有任何 聚合 变量 出现在以下集合中：聚合 键。
    • 这些 聚合 变量 互不相同。
    • 这些 变量，位于聚合函数中，均出现 于 聚合模式的 Vall 中。

一条 规则 是一条 良构 规则 ，如果由 规则元素 组成的序列，属于该 规则体， 是一个 良构序列，初始时 V0 为空集， 并且每个变量，位于一个 三元组模板 中，该模板属于 规则头， 都是 Vall 的元素。

一个 规则集 是一个 良构规则集，当且仅当所有 该规则集中的规则都是 良构规则。

4.3 规则依赖

规则 R1 依赖于规则 R2，如果第二条规则的输出 影响第一条规则的规则体求值。也就是说，R2 的规则头 具有一个 三元组模板，它能够生成一个三元组，该三元组匹配 一个 三元组模式，该模式位于 R1 的规则体中， 或者作为一个 三元组模式元素，或者位于一个 否定元素 或一个 聚合模式 内部。

依赖有两种： 封闭依赖 和 开放 依赖。 一个封闭依赖确保规则 R2 在规则 R1 执行之前已生成其所有可能的输出。 如果规则依赖不是封闭的，则它是一个开放依赖。 它允许第一条规则 R1 执行 ，同时规则 R2 仍可能再次运行以生成更多三元组 ，这些三元组随后可能使 R1 使用来自 R2 的新三元组重新求值。

标志 .evaldata 设置为 false 的规则使用 基础图 进行匹配，并且该规则没有依赖。

在第一个示例中，第一条规则具有一个开放依赖 ，依赖于第二条规则。

示例 11: 开放依赖 
RULE { ?x :exposedTo ?v } WHERE { ?x :dependsOn ?y . ?y :hasVulnerability ?v }
RULE { ?x :dependsOn ?y } WHERE { ?x :callsService ?y }

在第二个示例中，第一条规则具有一个封闭依赖 ，依赖于第二条规则：三元组模式 ?x :status :criticallyExposed 出现在一个 否定元素 内部，该元素属于第一条规则，并且该模式 匹配一个 三元组模板，该模板位于第二条规则的规则头中。 第一条规则不能求值，直到第二条规则 已生成其所有可能的输出。

示例 12: 封闭依赖 
RULE { ?x :status :safeToDeploy }
WHERE { ?x rdf:type :Component . NOT { ?x :status :criticallyExposed } }

RULE { ?x :status :criticallyExposed } WHERE { ?x :exposedTo ?v }
三元组模式匹配

一个 三元组模式 匹配一个 三元组模板，如果 该三元组模板能够 生成 一个三元组，该三元组 匹配 该三元组模式。

三元组模式依赖

一个 三元组模式 依赖于 一个 三元组模板 ，如果该 三元组模式 能够 匹配 该 三元组模板。

规则依赖

规则 R1 依赖 于 规则 R2，如果 R1.evaldata 为 true 且任意 三元组 模式，位于 R1 的规则体中， 无论是作为一个 三元组模式元素， 还是位于一个 否定元素 neg 内部，其中 neg.evaldata 为 true， 或者位于一个 聚合模式 内部， 依赖于一个 三元组模板 ，该模板位于 R2 的规则头中。

封闭依赖

一个 规则依赖，由规则 R1 依赖于规则 R2，是一个 封闭依赖 ，如果以下任一条件成立：

  • 一个 三元组模式，出现在一个 否定元素 内部，该元素属于 R1，其中该 否定元素 的标志 .evaldata 为 true ，该模式匹配一个 三元组模板，该模板位于 规则头 中，属于 R2。
  • 规则 R1 依赖于 规则 R2 且 R1 是一条 仅运行一次的规则。
开放依赖

一个 规则依赖，由规则 R1 依赖于规则 R2， 是一个 开放依赖，如果该依赖不是一个 封闭依赖。

如果存在三元组模板变量的值，使得在模板中用值替换变量 得到一个三元组 T2，其中 T2 与 T1 相等，则一个三元组模板可以生成一个 RDF 三元组 T1。

类似地，如果存在一组变量值，使得将三元组模式中的变量替换为这些值后，匹配三元组 T1， 则该变量值必须使 三元组模式中的变量被替换，包括 将空白节点视为 变量， 从而得到三元组 T2，其中 T2 与 T1 相等 。

如果一个变量在三元组 模板 或三元组模式中使用多次，则使用相同的 RDF 术语 作为替换项。

在三元组模式中用 RDF 术语替换变量 包括替换三元组术语内部的变量。

4.3.1 依赖图

规则之间的依赖表示为一个有向图， 称为依赖图。 图的顶点是规则集中的规则，而边 根据依赖是开放依赖还是闭合依赖， 分别标记为开放或闭合。

依赖图
一个规则集的依赖图是一个有向图，其中每个 顶点都是该规则集中的一个规则，并且如果规则 R1 依赖于规则 R2，则存在一条从规则 R1 到规则 R2 的边。 该边根据依赖 是开放依赖还是闭合依赖， 分别标记为开放 或闭合。
传递规则依赖
如果在依赖图中存在一条从 R1 到 R2 的路径， 则规则 R1 对规则 R2 具有传递依赖。
递归规则依赖

如果依赖图中存在一条涉及 R 的 循环路径，则规则 R 具有递归依赖。

注

依赖图不受基础图影响。

4.3.2 依赖图算法

以下算法给出了 从一个规则集构建依赖 图的一种可能方法。一致性取决于生成符合依赖图定义的依赖图， 而不是使用此过程。 

define mergeLabel(oldLabel, newLabel):
    # 封闭依赖覆盖开放依赖。
    if oldLabel == "open" and newLabel == "open":
        the result is "open"
    else:
        the result is "closed"
    endif
enddefine

# output -- 以规则为顶点、边带有标签的依赖图。
define buildDependencyGraph(ruleSet):
    # edgeLabelMap 将 (R1, R2) 映射到 "open" 或 "closed"
    let edgeLabelMap be a map from pair (rule, rule) to label

    foreach rule R1 in ruleSet.rules:
        let bodyDependencies = {}

        if R1.evaldata then:
            # 将规则中的每个三元组模式 TP 分类为需要 "open" 或 "closed"
            # ，具体取决于它是否位于否定元素或聚合
            # 模式中。
            foreach rule element RBE in R1.body:
                if RBE is a triple pattern element of triple pattern TP:
                    let item be a pair (TP, "open")
                    add item to bodyDependencies
                else if RBE is a filter element:
                    # 不执行任何操作
                else if RBE is a negation element:
                    if RBE.evaldata then:
                        foreach triple pattern TP in RBE.inner:
                            let item be a pair (TP, "closed")
                            add item to bodyDependencies
                        endfor
                    endif
                else if RBE is an assignment element:
                    # 不执行任何操作
                else if RBE is an aggregation element:
                    foreach triple pattern TP in RBE.pattern:
                        let item be a pair (TP, "closed")
                        add item to bodyDependencies
                    endfor
                endif
            endfor
        endif

        foreach pair (triple pattern TP, depLabel) in bodyDependencies:
            if R1 is a run-once rule:
              set depLabel to "closed"
            endif
            # 查找此三元组模式元素或否定元素的依赖。
            foreach rule R2 in ruleSet.rules:
                foreach triple template TT in R2.head:
                    if triple pattern TP matches triple template TT:
                        let key = (R1, R2)
                        if edgeLabelMap contains key:
                            let oldLabel = edgeLabelMap.get(key)
                            let merged = mergeLabel(oldLabel, depLabel)
                            edgeLabelMap.set(key, merged)
                        else:
                            edgeLabelMap.set(key, depLabel)
                        endif
                    endif
                endfor
            endfor
        endfor
    endfor

    let DP = { }
    foreach entry ((R1, R2), label) in edgeLabelMap:
        add an edge (R1 -> R2) labeled with label to DP
    endfor

    the result is DP
enddefine

4.4 分层

分层 是将一个 规则集 划分 为一个有序序列的过程，该序列由 分层层级 组成（也称 为“strata”，单数为“stratum”）。位于较低 层级 中的规则 先于较高 层级 中的规则求值。

分层 对以下对象之间的依赖施加约束：规则 ，以确保 否定元素、聚合元素 和 仅运行一次的规则 仅依赖 于使用较早（较低）层级 计算的结果以及 基础图。 这保证了唯一、定义明确且有限的 求值结果，来自对一个 规则集 在给定的 基础图 上求值。

注

分层过程也可以用于作出其他求值 决策。本文档描述了实现一致求值的必要条件 ，并给出了一种可能的方式来形成 分层。实现需要满足这些条件 ，即此处描述的条件，以获得兼容的行为，但并不 要求按照所给出的形式实现该算法。

分层层级

一个 分层层级 SL 是一个有序对 ，由两个不相交的集合组成，集合中的元素为 规则（SL.once、SL.general）。 SL.once 恰好包含该层级的 仅运行一次的 规则； 这些规则中的每一条都会被求值 恰好一次，在开始对该 分层层级 求值时。 SL.general 是该层级中其余规则的集合， 这些规则会被反复求值，直到不再推断出新的三元组。

分层

一个 分层，属于一个 规则集，是一个由 分层层级 组成的序列。 每条规则，位于一个 规则集 中，都恰好出现在某一个集合中，该集合属于某一个 分层层级。

这些 分层层级，属于一个 分层，其编号 从零开始。一个 层级编号，属于一条 规则，是以下对象的编号： 该 分层层级，它包含该规则。 一条具有较小 层级编号 的规则位于 较低层级； 一条具有较大 层级编号 的规则位于 较高层级。

对于从规则 R1 指向规则 R2 的每条边，它位于 依赖图 中，该图属于该 规则集：

  • 如果该边标记为封闭，则 层级 编号，属于 R1，严格大于 层级 编号，后者属于 R2。
  • 如果该边标记为开放，则 层级 编号，属于 R1，大于或等于 层级 编号，后者属于 R2。
注

一个 规则集 可以具有多个 分层。 实现可以使用任意一个 分层，属于该 规则集。

4.4.1 分层条件

只有满足以下 条件时，才定义分层。如果一个规则集不满足此条件，则本 规范不会为此类规则集的求值定义结果。

分层条件
分层条件要求 一个闭合依赖所涉及的 递归依赖 不存在于一个规则集的依赖图中。
注

分层条件恰好就是 分层存在的条件：当且仅当 规则集的依赖图中没有循环路径包含一个闭合依赖时，才能 为一个规则集形成一个分层。

4.4.2 分层算法

以下算法给出了一种仅基于 规则集的可能分层。 

define stratification(ruleSet):

    let DP = Dependency graph for the rule set.
    let stratumMap be a map from rule to integer

    # 依赖图应满足分层条件。
    # 对无界分层的检查是一项防护措施，
    # 用于处理违反分层条件的情况。
    let limit = num rules + 1
    let maxStratum = 0

    # 初始化 stratumMap
    foreach rule in ruleSet.rules:
        stratumMap.set(rule, 0)
    endfor

    boolean changed = true
    while changed:
        changed = false
        foreach edge E in DP:
            # 从 pRule 到 qRule 且带有标签的边
            let pRule = source of edge
            let qRule = destination of the edge
            let label = edge label

            if label == "open":
                if stratumMap.get(pRule) < stratumMap.get(qRule):
                    stratumMap.set(pRule, stratumMap.get(qRule))
                    changed = true
                endif
            endif
            if label == "closed":
                if stratumMap.get(pRule) <= stratumMap.get(qRule):
                    let xStratum = 1 + stratumMap.get(qRule)
                    if xStratum > limit:
                        # 违反分层要求
                        error "Stratification error"
                    endif
                    stratumMap.set(pRule, xStratum)
                    maxStratum = max(maxStratum, xStratum)
                    changed = true
                endif
            endif
        endfor
    endwhile

    # 初始化结果映射。
    let stratumRules be a map from integer to rules.
    foreach i = 0 to maxStratum
        stratumRules.set(i, {})
    endfor

    # 收集 stratumMap 中层级编号相同的规则
    foreach rule R in map stratumMap:
        let stratumNum = stratumMap.get(R)
        add R to stratumRules.get(stratumNum)
    endfor

    # 将每个层级划分为 once 和 general
    let stratumLevels be a sequence of pairs of sets of rules.
    for i = 0 to maxStratum:
        let rules = stratumRules.get(i)
        let once = { R in rules | R is a run-once rule }
        let general = rules \ once
        stratumLevels.set(i, pair(once, general))
    endfor

    the result is stratumLevels
enddefine
注

分层条件的一个结果 是，一旦一个 单次运行规则被求值， 用于确定该规则结果的数据在 后续求值期间将不会改变。

对一个完整规则集逐步应用依赖分析和 分层，并一直进行到 求值的过程见 6.6 完整 示例。

4.5 处理导入

从 Web 读取文档会涉及安全问题。 是否支持导入规则集由SPARQL-RL 处理器自行决定。 此外，实现可以提供部分支持， 例如仅支持导入某些规则集，而不支持其他规则集， 并且可能从经过验证的副本导入。

以下条件适用于导入处理：

  • 不支持导入规则集的实现必须拒绝 任何规则集，如果其中包含 IMPORTS 语句，并 报告错误。
  • 提供部分支持的实现 必须在遇到不支持的导入时 报告错误。
  • 如果无法解析导入的文档，实现必须报告错误， 或者文档在语法上无效时，也必须报告错误。
  • 处理器必须确保每个规则集仅导入一次，以避免 在处理 IMPORTS 语句时出现无限循环。

已解析规则集是通过 递归读取另一个规则集的导入中提及的所有规则集， 从该规则集生成的。

示例算法见 B. 导入算法 示例。

5. SPARQL-RL 与 SPARQL 之间的关系

本节为非规范性的。

SRL 和 SPARQL 关系密切。SRL 旨在兼容 SPARQL，并且 SRL 中的许多构造源自或受到启发于 SPARQL 模式匹配。不过，两者也存在一些差异。

在 SRL 中，RULE 变量始终在使用前绑定，无论是用于 FILTER 或 SET 的表达式中，还是用于 三元组模板 中， 这些模板属于 规则头。SPARQL CONSTRUCT 查询和 INSERT 更新会 产生部分结果，如果某个变量出现在 CONSTRUCT 或 INSERT 模板中，但未在 WHERE 子句中被赋值。

  • 良构性条件确保 变量至少出现在一个 三元组模式元素 中， 或者作为一个 赋值变量 出现， 然后才能用于一个 过滤元素 或 赋值 元素 中， 这些元素位于 规则体 内。
  • SRL 的 SET 形式与 SPARQL 的 BIND 形式具有不同的 错误处理行为。在 SET 中遇到错误会导致 当前解被过滤掉，而 BIND 不会 设置当前解中的变量，但会继续传递该解。 SET(?var := expr) 等同于 SPARQL 中的 BIND(expr AS ?var)，后接 FILTER(BOUND(?var))。
  • 规则体 WHERE 子句的语法 不包含 UNION 或 OPTIONAL 语法。 这些 SPARQL 元素可能导致未绑定的变量。 UNION 或 OPTIONAL 的效果可以通过使用 良构规则 来实现。

其他差异包括：

  • NOT 的语法将内部主体限制为三元组 模式和过滤器，并且不允许嵌套模式。 NOT 作为过滤器执行，执行位置是规则体中 书写它的位置，这与 SPARQL FILTER NOT EXISTS 不同。
  • 属性路径语法仅涵盖具有 / 和 ^ 的路径。 这些路径可以展开为三元组模式。 它不允许任意长度运算符 * 和 +。 任意长度路径可以在 SPARQL-RL 中表示， 使用递归作为一种更通用的方法。
  • 某些函数未包含在 SRL 语法中。其中没有 COALESCE 或 BOUND。也没有哈希函数。其中 没有 RAND，因为它每次被 调用时都会产生不同的结果。
    注
    NOW() 是允许的，并被定义为返回同一个 时间点，在整个规则集求值过程中都是如此。
  • 使用 BNODE 会在每次调用时产生不同的空白节点。 规则集求值的结果将产生彼此 图同构的推断图。

  • UUID 和 STRUUID 可用于生成唯一标识符。 规则不应检查这些生成的标识符，而应仅使用它们 来生成三元组。

    可以使用专用生成器来测试可重现性， 类似于测试 NOW 的结果。

6. 规则集求值

本节定义了对给定数据求值规则集所产生的结果。 实现不要求使用此算法。 实现可以使用任何能够生成相同结果的算法。 

输入：图 G（称为基础图）和规则集 RS。
输出：由推导出的三元组组成的 RDF 图 GI

推导出的三元组不包括 该 基础图中已有的三元组。

6.1 求值定义

解映射
一个 解映射，μ，是一个偏 函数 μ : V → T， 其中 V 是所有变量的集合 ，而 T 是所有 RDF 术语 的集合。 μ 的定义域记 为 dom(μ)，它是一个子集 ，属于 V，其中的元素都有 μ 的定义值。术语 解 可以使用，当明确指的是一个 解映射 时。 用 μ0 表示满足以下条件的解映射： dom(μ0) 为空集。
替换函数

替换函数，或简称为替换， 是一个函数 subst(μ, 三元组模式) ，它返回一个 三元组模式 ，其中每次出现在该 三元组模式 中的变量 var，若它属于 dom(μ) ，则被替换为一个 RDF 术语，该术语由 解映射 为 var 给出。 如果所得的三元组模式没有变量，则它是一个 RDF 三元组。

函数 subst(μ, 三元组模板) 的定义类似。每次出现在 三元组模板 中的变量都被替换为一个 RDF 术语，该术语由 解映射 为 var 给出。

模板实例函数
模板实例函数 是一个函数 replaceBlankNodes(list of 三元组模板) ，它 返回一个列表，其中包含 三元组模板，其中每个 空白节点 ，若位于实参中，都会被替换为一个全新的空白节点。 同一个空白节点的多次出现 会被替换为同一个全新的空白节点。
求值 图
一个 求值图 是一个 RDF 图，它合并了 基础图 和规则集求值期间生成的所有三元组。
图匹配
图匹配 查找各种方式，以 将三元组模式映射到一个 RDF 图 中的三元组。

令 G 为一个 RDF 图，并令 TP 为一个 三元组模式。 函数 graphMatch(G, TP) 返回一个集合，其中包含所有可能的 解，这些解 应用于该三元组模式时，会生成一个三元组，该三元组位于 图 G 中。

令 G 为一个 RDF 图，TP 为一个 三元组模式， 并令 V 为出现在 TP 中的变量集合。 

graphMatch(G, TP) = { μ | dom(μ) = V and subst(μ, TP) is a triple in G }
解兼容
两个解 S1 和 S2 是 兼容的，如果它们对变量的取值一致 ，这些变量是两者共有的。

令 S1 和 S2 为解。 

compatible(μ1, μ2) = true
                      if forall v in dom(μ1) intersection dom(μ2)
                          μ1(v) = μ2(v)
compatible(μ1, μ2) = false otherwise
解序列
一个 解序列 是一个解的多重集。 该序列没有定义顺序。 它等价于一个无序列表，并且可以包含重复项。
解合并
如果两个解兼容，则这两个解的合并是这样一个解： 它将每个解中的变量映射到 RDF 术语 ，该术语来自其中一个解。
令 μ1、μ2 为解映射，并令 S1 和 S2 为解序列。 
merge(μ1, μ2) = μ such that
                    μ(v) = μ1(v) if v in dom(μ1)
                    μ(v) = μ2(v) otherwise
merge(S1, S2) = { μ |
                    μ1 in S1, μ2 in S2
                    and compatible(μ1, μ2)
                    μ = merge(μ1, μ2) }
注

merge(μ1, μ2) 的定义域 是 domain(μ1) ∪ domain(μ2)。

如果两个解没有共有变量，则它们是兼容的， 并且这两个解的合并是以下两者的并集： μ1 和 μ2。

有效布尔值
函数 EBV(x) 返回有效布尔值 ，对应于一个 RDF 术语。

6.4 规则求值

一条 规则 的求值方式是计算一个 解 序列，它来自 规则体 ，然后使用每个 解映射，它们属于该 解序列，来 生成三元组，使用该 规则头。

在规则体内，位于 三元组模式 中的空白节点行为如同变量。 这兼容 SPARQL 图模式匹配。

将空白节点视为变量
空白节点被视为变量，位于 三元组 模式 中，这些模式属于一个 规则体，方法是将每个空白节点替换为一个变量，该变量 未在规则中使用。 这包括替换位于 三元组术语 内部的空白节点。 对于每次出现的 同一个空白节点，使用同一个变量，而对于每个 不同的空白节点，使用不同的变量。 
# 对规则体求值
# 此函数返回一个解序列

define evalRuleElements(B, SEQ, G, GD):
    where
        B is a sequence of rule elements
        SEQ is a solution sequence
        G and GD are RDF graphs

    foreach rule element rElt in B:

        if rElt is a triple pattern element TP:
            X = graphMatch(G, TP)
            SEQ1 = {}
            foreach μ1 in X:
                foreach μ2 in SEQ:
                    if compatible(μ1, μ2):
                      μ3 = merge(μ1, μ2)
                      add μ3 to SEQ1
                    endif
                endfor
            endfor
        endif

        if rElt is a filter element F:
            SEQ1 = {}
            foreach solution μ in SEQ:
                let x = evalFunction(F.expr, μ)
                if x is not an error and EBV(x) is true:
                    add μ to SEQ1
                endif
            endfor
        endif

        if rElt is a negation element N:
            SEQ1 = {}
            foreach solution μ in SEQ:
                S = sequence{ μ }
                if N.evaldata:
                    NEG = evalRuleElements(N.inner, S, G, GD)
                else:
                    NEG = evalRuleElements(N.inner, S, GD, GD)
                endif
                if NEG is empty:
                    add μ to SEQ1
                endif
            endfor
        endif

        if rElt is an assignment element A:
            SEQ1 = {}
            foreach solution μ in SEQ:
                let x = evalFunction(A.expr, μ)
                if x is not an error:
                    # 将映射 A.var -> x 添加到解 μ
                    let μ2 be a solution mapping μ ∪ { (A.var, x) }
                    add μ2 to SEQ1
                else:
                    # 错误：丢弃解 μ
                endif
            endfor
        endif

        ## COUNT(*) 怎么处理？
        if rElt is an aggregation element AGG:
            let SEQX = evalRuleElements(AGG.pattern, SEQ, G, GD)
            let KGRP = empty map of solution mappings to solution sequences
            # 将解映射分配到各组。
            foreach solution μx in SEQX:
                let μk be μx restricted to AGG.grouping
                if KGRP[μk] is defined:
                    Add μx to the solution sequence KGRP[μk]
                else:
                    KGRP[μk] = solution sequence of one element μx
                endif
            endfor
            # 对每个分组，计算聚合函数，并
            # 并创建一个解映射，其中包含分组键和
            # 聚合赋值的结果。
            let SEQ1 be an empty solution sequence
            foreach key K of map KGRP:
                let X be solution sequence of KGRP[K]
                let Z be an empty solution mapping
                foreach aggregation function F in AGG.assignments:
                    let V = calculate F.function(X)
                    add solution mapping (F.var, V) to Z
                endfor
                Z = merge(Z, K)
                add Z to SEQ1
            endfor
        endif
        SEQ = SEQ1
    endfor

    return SEQ
enddefine

define evalRule(R, G, GD):
    where
        R is a well-formed rule
        G and GD are RDF graphs
    let B be R.body
        treating 空白节点为变量.

    # 仅含一个解的解序列，该解不映射任何变量。
    let SEQ0: Solution sequence = { μ0 }

    if R.evaldata:
        let SEQ = evalRuleElements(B, SEQ0, G, GD)
    else:
        let SEQ = evalRuleElements(B, SEQ0, GD, GD)
    endif

    # 对规则头求值
    let OUT = empty set
    foreach μ in SEQ:
        let S = {}
        # 规则头，其中每个空白节点都被替换为一个全新的空白节点
        let HT = replaceBlankNodes(R.head)
        foreach triple template TT in HT
            let triple = subst(μ, TT)
            Add triple to S
        endfor
        OUT = OUT ∪ S
    endfor
    return OUT
enddefine

6.5 规则集求值

对规则集求值，定义为执行该规则集某个层，这些层来自该规则集的 分层，其中每一层都必须 完整执行， 并按顺序执行，然后才能进入下一层。 对层求值时，首先执行 该层中的每条仅运行一次的规则，然后反复执行该层的 一般规则，直到不再有新的三元组 产生。

let RS be the rule set

        GE = GE ∪ Y
    endfor

    let finished = false
    while ! finished:
        finished = true
        foreach rule R in ST.general:
            let X = evalRule(R, GE, G0)
            let Y = { t ∈ X | t ∉ GE }
            if Y is not empty:
                finished = false
                GI = GI ∪ Y
                GE = GE ∪ Y
            endif
        endfor
    endwhile
endfor
the result is GI

6.6 完整示例

本节为非规范性的。

本节逐步展示一个完整 规则集的求值过程：确定规则依赖 （4.3 规则 依赖）、 计算分层 （4.4 分层）， 并依次对每个层求值以产生 推理图 （6.5 规则集 求值）。

该示例描述了软件组件及其依赖关系： 一个前端依赖于应用服务器，而应用服务器依赖于 数据库和日志库。数据库存在一个已知 漏洞。规则沿依赖链传播漏洞暴露关系， 为暴露于严重漏洞的组件赋予 :criticallyExposed 状态，为不严重的组件赋予 :safeToDeploy 状态，并为每个严重暴露的组件创建 通知。 （实际中，一个漏洞是否影响组件 取决于部署的版本；该示例省略了版本信息，并 直接声明漏洞。） 为简洁起见，基础图直接声明 :dependsOn 三元组， 而不是像 3.1 三元组 模式中那样从更具体的关系派生它们。

示例 13：完整示例：数据和规则 
:frontend rdf:type :Component ;
          :dependsOn :app .
:app      rdf:type :Component ;
          :dependsOn :db ;
          :dependsOn :logger .
:db       rdf:type :Component ;
          :hasVulnerability :vuln1 .
:logger   rdf:type :Component .
:vuln1    :severity 9.1 .
# R1
RULE { ?x :exposedTo ?v } WHERE { ?x :hasVulnerability ?v }

# R2
RULE { ?x :exposedTo ?v } WHERE { ?x :dependsOn ?y . ?y :exposedTo ?v }

# R3
RULE { ?x :status :criticallyExposed }
WHERE { ?x :exposedTo ?v . ?v :severity ?s . FILTER(?s >= 9.0) }

# R4

# R5

这些规则在注释中标记为 R1 到 R5，本节其余部分 使用这些标签引用它们。 它们是从 3.2 递归到 3.5 赋值 和创建 RDF 术语中引入的规则。 该规则集没有 IMPORTS，因此导入处理 不会改变它；也没有 DATA 块，因此求值仅 从基础图开始。

6.6.1 确定 依赖

将每个规则主体中的每个三元组模式与 每个规则头中的三元组模板进行比较，以确定哪些规则 依赖于哪些规则 （4.3 规则 依赖）。

  • R1 的主体是单个三元组模式 ?x :hasVulnerability ?v。没有任何规则头包含能 生成谓语为 :hasVulnerability 的三元组的三元组模板， 因此该模式只能匹配数据。 R1 没有依赖。
  • R2 的主体有两个三元组模式。 ?x :dependsOn ?y 无法匹配任何规则头，因此它只能匹配 数据。?y :exposedTo ?v 与 R1 的头模板 ?x :exposedTo ?v 匹配，也与 R2 自身的头匹配。 两次出现都是三元组模式元素 （它们不出现在否定元素内部，并且 R2 不是单次运行规则），因此 R2 对 R1 具有开放依赖，并且 对自身具有开放依赖。 R2 对自身的依赖使 R2 成为递归规则。
  • 在 R3 的主体中，模式 ?x :exposedTo ?v 与 R1 和 R2 的头匹配，因此 R3 对它们各自具有开放 依赖。模式 ?v :severity ?s 不匹配任何 规则头。
  • 在 R4 的主体中，模式 ?x rdf:type :Component 不匹配任何规则头：唯一一个谓语为 rdf:type 的头模板位于 R5 中，而它的宾语 :Notification 是 与 :Component 不同的 RDF 术语，因此任何生成的 三元组都无法匹配。 模式 ?x :status :criticallyExposed 出现在 否定元素 NOT { ?x :status :criticallyExposed } 中，并且 与 R3 的头模板匹配。因为该模式 出现在否定元素中，所以 R4 对 R3 具有闭合 依赖。
  • 在 R5 的主体中，模式 ?x :status :criticallyExposed 与 R3 的头匹配。R5 的头包含一个 空白节点，因此它对 R3 的依赖是闭合 依赖，即使该模式是普通的 三元组模式元素。 任何规则主体中的模式都不匹配 R5 的头模板， 因此没有规则依赖于 R5。

因此，依赖图有五个顶点和六条 边：

  • R2 → R1（开放）
  • R2 → R2（开放）
  • R3 → R1（开放）
  • R3 → R2（开放）
  • R4 → R3（闭合）
  • R5 → R3（闭合）

尽管 R4 和 R5 都不直接依赖于 R1 或 R2，但它们各自通过 R3 对二者都具有传递依赖。

图中唯一的循环是自环 R2 → R2， 它是开放依赖。没有循环涉及闭合 依赖，因此满足分层条件， 并且该规则集具有明确定义的结果。

6.6.2 计算 分层

按照 分层算法， 每个规则都从第 0 层开始。然后反复检查各条边， 直到没有任何变化：

  • 一条开放边要求源规则处于 与其目标相同或更高的层。所有四条开放边在 每个规则都处于第 0 层时已经满足此条件，因此它们 不会引起任何变化。
  • 一条闭合边要求源规则处于 严格高于其目标的层，因为目标 必须先运行至完成。边 R4 → R3 （闭合）发现 R4 和 R3 都处于第 0 层，因此 R4 被 移到第 1 层。同样，边 R5 → R3 （闭合）将 R5 移到第 1 层。

再次遍历各条边不会产生变化，因此这些层 已最终确定。然后将每个层划分为 单次运行规则和一般规则。 R5 的头中有一个空白 节点，因此它是单次运行规则；该规则集的其他规则 都不是单次运行规则。 分层如下：

  • 第 0 层：一般规则 R1、R2、R3；没有单次运行规则
  • 第 1 层：单次运行规则 R5；一般规则 R4

此顺序体现了较高 层中规则的意图。一个组件是否可以安全部署，以及哪些 组件需要通知，只有在 所有 :status :criticallyExposed 三元组都已派生后才能确定 —— 而派生这些三元组的规则 R3 会在 较低的层中完成，同时完成的还有向它提供数据的规则 R1 和 R2。

6.6.3 对各层求值

求值遵循 6.5 规则集 求值的算法。 求值图 GE 以基础图开始，而 推理图 GI 初始为空。每个层都会按顺序求值至 完成：该层的规则按轮次求值， 并重复这些轮次，直到某一轮不产生新的三元组。 该算法并未固定同一轮中 对一个层内规则求值的顺序；此处跟踪使用 R1、R2、R3 的顺序。不同的顺序可能会将相同的 推理分散到不同数量的轮次中，但由于 第 0 层会运行至完成，因此会产生相同的最终图。

由于此规则集没有 DATA 块，因此在求值的每个时刻，GE 都是 G0 加 GI。因此，下面的跟踪 只记录 GI，显示求值进行时它的状态，并 用产生每个新三元组的规则进行标记。

7. SPARQL-RL 语法

一个 SPARQL-RL 文档 是一个采用 UTF-8 [RFC3629] 编码并以 RuleSet 产生式开始，且符合 7.6 语法中定义的附加约束的 RDF 字符串。 仅允许Unicode 标量值， 其范围为 U+0000 到 U+D7FF 以及 U+E000 到 U+10FFFF。 这排除了 代理代码点， 即范围 U+D800 到 U+DFFF。

7.1 版本声明

一个 版本标签是标识 SPARQL-RL 语法和语义 一致性的字符串。

版本标签
版本标签
"1.2"

版本声明应该在文档的较前位置给出。

多个 VERSION 指令 可以出现在一个SPARQL-RL 文档中。 每个指令适用于该指令之后的文档部分， 直到遇到另一个指令或到达文档末尾。

版本标签也可以由 媒体类型的 version 参数给出。在没有当前 VERSION 指令的情况下， 会采用作为媒体类型一部分指定的版本。

7.2 空白字符

空白字符 （产生式 WS）用于 分隔两个原本会被错误地 识别为一个终结符的终结符。 下文以大写字母表示的规则名称指明空白字符在何处 具有重要意义；这些规则构成了用于构建 SPARQL-RL 解析器时可选用的一组终结符。

空白字符在产生式 String中具有重要意义。

7.3 注释

注释以位于 IRIREF、 STRING_LITERAL1、 STRING_LITERAL2、 STRING_LITERAL_LONG1 或 STRING_LITERAL_LONG2 之外的 # 开始， 并持续到行尾（由 LF 或 CR 标记）， 如果注释标记之后没有行尾，则持续到文件末尾。 注释被视为空白字符。

7.4 IRI 引用

相对 IRI 引用使用基 IRI 按照 统一资源标识符（URI）：通用 语法 [RFC3986] 进行解析，仅使用 第 5.2 节中的基本算法。 不执行基于语法的规范化或基于方案的规范化 （RFC3986 第 6.2.2 节和第 6.2.3 节中所述）。 IRI 引用中额外允许的字符按照与 URI 引用中非保留字符相同的方式处理，依据 国际化资源标识符 （IRI） [RFC3987] 第 6.5 节。

BASE 指令定义用于解析 相对 IRI 引用的基 IRI，依据 [RFC3986] 第 5.1.1 节，“嵌入内容中的基 URI ”。 第 5.1.2 节，“来自封装 实体的基 URI” 定义作用域内基 IRI 如何来自封装文档， 例如具有 xml:base 指令的 SOAP 信封或具有 Content-Location 标头的 MIME 多部分文档。 在 5.1.3，“来自检索 URI 的基 URI”中标识的“检索 URI”， 是从中检索特定SPARQL-RL 文档的 URL。 如果上述内容均未指定基 URI，则使用默认 基 URI（第 5.1.4 节，“默认基 URI”）。 每个 BASE 指令都会设置一个新的作用域内基 URI， 相对于前一个基 URI。

B. 导入算法示例

本节为非规范性内容。

以下算法展示了一种解析 IMPORTS 语句的方法， 即递归访问所有被引用的文档。

两个规则集 RS1 和 RS2 的规则集合并 会产生一个规则集 MR，其定义如下： 

let RS be a rule set
let V = {}
if RS has a location:
    V = { location of RS }
endif

define ruleSetMerge(rule set RS1, rule set RS2):
    let MR be a rule set
    MR.rules = RS1.rules ∪ RS2.rules
    MR.data = rdf_merge(RS1.data, RS2.data)
    MR.imports = {}
    the result is MR
enddefine

define imports(rule set RS):
    let RS2 be a rule set formed from RS.rules and RS.data
    foreach URL x in RS.imports:
        if x ∉ V:
            V = V ∪ { x }
            read rule set RS3 from URL x
            RS2 = ruleSetMerge(RS2, imports(RS3))
        endif
    endfor
    the result is RS2
enddefine

result is imports(RS)

其中 rdf_merge 是 RDF 合并 操作。

D. 安全注意事项

本节为非规范性内容。

SPARQL-RL 文档可能包含引用其他 SPARQL-RL 文档的 IMPORTS 语句，并将其内容导入当前 文档。 如果被导入的文档本身也包含自己的 IMPORTS 语句， 则这些文档也会被导入。

虽然使用 IMPORTS 语句有助于将规则集模块化， 但也可能引入安全风险。 风险包括但不限于：规则集 在求值期间恶意或意外地导致过量计算； 以及 HTTP 请求被拦截并返回其他文档， 包括过时的副本。

将 SPARQL-RL 规则集应用于 RDF 图可能导致 大量的计算和内存使用，这可能被利用 来造成拒绝服务攻击。 应用程序应注意限制应用 SPARQL-RL 规则集时 可能产生的计算量和内存使用量。

SPARQL-RL 语法使用 UTF-8 编码 [RFC3629]，并且 允许 在字符串数据中使用未转义的控制字符。 虽然本规范不会直接向最终用户公开这些内容， 但这些内容可能通过用户代理呈现，从而导致呈现的文本 因此类字符而产生误导。

SPARQL-RL 可用于处理和创建任意应用程序数据； 安全注意事项会因使用领域而异。 适用于文本的安全工具和协议 （例如 PGP 加密、校验和验证、受密码保护的压缩） 也可以用于SPARQL-RL 文档。 必须实施安全／隐私协议，以反映 SPARQL-RL 规则集求值结果中信息的敏感程度。

SPARQL-RL 的安全注意事项包括 RDF 数据以及 RDF Turtle 等 格式的安全注意事项。

E. 隐私注意事项

本节为非规范性内容。

SPARQL-RL 文档可以包含其他应用程序数据， 其中可能包含个人身份信息（PII） 或其他可能被视为敏感的信息。 建议发布包含此类信息的规则集的作者仔细 考虑发布此类信息的必要性和用途， 以及数据预计会被使用和可能被披露的地区 所适用的法规（例如 GDPR、 CCPA 和其他法规）， 尤其应考虑访问这些数据是否需要授权措施。
