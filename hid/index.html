1. 简介

本节为非规范性内容。

HID（人机接口设备）是一类接收人的输入或向人提供输出的设备。HID 也指 HID 协议，这是一种在主机与设备之间进行双向通信的标准，旨在简化安装过程。HID 协议最初为 USB 设备而开发，后来也在包括蓝牙在内的许多其他协议之上实现。

Web 平台已经支持许多 HID 设备的输入。键盘、指点设备和游戏手柄通常都使用 HID 协议实现。不过，这种支持依赖于操作系统的 HID 驱动程序，由它们将 HID 输入转换为高级输入 API。主机 HID 驱动程序不能良好支持的设备往往无法由网页访问。同样，大多数未获主机 HID 驱动程序支持的设备输出功能也无法访问。

另请参阅相关的说明文档。

2. 应用需求

本节为非规范性内容。

2.1. 小众设备

Web 平台已通过现有的高级输入 API 良好支持最常见的 HID 输入设备类别。例如，可通过 PointerEvent 访问鼠标输入，通过 KeyboardEvent 访问键盘输入。这些设备的输入由主机原生 HID 驱动程序处理，通常无需设备专用驱动程序或配置即可正常工作。WebHID 并非面向这类已经得到高级输入 API 良好支持的设备。

对于某些 HID 设备类别，Web 平台支持设备的部分功能，但限制对其他功能的访问。例如，[GAMEPAD] 支持大多数游戏控制器的输入功能，却不支持 LED 指示灯或音频等较少见的功能。主机 API 往往不能良好支持这些功能，而在用户代理中添加支持可能会显著增加复杂性。当高级 API 提供的功能不完整时，WebHID 将为应用提供另一种选择。

许多 HID 设备未得到任何 Web 平台 API 的支持。HID 规范描述了可通过 HID 支持的多种设备，包括虚拟现实控制器、飞行模拟器、医疗设备等。WebHID 将允许使用这些设备，而无需额外的驱动程序或修改用户代理。

2.2. 原型开发、业余爱好者和教育设备

HID 对原型开发和业余爱好者应用很有吸引力，因为设备可以使用主机的通用 HID 驱动程序，而不必为使用设备的每种主机提供驱动程序。简化的安装过程也便于教育工作者在课堂中为学生部署设备，无需修改每台主机的系统配置。通过 Web 平台提供 HID 设备访问能力，将进一步降低安装要求，尤其适用于目前仅由主机专用应用支持的设备。

3. 安全与隐私注意事项

本节为非规范性内容。

3.1. 滥用设备访问权限

HID 外设可能暴露强大的功能，未经用户明确同意，不应允许页面访问这些功能。例如，HID 外设可能带有可收集周围环境信息的传感器。设备可能存储不应泄露或覆盖的私密信息。许多设备暴露了允许升级设备固件的功能。操作系统通常不限制应用访问 HID 设备，而这种访问权限有时会遭到滥用，导致设备损坏或其中存储的数据遭到破坏。

在某些情况下，设备暴露的功能完全不应允许网页访问。可以根据设备的供应商 ID 和产品 ID 识别特定设备，并在枚举时隐藏它们，从而屏蔽这些设备。报告描述符允许设备描述自身的能力，即使无法预先获知供应商 ID 和产品 ID，也可以利用这些信息屏蔽某些设备类别。具体可检查HID 用途值，这些值被分配给报告描述符中的集合；例如，可以拒绝访问包含顶层集合且该集合的HID 用途为键盘的设备，从而拒绝对类似键盘的设备的访问。

为减少滥用，在用户明确授予访问权限之前，页面不能使用设备。页面必须先请求访问权限，用户从显示所有可用设备的选择器中选定设备后，才会获准访问。页面获得访问权限后，将显示指示器，表明设备正在使用中。

3.2. 攻击设备

HID 协议极为灵活，许多设备的设计利用了这种灵活性。因此，恶意页面可能以多种方式利用设备访问权限损坏设备本身。HID 外设允许通过自定义 HID 报告发送固件更新的情况相当常见。设备制造商必须谨慎设计固件升级机制，以验证固件二进制文件的真实性，并且应防止可能降低设备安全性的降级操作。不可信的升级可能被用于向设备添加新功能，或使其伪装成完全不同类型的设备。

如果提供的输入超出预期范围，某些设备可能会损坏。例如，页面发送无效的振动命令时，游戏手柄的振动功能可能受损。

一般而言，这类攻击与具体设备有关，无法在 API 层面缓解。

3.3. 攻击主机

如果恶意页面取得设备访问权限，在某些情况下，它可以利用该权限攻击主机。一个主要问题是设备能否用于生成可信输入事件。这些事件被视为用户意图的替代信号，可用于访问更强大的 Web 平台功能。

鼠标和键盘通常作为 HID 外设实现，也能够生成可信输入。HID 键盘或鼠标可能包含可编程宏等高级功能，用于存储输入序列并在稍后重放。设备制造商必须谨慎设计这些功能，防止恶意应用将意外的输入序列重新编程到设备中，还必须防止在未经用户明确同意时触发宏重放。

3.4. 缓解措施

为降低安全与隐私风险，建议用户代理采用基于选择器的设备访问请求流程。页面请求访问 HID 设备时，用户代理应显示对话框，告知用户该页面想要访问设备。对话框应列出已连接的 HID 设备，并要求用户选择一个向页面暴露的设备。为减少误点击的可能性，对话框应要求两次独立交互：第一次从列表中选择设备，第二次确认选择并关闭对话框。

6. HID 接口

[Exposed=(DedicatedWorker,ServiceWorker,Window), SecureContext]
interface HID : EventTarget {
    attribute EventHandler onconnect;
    attribute EventHandler ondisconnect;
    Promise<sequence<HIDDevice>> getDevices();
    [Exposed=Window] Promise<sequence<HIDDevice>> requestDevice(
        HIDDeviceRequestOptions options);
};

注：用户代理的实现可以选择有条件地暴露 hid 属性（属于 Navigator），条件是相关全局对象（属于 Navigator）为 ServiceWorkerGlobalScope。例如，浏览器扩展上下文的情形，见 [browserext]。

创建 HID 的实例时，包含下表描述的内部槽：

内部槽 初始值 说明（非规范性）
[[devices]] 空的有序集合 一个有序集合，其中包含HIDDevice 实例，用于表示HID 接口（系统中当前可用的接口）
onconnect 属性，类型为EventHandler
onconnect，是一个事件处理程序 IDL 属性，对应connect 事件类型。
ondisconnect 属性，类型为EventHandler
ondisconnect，是一个事件处理程序 IDL 属性，对应disconnect 事件类型。
当一个HID 接口在系统上变为可用时，运行以下步骤：
一个HID 接口是可通过 HID 协议与设备通信的逻辑接口。每个HID 接口恰好有一个报告描述符，用于描述该接口支持的报告集。单个物理设备可以暴露多个HID 接口。对于具有多个HID 接口的设备，每个接口都运行一次这些步骤。

例如，USB 设备以接口集合的形式实现，每个接口都可以指定接口类别。当设备包含多个使用 HID 类别的 USB 接口时，每个接口都被枚举为独立的HID 接口。

  1. 令 device 为一个 HIDDevice。

  2. 将 device.[[vendorId]] 设为供应商 ID，其值来自暴露该接口的设备。

  3. 将 device.[[productId]] 设为产品 ID，其值来自暴露该接口的设备。

  4. 将 device.[[productName]] 设为产品名称，其值来自暴露该接口的设备。

  5. 将 device.[[collections]] 设为解析报告描述符的结果。

  6. 令 hid 为调用 device 的相关全局对象的 Navigator 对象的 hid 获取器的结果（如果 device 的相关全局对象是 Window 对象）；否则，设为调用 device 的相关全局对象的 WorkerNavigator 对象的 hid 获取器的结果。

  7. 追加 device 到 hid.[[devices]]。

  8. 如果用户已允许站点访问 device（这是先前调用 requestDevice() 的结果），则将一个全局任务加入队列，目标为相关全局对象（属于 hid），使用HID 设备任务源，以触发事件，其名称为 connect，目标为 hid，使用 HIDConnectionEvent，并将其 device 属性初始化为 device。

要解析报告描述符，运行以下步骤：
系统通常会读取报告描述符 字节序列，针对每个HID 接口在设备首次连接时执行此操作，并将这些值缓存到系统注册表中。如果报告描述符不可用，但系统提供的信息能够用于重建每个报告的布局，则用户代理可以使用另一种算法，而不是解析报告描述符.

报告描述符的格式见 [USBIF-HID-CLASS] 第 6.2.2 节。以下算法旨在实现该节描述的同一解析算法。

报告描述符包含三类项目。主项目用于定义数据字段及对其分组。全局项目和局部项目描述数据字段。局部项目定义仅适用于下一个主项目的特征，而全局项目定义影响随后定义的所有主项目的特征。

每个项目都有一个项目数据字段，其中包含与该项目关联的 0、1、2 或 4 字节数据；还有一个bSize 字段，说明存储项目数据字段所用的字节数。每个项目还具有标识其类型的标签。

  1. 令 items 为以下转换的结果：将报告描述符的字节序列转换为列表，其中包含主项目、全局项目和局部项目。

  2. 将 collections 初始化为空序列，其元素类型为 HIDCollectionInfo。

  3. 将 ancestors 初始化为空列表。

  4. 将 localState 初始化为空有序映射。

  5. 将 usages 初始化为空序列，其元素类型为 unsigned long。

  6. 将 stringIndices 初始化为空列表。

  7. 将 globalStack 初始化为空栈。

  8. 将 initialGlobalState 初始化为空有序映射。

  9. 将 reportId 初始化为 0。

  10. 将 initialGlobalState["unitSystem"] 设为 "none"。

  11. 将 initialGlobalState["unitExponent"] 设为 0。

  12. 将 initialGlobalState["unitFactorLengthExponent"] 设为 0。

  13. 将 initialGlobalState["unitFactorMassExponent"] 设为 0。

  14. 将 initialGlobalState["unitFactorTimeExponent"] 设为 0。

  15. 将 initialGlobalState["unitFactorTemperatureExponent"] 设为 0。

  16. 将 initialGlobalState["unitFactorCurrentExponent"] 设为 0。

  17. 将 initialGlobalState["unitFactorLuminousIntensityExponent"] 设为 0。

  18. 将 initialGlobalState["logicalMinimum"] 设为 0。

  19. 将 initialGlobalState["logicalMaximum"] 设为 0。

  20. 将 initialGlobalState["physicalMinimum"] 设为 0。

  21. 将 initialGlobalState["physicalMaximum"] 设为 0。

  22. 压入 initialGlobalState 到 globalStack。

  23. 对于每个 item（属于 items）：

    注：主项目见 [USBIF-HID-CLASS] 第 6.2.2.4 至 6.2.2.6 节。带有输入标签、输出标签或特征标签的项目定义输入、输出或特征报告中的一个字段。项目数据字段（属于主项目，且该项目带有输入标签、输出标签或特征标签）是一个位字段，包含描述数据字段的若干布尔参数。带有集合标签的项目定义嵌套在当前集合内的新集合；如果没有当前集合，则定义新的顶层集合。项目数据字段（属于主项目，且该项目带有集合标签）包含集合类型。带有结束集合标签的项目关闭当前集合。

    • 如果 item 是主项目：

      1. 如果 item 带有输入标签、输出标签或特征标签：

        1. 令 globalState 为最后一个项目（属于 globalStack）。

        2. 令 reportId 为 globalState["reportId"]。

        3. 令 reportItem 为创建 HID 报告项目的结果，使用 item、localState、globalState、usages 和 strings。

        4. 对于每个 collection（属于 ancestors）：

          1. 令 reports 为：

            • collection["inputReports"]，如果 item 带有输入标签；

            • collection["outputReports"]，如果 item 带有输出标签；或者

            • collection["featureReports"]，如果 item 带有特征标签。

          2. 如果 reports 包含某个项目，且其 reportId 属性等于 reportId，则令 report 为该项目。

            否则：

            1. 令 report 为一个新的 HIDReportInfo 字典。

            2. 将 report["reportId"] 设为 reportId。

            3. 将 report["items"] 设为空序列，其元素类型为 HIDReportItem。

            4. 追加 report 到 reports。

          3. 追加 item 到 report["items"]。

      2. 如果 item 带有集合标签：

        1. 令 collection 为一个新的 HIDCollectionInfo 字典。

        2. 令 usage 为第一个项目（属于 usages）。

        3. 如果大小（属于 usages）大于 1，则移除第一个项目（属于 usages）。

        4. 将 collection["usagePage"] 设为 globalState["usagePage"]。

        5. 将 collection["usage"] 设为 usage。

        6. 将 collection["type"] 设为表示该集合类型的值。

        7. 将 collection["children"] 设为空序列，其元素类型为 HIDCollectionInfo。

        8. 将 collection["inputReports"] 设为空序列，其元素类型为 HIDReportInfo。

        9. 将 collection["outputReports"] 设为空序列，其元素类型为 HIDReportInfo。

        10. 将 collection["featureReports"] 设为空序列，其元素类型为 HIDReportInfo。

        11. 如果 ancestors 为空，则追加 collection 到 collections。

          否则：

          1. 令 parent 为最后一个项目（属于 ancestors）。

          2. 追加 collection 到 parent["children"]。

        12. 追加 collection 到 ancestors。

      3. 如果 item 带有结束集合标签，则移除最后一个项目（属于 ancestors）。

      4. 将 localState 设为空有序映射。

      5. 将 usages 设为空序列，其元素类型为 unsigned long。

        注：全局项目见第 6.2.2.7 节。带有用途页标签、逻辑最小值标签、逻辑最大值标签、物理最小值标签、物理最大值标签、单位指数标签、单位标签、报告大小标签、报告 ID 标签或报告数量标签的项目会修改全局项目状态表中对应的字段。带有压栈标签的项目将当前全局项目状态表的副本压入项目状态栈。带有出栈标签的项目用项目状态栈的栈顶替换全局项目状态表。操作项目状态栈时，全局报告 ID 的值不受影响。

      6. 如果 item 是全局项目：

        1. 令 globalState 为最后一个项目（属于 globalStack）。

        2. 令 value 为项目数据字段按 unsigned long 解释所得的值。

        3. 如果 item 带有用途页标签，则将 globalState["usagePage"] 设为 value。

        4. 如果 item 带有逻辑最小值标签，则将 globalState["logicalMinimum"] 设为 value。

        5. 如果 item 带有逻辑最大值标签，则将 globalState["logicalMaximum"] 设为 value。

        6. 如果 item 带有物理最小值标签，则将 globalState["physicalMinimum"] 设为 value。

        7. 如果 item 带有物理最大值标签，则将 globalState["physicalMaximum"] 设为 value。

        8. 如果 item 带有报告大小标签，则将 globalState["reportSize"] 设为 value。

        9. 如果 item 带有报告 ID 标签，则将 globalState["reportId"] 设为 value。

        10. 如果 item 带有报告数量标签，则将 globalState["reportCount"] 设为 value。

        11. 如果 item 带有单位标签：

          1. 令 nibbles 为将 value 解释成序列的结果；该序列从低位开始，由八个 4 位二进制补码有符号整数组成。

          2. 如果 nibbles[0] 为：

            • 0，则将 globalState["unitSystem"] 设为 "none"

            • 1，则将 globalState["unitSystem"] 设为 "si-linear"

            • 2，则将 globalState["unitSystem"] 设为 "si-rotation"

            • 3，则将 globalState["unitSystem"] 设为 "english-linear"

            • 4，则将 globalState["unitSystem"] 设为 "english-rotation"

            • -1，则将 globalState["unitSystem"] 设为 "vendor-defined"

            • 否则，将 globalState["unitSystem"] 设为 "reserved"

          3. 将 globalState["unitFactorLengthExponent"] 设为 nibbles[1]。

          4. 将 globalState["unitFactorMassExponent"] 设为 nibbles[2]。

          5. 将 globalState["unitFactorTimeExponent"] 设为 nibbles[3]。

          6. 将 globalState["unitFactorTemperatureExponent"] 设为 nibbles[4]。

          7. 将 globalState["unitFactorCurrentExponent"] 设为 nibbles[5]。

          8. 将 globalState["unitFactorLuminousIntensityExponent"] 设为 nibbles[6]。

        12. 如果 item 带有单位指数标签，则将 globalState["unitExponent"] 设为以下结果：将项目数据字段的最低 4 位解释为二进制补码有符号整数。

        13. 如果 item 带有压栈标签，则压入 globalState 的副本到 globalStack。

        14. 如果 item 带有出栈标签，则弹出 globalStack 的栈顶。

      注：局部项目见第 6.2.2.8 节。带有用途标签、用途最小值标签、用途最大值标签、字符串索引标签、字符串最小值标签或字符串最大值标签的项目会修改局部项目状态表中对应的字段。每个主项目之后都会清除局部项目状态。

    • 如果 item 是局部项目：

      1. 令 value 为项目数据字段按 unsigned long 解释所得的值。

      2. 如果 item 带有用途标签：

        1. 如果 item 的bSize 字段为 1 或 2：

          1. 令 usageId 为一个 unsigned short，其中包含 value 的低 16 位。

          2. 令 globalState 为最后一个项目（属于 globalStack）。

          3. 将 value 设为一个HID 用途，其高位为 globalState["usagePage"]，低位为 usageId。

        2. 追加 value 到 usages。

      3. 如果 item 带有用途最小值标签，则将 localState["usageMinimum"] 设为 value。

      4. 如果 item 带有用途最大值标签，则将 localState["usageMaximum"] 设为 value。

      5. 如果 item 带有字符串索引标签，则追加 value 到 stringIndices。

      6. 如果 item 带有字符串最小值标签，则将 localState["stringMinimum"] 设为 value。

      7. 如果 item 带有字符串最大值标签，则将 localState["stringMaximum"] 设为 value。

6.1. getDevices() 方法

该getDevices()方法的步骤如下：

  1. 令 promise 为一个新的 promise。

  2. 令 document 为 null。

  3. 如果 this 的相关全局对象是 DedicatedWorkerGlobalScope 或 window 对象，则将 document 设为 this 的相关全局对象的关联 Document。

  4. 如果 this 的相关全局对象是 ServiceWorkerGlobalScope 对象，且关联的服务工作线程客户端为窗口客户端，则将 document 设为关联 Document，它属于关联的服务工作线程客户端的全局对象。

  5. 如果 document 为 null，或 document 未获允许使用该受策略控制的功能（名称为 "hid"），则拒绝 promise，理由为一个 "SecurityError" DOMException，并返回 promise。

  6. 并行运行以下步骤：

    1. 令 devices 为空序列，其元素类型为 HIDDevice。

    2. 对于每个 device（属于 this.[[devices]]）：

      1. 如果用户已允许站点访问 device（这是先前调用 requestDevice() 的结果），并且 device.[[state]] 不是 "forgotten"，则追加 device 到 devices。

    3. 将一个全局任务加入队列，目标为相关全局对象（属于 this），使用HID 设备任务源，以兑现 promise，值为 devices。

  7. 返回 promise。

6.2. requestDevice() 方法

该requestDevice()权限对话框列出已连接的设备，并要求用户选择一个。

如果设备具有多个HID 接口，对话框可以只显示一个代表所有接口的项目。当用户选择代表多个HID 接口的项目时，用户代理必须授予对该设备暴露的所有HID 接口的访问权限。

该requestDevice()方法的步骤如下：

  1. 令 promise 为一个新的 promise。

  2. 如果 this 的相关全局对象的关联 Document未获允许使用该受策略控制的功能（名称为 "hid"），则拒绝 promise，理由为一个 "SecurityError" DOMException，并返回 promise。

  3. 如果相关全局对象（属于 this）不是 window，则拒绝 promise，理由为一个 "NotSupportedError" DOMException，并返回 promise。

  4. 如果相关全局对象（属于 this）没有瞬时激活，则拒绝 promise，理由为一个 "SecurityError" DOMException，并返回 promise。

  5. 如果 options["filters"] 存在，则运行以下步骤，对于每个 filter（属于 options["filters"]）：

    1. 如果 filter 不是有效筛选器，则拒绝 promise，理由为一个 TypeError，并返回 promise。

  6. 如果 options["exclusionFilters"] 存在，则运行以下步骤：

    1. 如果 options["exclusionFilters"] 为空，则拒绝 promise，理由为一个 TypeError，并返回 promise。

    2. 对于每个 exclusionFilter（属于 options["exclusionFilters"]）：

      1. 如果 exclusionFilter 不是有效筛选器，则拒绝 promise，理由为一个 TypeError，并返回 promise。

  7. 并行运行以下步骤：

    1. 将 availableDevices 初始化为空列表。

    2. 对于每个 device（属于 this.[[devices]]）：

      1. 如果 device 匹配任一筛选器（位于 options["filters"] 中），且 device 不匹配任何筛选器（位于 options["exclusionFilters"] 中），则追加 device 到 availableDevices。

    3. 向用户显示 availableDevices 中的设备列表，请求用户授予站点访问某个 HID 设备的权限。

      注：用户代理可以在向用户显示设备列表前修改该列表。例如，具有多个HID 接口的设备应由单个项目表示，选择该项目即可授予对设备暴露的所有接口的访问权限。设备是以单个接口还是接口集合实现，属于实现细节；用户可能并不知情，而且不应认为这与设备访问权限相关。

    4. 令 devices 为空序列，其元素类型为 HIDDevice。

    5. 如果用户未选择设备，则将一个全局任务加入队列，目标为相关全局对象（属于 this），使用HID 设备任务源，以兑现 promise，值为 devices，并中止这些步骤。

    6. 对于每个 device（属于 this.[[devices]]）：

      1. 如果 device 表示所选设备暴露的一个HID 接口，则将 device.[[state]] 设为 "closed"，并追加 device 到 devices。

    7. 将一个全局任务加入队列，目标为相关全局对象（属于 device），使用HID 设备任务源，以兑现 promise，值为 devices。

  8. 返回 promise。

6.2.2. HIDDeviceFilter 字典

dictionary HIDDeviceFilter {
    unsigned long vendorId;
    unsigned short productId;
    unsigned short usagePage;
    unsigned short usage;
};
vendorId 成员，类型为unsigned long
该供应商 ID，即要匹配的值。
productId 成员，类型为unsigned short
该产品 ID，即要匹配的值。如果vendorId成员不存在，则productId被忽略。
usagePage 成员，类型为unsigned short
该顶层集合 用途页，即要匹配的值。
usage 成员，类型为unsigned short
该顶层集合 用途 ID，即要匹配的值。如果usagePage成员不存在，则usage被忽略。
设备筛选器用于缩小设备列表的范围，该列表显示在设备选择对话框中，此对话框由requestDevice()创建。未提供筛选器时，包含所有不匹配任何排除筛选器的已连接设备。提供一个或多个筛选器时，只要设备匹配任一筛选器且不匹配任何排除筛选器，就将其包含在内。

所有 HIDDeviceFilter 成员都是可选的。每个成员指定一条规则。要匹配某个 HIDDeviceFilter，每条规则都必须满足。空的 HIDDeviceFilter 匹配任意设备。

设备 ID 规则用于按设备的供应商 ID 和产品 ID选择设备。当应用仅针对特定设备设计，或依赖供应商专用功能时，这很有用。包含 vendorId 规则会使筛选器仅匹配具有指定供应商 ID 的设备。如果还包含 productId 规则，筛选器就只匹配具有指定供应商 ID 和产品 ID 的设备。productId 若在未指定 vendorId 规则的情况下指定，则会被忽略。

用途规则用于按分配给设备的HID 用途来选择设备，这些用途分配在其顶层集合上。当应用针对标准设备类别设计时，这很有用。要匹配设备，该设备至少一个集合必须匹配所有用途规则。包含 usagePage 规则会使筛选器仅在设备包含具有指定用途页的集合时才匹配。如果还包含 usage 规则，筛选器就只匹配具有指定用途页和用途 ID 的设备。usage 若在未指定 usagePage 规则的情况下指定，则会被忽略。

设备 ID 规则和用途规则可以组合使用。例如，应用可能希望匹配某个供应商的设备，但仅限于实现了特定设备类别的设备。

exclusionFilters 选项允许应用在 requestDevice() 创建的选择对话框中，排除某些原本会显示给用户的设备；这些设备虽实现了特定设备类别等要求，但已知无法按预期工作。

一个HIDDeviceFilter filter为有效筛选器，当且仅当以下步骤返回true:

  1. 如果 filter 为空，则返回 false。

  2. 如果 filter["productId"] 存在，而 filter["vendorId"] 不存在，则返回 false。

  3. 如果 filter["usage"] 存在，而 filter["usagePage"] 不存在，则返回 false。

  4. 返回 true。

一个HIDDevice device 匹配任一筛选器，该筛选器位于一个序列 filters，其中包含HIDDeviceFilter，当且仅当以下步骤返回true:

  1. 如果 filters 为空，则返回 true。

  2. 对于每个 filter（属于 filters）：

    1. 如果 filter 匹配设备 ID（属于 device），并且 filter 匹配任一集合（属于 device），则返回 true。

  3. 返回 false。

一个HIDDeviceFilter filter 匹配设备 ID（属于device），当且仅当以下步骤返回true:

  1. 如果 "vendorId" 在 filter 中：

    1. 如果 filter["vendorId"] 不等于 device.vendorId，则返回 false。

    2. 如果 "productId" 在 filter 中，且 filter["productId"] 不等于 device.productId，则返回 false。

  2. 返回 true。

一个HIDDeviceFilter filter 匹配任一集合（属于device），当且仅当以下步骤返回true:

  1. 对于每个 collection（属于 device.collections）：

    1. 如果 filter 匹配集合 collection，则返回 true。

  2. 返回 false。

一个HIDDeviceFilter filter 匹配集合 collection，当且仅当以下步骤返回true:

  1. 如果 "usagePage" 在 filter 中：

    1. 如果 filter["usagePage"] 不等于 collection.usagePage，则返回 false。

    2. 如果 "usage" 在 filter 中，且 filter["usage"] 不等于 collection.usage，则返回 false。

  2. 返回 true。

7.1. open() 方法

该open()方法的步骤如下：

  1. 令 promise 为一个新的 promise。

  2. 如果 this.[[state]] 不是 "closed"，则拒绝 promise，理由为一个 "InvalidStateError" DOMException，并返回 promise。

  3. 将 this.[[state]] 设为 "opening"。

  4. 并行执行以下步骤：

    1. 调用操作系统以打开 HID 设备。

    2. 如果此操作因任何原因失败，则将一个全局任务加入队列，目标为相关全局对象（属于 this），使用HID 设备任务源，以拒绝 promise，理由为一个 "NetworkError" DOMException，并中止这些步骤。

    3. 将 this.[[state]] 设为 "opened"。

    4. 将一个全局任务加入队列，目标为相关全局对象（属于 this），使用HID 设备任务源，以兑现 promise，值为 undefined。

  5. 返回 promise。

7.2. close() 方法

该close()方法的步骤如下：

  1. 令 promise 为一个新的 promise。

  2. 如果 this.[[state]] 为 "forgotten"、"forgetting"、"opening" 或 "closing" 之一，则拒绝 promise，理由为一个 "InvalidStateError" DOMException，并返回 promise。

  3. 将 this.[[state]] 设为 "closing"。

  4. 对于每个 pendingPromise（属于 this.[[pendingSendReportPromises]]）：

    1. 拒绝 pendingPromise，理由为一个 "AbortError" DOMException。

  5. 清空 this.[[pendingSendReportPromises]]。

  6. 对于每个 pendingPromise（属于 this.[[pendingSendFeatureReportPromises]]）：

    1. 拒绝 pendingPromise，理由为一个 "AbortError" DOMException。

  7. 清空 this.[[pendingSendFeatureReportPromises]]。

  8. 对于每个 pendingPromise（属于 this.[[pendingReceiveFeatureReportPromises]]）：

    1. 拒绝 pendingPromise，理由为一个 "AbortError" DOMException。

  9. 清空 this.[[pendingReceiveFeatureReportPromises]]。

  10. 并行执行以下步骤：

    1. 调用操作系统以关闭 HID 设备并释放所有关联资源。

    2. 将 this.[[state]] 设为 "closed"。

    3. 将一个全局任务加入队列，目标为相关全局对象（属于 this），使用HID 设备任务源，以兑现 promise，值为 undefined。

  11. 返回 promise。

7.3. forget() 方法

注：用户代理可以决定合并不同 API 的权限，例如在统一的底层设备访问权限下跟踪 WebHID 和 WebUSB 的设备访问。因此，此方法将来也可能撤销其他权限（目前尚未规定）。

该forget()方法的步骤如下：

  1. 令 promise 为一个新的 promise。

  2. 并行执行以下步骤：

    1. 对于每个 device（属于 this.[[devices]]）：

      1. 如果 device 不与该 HIDDevice 共享设备访问权限，则继续处理下一个设备。

      2. 将 device.[[state]] 设为 "forgetting"。

      3. 对于每个 pendingPromise（属于 device.[[pendingSendReportPromises]]）：

        1. 拒绝 pendingPromise，理由为一个 "AbortError" DOMException。

      4. 清空 device.[[pendingSendReportPromises]]。

      5. 对于每个 pendingPromise（属于 device.[[pendingSendFeatureReportPromises]]）：

        1. 拒绝 pendingPromise，理由为一个 "AbortError" DOMException。

      6. 清空 device.[[pendingSendFeatureReportPromises]]。

      7. 对于每个 pendingPromise（属于 device.[[pendingReceiveFeatureReportPromises]]）：

        1. 拒绝 pendingPromise，理由为一个 "AbortError" DOMException。

      8. 清空 device.[[pendingReceiveFeatureReportPromises]]。

      9. 调用用户代理，以撤销对所有HID 接口的访问权限，这些接口由 device 暴露。

      10. 将 device.[[state]] 设为 "forgotten"。

    2. 将一个全局任务加入队列，目标为相关全局对象（属于 this），使用HID 设备任务源，以兑现 promise，值为 undefined。

  3. 返回 promise。

7.4. sendReport() 方法

该sendReport()方法用于发送输出报告，指定reportId和data。如果HID 接口不使用报告 ID，则传入 0，而不是报告 ID。

对于HID 接口中使用报告 ID的接口，报告 ID 值 0 是保留值，不应使用。

sendReport() 方法的步骤如下：

  1. 令 promise 为一个新的 promise。

  2. 如果 this.[[state]] 不是 "opened"，则拒绝 promise，理由为一个 "InvalidStateError" DOMException，并返回 promise。

  3. 如果 reportId 为 0，且HID 接口（由 this 表示）使用报告 ID，或者 reportId 不为 0 且该接口不使用报告 ID，则拒绝 promise，理由为一个 "TypeError" DOMException，并返回 promise。

  4. 追加 promise 到 this.[[pendingSendReportPromises]]。

  5. 并行执行以下步骤：

    1. 如果此报告是受屏蔽的报告，则将一个全局任务加入队列，目标为相关全局对象（属于 this），使用HID 设备任务源，以拒绝 promise，理由为一个 "NotAllowedError" DOMException，并中止这些步骤。

    2. 调用操作系统，以指定的 reportId 和 data 发送输出报告。

    3. 如果此操作因任何原因失败，则将一个全局任务加入队列，目标为相关全局对象（属于 this），使用HID 设备任务源，以拒绝 promise，理由为一个 "NetworkError" DOMException，并中止这些步骤。

    4. 将一个全局任务加入队列，目标为相关全局对象（属于 this），使用HID 设备任务源，以兑现 promise，值为 undefined。

  6. 返回 promise。

10. HIDCollectionInfo 字典

dictionary HIDCollectionInfo {
    unsigned short usagePage;
    unsigned short usage;
    octet type;
    sequence<HIDCollectionInfo> children;
    sequence<HIDReportInfo> inputReports;
    sequence<HIDReportInfo> outputReports;
    sequence<HIDReportInfo> featureReports;
};

设备首次连接到系统时，系统必须取得报告描述符，对设备暴露的每个HID 接口都如此。报告描述符是一个字节序列，可展开为层次数据结构，用于描述设备所支持的每个报告的布局。此数据结构的元素称为项目。具有某种关系的一组项目称为集合。

一个 HIDCollectionInfo 对象表示报告描述符中的单个集合。当集合包含嵌套集合时，嵌套集合会作为 children 的元素包含在内。

inputReports、outputReports 和 featureReports 属性包含序列，元素为 HIDReportInfo，用于提供此集合中描述的每个报告的信息。对于顶层集合，HIDReportInfo 表示构成报告的所有项目的扁平视图。此扁平视图将嵌套集合中的项目与顶层集合中的项目交错排列。对于嵌套集合，HIDReportInfo 仅包含此集合及其嵌套集合中的项目。

usagePage 成员，类型为unsigned short
该用途页分量，属于HID 用途（与此集合关联）。

HID 用途是常量，应用可对其解释，以识别项目或集合的目的及含义。HID 用途是一个 unsigned long 值，由高位的 unsigned short 用途页与低位的 unsigned short 用途 ID 组成。标准HID 用途值见 [USBIF-HID-CLASS] 以及USB 开发者论坛发布的其他文档。

HID 用途（属于设备暴露的顶层集合）用于识别设备的大致类型。

usage 成员，类型为unsigned short
该用途 ID分量，属于HID 用途（与此集合关联）。

用途 ID 用于选择单个HID 用途，其位于某个用途页上。按照惯例，用途 ID 0x01 至 0x1F 保留给顶层集合使用。

type 成员，类型为octet
一个值，表示集合类型.
集合类型 值
物理 0x00
应用 0x01
逻辑 0x02
报告 0x03
具名数组 0x04
用途切换 0x05
用途修改 0x06
保留供将来使用 0x07 至 0x7F
供应商定义 0x80 至 0xFF

每种集合类型描述分组项目之间的不同关系。请参阅 [USBIF-HID-CLASS] 第 6.2.2.6 节，了解有关集合类型的更多信息。

children 成员，类型为序列<HIDCollectionInfo>
一个序列，其中包含HIDCollectionInfo，表示嵌套在此集合内的集合。
inputReports 成员，类型为序列<HIDReportInfo>
一个序列，其中包含HIDReportInfo，表示此集合中描述的输入报告。
outputReports 成员，类型为序列<HIDReportInfo>
一个序列，其中包含HIDReportInfo，表示此集合中描述的输出报告。
featureReports 成员，类型为序列<HIDReportInfo>
一个序列，其中包含HIDReportInfo，表示此集合中描述的特征报告。

"none"

取得页面可访问的设备列表。默认情况下，没有可访问的设备，因为页面尚未获得访问任何设备的权限。 
document.addEventListener('DOMContentLoaded', async () => {
  let devices = await navigator.hid.getDevices();
  devices.forEach(device => {
    console.log(`HID: ${device.productName}`);
  });
});
为 HID 设备的连接和断开注册事件监听器。 
navigator.hid.addEventListener('connect', ({device}) => {
  console.log(`HID connected: ${device.productName}`);
});

navigator.hid.addEventListener('disconnect', ({device}) => {
  console.log(`HID disconnected: ${device.productName}`);
});
无法通过getDevices()访问设备，也不会产生连接事件，直到获得访问该设备的权限。页面可以使用以下方法请求权限：requestDevice()。在此示例中，页面请求访问具有以下标识的设备：供应商 ID 0xABCD。设备必须还具有一个集合，其用途为用途页消费类（0x000C）和用途 ID消费类控制（0x0001）。具有以下标识的设备：产品 ID 0x1234，已被报告为无法正常工作。 
let requestButton = document.getElementById("request-hid-device");
requestButton.addEventListener("click", async () => {
  let device;
  try {
    const devices = await navigator.hid.requestDevice({
      filters: [
        {
          vendorId: 0xabcd,
          usagePage: 0x000c,
          usage: 0x0001,
        },
      ],
      exclusionFilters: [
        {
          vendorId: 0xabcd,
          productId: 0x1234,
        }
      ],
    });
    device = devices[0];
  } catch (error) {
    console.log("An error occurred.");
  }

  if (!device) {
    console.log("No device was selected.");
  } else {
    console.log(`HID: ${device.productName}`);
  }
});

以下操作的结果：解析屏蔽列表，位于 URLurl，是一个序列，由字典对象组成，生成方式是获取url并将其内容按 JSON 解析。

HID 屏蔽列表是解析屏蔽列表的结果，其地址为 https://github.com/whatwg/hid/blob/main/blocklist.txt

报告为受屏蔽的报告，当且仅当以下步骤返回true:

  1. 对于每个 rule（属于HID 屏蔽列表）：

    1. 如果报告被屏蔽列表规则屏蔽，规则为 rule，则返回 true。

  2. 返回 false。

报告被屏蔽列表规则屏蔽 rule，当且仅当以下步骤返回true:

  1. 令 reportId 为该报告的报告 ID；如果HID 接口不使用报告 ID，则为 0。

  2. 令 reportType 为 "input"（如果报告是输入报告）、"output"（如果报告是输出报告），或 "feature"（如果报告是特征报告）。

  3. 令 collection 为包含该报告的顶层集合。

  4. 如果 rule 包含 "vendor"，且 rule["vendor"] 不是 device.vendorId，则返回 false。

  5. 如果 rule 包含 "product"，且 rule["product"] 不是 device.productId，则返回 false。

  6. 如果 rule 包含 "reportId"，且 rule["reportId"] 不是 reportId，则返回 false。

  7. 如果 rule 包含 "reportType"，且 rule["reportType"] 不是 reportType，则返回 false。

  8. 如果 rule 包含 "usagePage"，且 rule["usagePage"] 不是 collection["usagePage"]，则返回 false。

  9. 如果 rule 包含 "usage"，且 rule.["usage"] 不是 collection["usage"]，则返回 false。

  10. 返回 true。
