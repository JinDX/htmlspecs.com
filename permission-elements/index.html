摘要

用于在页面内请求浏览器权限的 HTML 元素。

本规范定义了一组新的 HTML 元素，其共同目标是为用户提供一种 从页面内控制浏览器权限及相关 能力的方式。

对此新元素施加适当的样式和 UI 约束，可确保用户 理解点击该元素意味着什么，从而使浏览器能够高度 确信用户有意作出权限决定。 这些权限元素旨在比当前由脚本触发的权限流程更易于访问、更安全且更加 用户友好。

1. 简介

用户 代理向网站公开强大功能，这些功能对某些用例非常重要， 但也很容易被滥用。此类强大功能中可以说最典型的 示例是摄像头访问，它对于在线会议等许多用例 至关重要，但未经请求便激活摄像头会造成严重的隐私问题。为处理此问题，用户 代理使用权限来询问用户是否希望允许某项特定 访问。

这些权限请求最初是一种相当直接的传递机制：网站会 请求某项能力，而用户代理会立即提示用户对该请求 作出决定。然而，垃圾信息和滥用迫使用户代理 采取更具倾向性的方式来保护用户的安全、隐私和 注意力。当前的情况是，用户会收到大量权限请求， 而用户往往并不清楚这些请求可能产生什么后果。

本规范引入了一种新机制，通过页面内元素请求并启动对 强大功能的访问，并内置防止 滥用的保护措施。此机制旨在将权限请求与其实际使用的上下文 关联起来，从而减少“权限轰炸”，同时 为实现提供更可靠的用户意图信号。

2. HTML 权限元素的共同行为：InPagePermissionMixin

本规范中的元素具有许多共同行为，这些行为 由InPagePermissionMixin 及其相关状态、 算法和渲染规则进行定义。

InPagePermissionMixin 接口混入定义如下：

interface mixin InPagePermissionMixin {
  readonly attribute boolean isValid;
  readonly attribute InPagePermissionMixinBlockerReason invalidReason;
  readonly attribute PermissionState initialPermissionStatus;
  readonly attribute PermissionState permissionStatus;

  attribute EventHandler onpromptaction;
  attribute EventHandler onpromptdismiss;
  attribute EventHandler onvalidationstatuschange;
};

使用此混入的元素应支持以下 内容属性：

isValid
查询元素当前是否可以激活。
invalidReason
返回表示元素当前无法激活原因的字符串。
onpromptdismiss
当用户关闭因与该元素交互而产生的权限提示时发出通知
onpromptaction
当用户回答了因与该元素交互而产生的权限提示时发出通知 （无论肯定还是否定）。
onvalidationstatuschange
当验证状态发生变化时发出通知。

isValid 属性反映该 权限元素当前是否未被阻止。

invalidReason 属性是一个 枚举属性，它反映权限 元素的内部状态。其值集合为InPagePermissionMixinBlockerReason。

元素会观察全局lang 属性， 以选择本地化文本。

元素上的全局 tabindex 内容属性的默认 值 为 0。

以下是包含InPagePermissionMixin 的元素必须支持的事件处理器（及其对应的事件处理器事件类型）：

onpromptaction 事件
onpromptdismiss 事件
onvalidationstatuschange 事件

2.1. Mixin 内部状态

HTML 权限元素表示 由用户可请求的权限所管控的能力， 用户可以激活这些元素，使网站开始访问相应能力。 这些元素的核心在于，此类请求应由用户 触发，而不是由页面脚本触发。为强制执行 此要求，元素会检查激活事件是否为受信任的。 此外，它还会监视多种条件，例如元素是否 （部分）被遮挡，或者最近是否被移动。元素维护一个内部[[BlockerList]] 来跟踪这些情况。

InPagePermissionMixin 元素具有以下内部槽：

  • [[Features]] 为 null 或由有序集合组成，其中包含强大功能。对于大多数权限 元素，这可能是固定集合，而对于某些元素则可能是可变的。 将其设为内部槽，使我们能够编写适用于所有 此类元素的算法。

  • [[InitialPermissionStatus]] 是一个PermissionState， 用于存储 [[Features]] 的初始PermissionState。

  • [[BlockerList]] 是一个 记录列表，其中包含 阻止器时间戳和 阻止原因。阻止原因是一个InPagePermissionMixinBlockerReason， 但不能是空字符串。

  • [[IntersectionObserver]] 是对IntersectionObserver 的引用。

  • [[IntersectionRect]] 是 一个 DOMRectReadOnly， 用于存储最近一次观察到的交叉区域，即 permission 相对于视口的位置。

  • [[LastNotifiedValidState]] 是一个布尔值，用于存储最近一次通知的 isValid 状态。

  • [[LastNotifiedInvalidReason]] 是一个字符串，用于存储最近一次通知的 invalidReason 状态。 [[LastNotifiedValidState]] 和[[LastNotifiedInvalidReason]] 用于 确定是否需要分派 onvalidationstatuschange 事件。

2.2. Mixin 在 可导航对象上的支持状态

为了支持InPagePermissionMixin， 可导航对象维护一个元素的有序集合，即[[PermissionElements]]。此有序 集合用于评估类型为unsuccesful_registration 的阻止器。

2.3. Mixin 激活和激活阻止器

权限元素系列的关键目标是反映用户的 有意识选择，我们需要确保用户不会轻易被欺骗 而激活它。为此，权限元素会维护一个 阻止原因列表，这些原因可能永久或暂时阻止元素 被激活。

这些行为中的大多数对于所有权限元素都应相同。 为简单起见，我们还会包含仅适用于一个元素或某些 元素的阻止器。

enum InPagePermissionMixinBlockerReason {
  // 无阻止原因。
  "",

  // 所有 InPagePermissionMixin 使用者均支持的阻止原因。
  "illegal_subframe", "unsuccesful_registration",
  "recently_attached", "intersection_changed",
  "intersection_out_of_viewport_or_clipped",
  "intersection_occluded_or_distorted", "style_invalid",

  // HTMLPermissionElement 特有的阻止原因。
  "type_invalid",
};

权限元素会跟踪“阻止器”，即元素（当前）无法激活的原因。 这些阻止器具有三种生命周期：永久、临时和到期。

永久 阻止器

一旦元素具有永久阻止器，它将被永久禁用。 这类阻止器用于网站所有者应当修复的问题。 一个示例是位于 fencedframe 内的 permission 元素。

临时 阻止器

这种阻止器仅在阻止条件仍然存在时有效。 一个示例是当前不在视野中的 permission 元素。所有临时阻止器都会在条件不再适用后 转变为到期阻止器。

到期 阻止器

这种阻止器仅在固定时间段内有效。它用于 阻止诸如“点击劫持”之类的滥用场景。一个示例是 最近被移动过的 permission 元素。

阻止器名称 阻止器类型 示例条件 顺序提示
type_invalid 永久 设置了不受支持的权限类型 时。 1
illegal_subframe 永久 元素在 fencedframe 内使用时。 2
unsuccesful_registration 临时 同一文档中插入了过多针对同一 强大功能的其他元素时。 3
recently_attached 到期 元素刚刚附加到 DOM 时。 4
intersection_changed 到期 元素正在移动时。 6
intersection_out_of_viewport_or_clipped 临时 元素未处于或未完全处于视口中时。 7
intersection_occluded_or_distorted 临时 元素完全位于视口中， 但仍未完全可见时（例如部分位于其他内容之后）。 8
style_invalid 临时 9
要使用InPagePermissionMixinBlockerReason reason 和可选标志 expires 添加阻止器：

  1. 断言：reason 不是 ""。 （InPagePermissionMixinBlockerReason 中的空字符串表示不存在阻止器。 为什么要添加一个不产生阻止作用的空字符串阻止器？）

  2. 令 timestamp 为 None。

  3. 如果 expires，则令 timestamp 为当前高分辨率时间 加上阻止器延迟。

  4. 向内部[[BlockerList]] 中追加一个包含 reason 和 timestamp 的条目。

阻止器延迟为 500ms。
要使用InPagePermissionMixinBlockerReason reason 添加到期阻止器：

  1. 断言：reason 在阻止器 原因表中列为“到期”。

  2. 使用 reason 和 true添加阻止器。

要使用InPagePermissionMixinBlockerReason reason 添加临时阻止器：

  1. 断言：reason 在阻止器 原因表中列为“临时”。

  2. 使用 reason 和 false添加阻止器。

要使用InPagePermissionMixinBlockerReason reason 添加永久阻止器：

  1. 断言：reason 在阻止器 原因表中列为“永久”。

  2. 使用 reason 和 false添加阻止器。

要从 element 中使用 InPagePermissionMixinBlockerReason reason 移除阻止器：

  1. 断言：reason 在 阻止器 原因表中列为“临时”。

  2. 对于 element 的[[BlockerList]] 中的每个 entry：

    1. 如果 entry 的 reason 与 reason相等， 则从 element 的[[BlockerList]] 中移除 entry。

  3. 使用 reason 和 true添加阻止器。

要确定一个InPagePermissionMixin element 的 阻止器：

  1. 令 blockers 为使用阻止器排序算法对 element 的[[BlockerList]] 进行排序的结果。

  2. 如果 blockers 不为空，且 blockers[0] 正在阻止，则返回 blockers[0]。

  3. 不返回任何内容。

要确定两个阻止器 a 和 b 的 阻止器排序：

  1. 令 really large number 为 99。

  2. 断言：阻止器原因表中没有任何 顺序提示等于或 大于 really large number。

  3. 如果 a 正在阻止，则令 a hint 为 阻止器 原因表中 a 的原因对应的 顺序提示；否则令 a hint 为 really large number。

  4. 如果 b 正在阻止，则令 b hint 为 阻止器 原因表中 b 的原因对应的 顺序提示；否则令 b hint 为 really large number。

  5. 返回 a hint 是否小于或等于 b hint。

如果满足以下条件，则InPagePermissionMixin 的阻止器列表的 entry 正在阻止：

  1. entry 没有阻止器时间戳，

  2. 或者 entry 具有阻止器时间戳，且该阻止器时间戳 大于或等于当前高分辨率时间。

注：本规范以列表[[BlockerList]] 的形式维护阻止器，该列表 可能会无限增长（因为某些阻止器类型只是到期， 但不会被移除）。 选择这种结构是为了便于说明，而不是为了 提高效率。除这里定义的少数算法之外，此阻止器结构的细节 不可观察，这应当为实现以更高效的方式处理它 提供充足空间。

2.4. Mixin 算法

一个InPagePermissionMixin element 的isValid 获取器步骤为：

  1. 返回 element 的阻止器是否为 Nothing。

一个InPagePermissionMixin element 的invalidReason 获取器步骤为：

  1. 如果 element 的阻止器为 Nothing，则返回 ""。

  2. 否则，返回 element 的阻止器的原因字符串。

一个InPagePermissionMixin element 的 initialPermissionStatus 获取器步骤为：

  1. 返回 element 的内部[[InitialPermissionStatus]]。

一个InPagePermissionMixin element 的 permissionStatus 获取器步骤为：

  1. 返回为 element获取当前 权限状态的结果。

如何为一个InPagePermissionMixin element 获取当前权限状态 取决于包含该混入的具体元素。 因此，每个元素都必须定义自己的算法。

2.5. Mixin 事件算法

要为 element 可能分派 onvalidstatechange：

  1. 令 oldState 为[[LastNotifiedValidState]]。

  2. 令 newState 为 element 的阻止器是否为 Nothing。

  3. 将[[LastNotifiedValidState]] 设置为 newState。

  4. 令 oldReason 为[[LastNotifiedInvalidReason]]。

  5. 令 newReason 为 element 的 invalidReason。

  6. 将[[LastNotifiedInvalidReason]] 设置为 newReason。

  7. 如果 oldState != newState 或 oldReason != newReason， 则：

    1. 令 event 为一个新的Event。

    2. 使用 type “onvalidationstatuschange”、 bubbles true 和 cancelable true初始化 event。

    3. 将 event分派给 element。

要为 element 分派 onpromptaction：

  1. 令 event 为一个新的Event。

  2. 使用 type “onpromptaction”、 bubbles true 和 cancelable true初始化 event。

  3. 将 event分派给 element。

要为 element 分派 onpromptdismiss：

  1. 令 event 为一个新的Event。

  2. 使用 type “onpromptdismiss”、 bubbles true 和 cancelable true初始化 event。

  3. 将 event分派给 element。

3. 共同渲染和样式限制

权限元素是不可退化部件，主要 像 button 一样渲染。 按钮标签在很大程度上应由浏览器而非页面 决定，并以文本和图标的形式反映[[Features]] 中列出的一个或多个 强大功能。该元素还可以传达 底层强大功能当前状态的信息。实际渲染由各 元素定义。

页面可以影响权限元素的样式，但会受到 防止滥用的约束（例如字体和标签本身的最小及 最大尺寸）。页面还可以通过 lang 属性为文本选择区域设置。

权限元素支持回退内容，尚不支持相应元素的 浏览器将显示这些内容。请注意， 即使浏览器支持相应权限元素，也存在 回退到其回退内容的情况。

3.1. 呈现

详细描述用户代理 UI 的先例并不多。 给用户代理保留更多自由度可能更好。

权限元素包含由浏览器选择的内容、文本，或许还有一个 图标。激活它们通常会提示用户作出选择。 这提供了两部分用户可以交互的用户界面。 用户 代理可以在很大程度上自由决定这两者——元素的渲染以及 后续的权限 提示——采用它认为最能传达元素意图的方式。

权限元素呈现的 UI 选项包括：

  • 使用元素的语言所指示的语言， 对[[Features]] 中列出的强大功能进行命名。 请注意，如果存在 lang 属性，则始终使用该属性所指示的语言。

  • 指示强大功能类型的一个或多个图标。

  • 所涉及强大功能的当前 权限状态。 例如，如果相应权限已经 授予， 则 permission 元素可以标记为 “地理位置已在使用中”。

  • 带有“遮罩层”的模态提示。 （即将提示后方的页面变暗。） 这通常会非常具有干扰性。但这里的目标是确保 用户确实有意作出此选择。

鼓励用户 代理以与程序或其运行平台中类似用法一致的方式 命名或描述强大功能。

非常非规范性的示例可能包括：

  • <permission lang="de" types="geolocation">：“Standort verwenden”。

  • <permission types="microphone">（位于英语页面中）：“使用麦克风。🎤”。

  • 激活 <permission types="microphone"> 后，当相应 权限状态为拒绝时， 将文本修改为 “继续阻止”。

3.2. 样式

权限元素会限制可应用于它们的样式。 这些约束分为三类：

  1. 如果条件不满足，则停用该元素。

  2. 由用户代理定义的样式表强制应用某些样式。

  3. 用户代理对其他样式强制实施界限，这些界限 无法轻易用 CSS 表达。例如，当样式界限是 相对于元素的计算样式表示时。

3.2.1. 停用元素的条件

如果其中一个条件未满足，则添加一个 类型为style_invalid 的临时阻止器。

'color'、'background-color' 默认设置为用户代理的默认 button 颜色。 两种颜色之间的对比度必须至少为 3。 Alpha 必须为 1。
'font-size' 如果指定值表示为<relative-size>：
  • 则 font-size 必须介于small 和 xx-large 之间。
  • 否则，计算值必须大于或等于 small 的计算值，并且小于或等于 xx-large 的计算值。

定义“alpha”。

3.2.2. 用户代理定义的样式表

权限元素应使用以下样式渲染：

@namespace "http://www.w3.org/1999/xhtml";
permission, geolocation {
  opacity: 1.0;
  line-height: normal !important;
  whitespace: nowrap !important;
  user-select: none !important;
  appearance: auto !important;
  box-sizing: content-box !important;
  vertical-align: middle !important;
  text-emphasis: initial !important;
  text-shadow: initial !important;
}

3.2.3. 用户代理定义的其他样式界限

权限元素为样式定义了若干界限。例如，我们希望 字体大小受到约束。样式界限说明如下。

为了便于表示，我们设想可以在 CSS 规则中通过 computed 访问元素的计算 值，就像可以通过 inherit 关键字访问元素的继承值一样。 那么，以下样式表可表示这些样式界限： 

@namespace "http://www.w3.org/1999/xhtml";
permission {
  outline-offset: clamp(0, computed, none); /* 不允许负的 outline-offset。 */
  font-weight: clamp(200, computed, none);  /* 不允许低于 200 的 font-weight。 */
  word-spacing: clamp(0, computed, 0.5em);  /* word-spacing 介于 0..0.5em */
  letter-spacing: clamp(-0.05em, commputed, 0.2em);  /* letter-spacing 介于 -0.05..0.2em */

  min-height: clamp(1em, computed, none);
  max-height: clamp(none, computed, 3em);
  min-width: clamp(none, computed, calc(fit-content));

  border-width: clamp(none, computed, 1em);

  font-style: if(computed = "normal" or computed = "italic", computed, "normal");
  display: if (computed = "inline-block" or computed = "none", computed, "inline-block");
  cursor: if (computed = "pointer" or computed = "not-allowed", computed, "pointer")
}

此外，还会根据难以用 CSS 表达的条件应用一些规则。

如果height 为 auto，则应用： 

@namespace "http://www.w3.org/1999/xhtml";
permission {
  padding-top: clamp(1em, computed, none);
  padding-bottom: calc(padding-top);
}

如果width 为 auto，则应用： 

@namespace "http://www.w3.org/1999/xhtml";
permission {
  padding-left: clamp(none, computed, 5em);
  padding-right: calc(padding-left);
}

如果元素不具备以下全部条件，则应用以下样式表：

  • 边框宽度至少为 1px，

  • color 与 background-color 的对比度至少为 3，

  • 并且 alpha 为 1。

@namespace "http://www.w3.org/1999/xhtml";
permission {
  max-width: clamp(none, computed, calc(3 * fit-content));
}

4.2.1. type 属性

权限类型不能修改。随意修改权限类型 可能导致用户困惑，因此我们希望阻止这种情况。不过， 由于页面可能动态创建 permission 元素，我们仍需要提供 修改它的 API。为此，我们区分新初始化状态和 空状态或无效状态（无权限），前者允许设置 类型，后者则不允许。

示例：

// 更改有效类型：
var pepc = document.createElement("permission");
pepc.type = "camera";  // 可以。
pepc.type;  // "camera"。
pepc.type = "geolocation";  // 不可以。若作为初始赋值则可以。
pepc.type;  // "camera"。反映未发生变化的内部状态。

// 设置无效类型：
pepc = document.createElement("permission");
pepc.type = "icecream";  // 冰淇淋不是强大的浏览器功能。不可以。
pepc.type;  // ""。反映内部状态。
pepc.type = "camera";  // 仍然不可以，因为 type 已经设置过。
                       // 若作为初始赋值则可以。
pepc.type;  // ""。反映未发生变化的内部状态。

  2. 返回一个字符串，其中包含[[Features]] 中所有强大功能名称的连接结果， 并以“ ”分隔。

HTMLPermissionElement 的type 设置器步骤为：

  1. 如果[[Features]] 不为 null：返回。

  8. 如果this的类型不允许，则使用unsuccesful_registration 添加临时阻止器。

  3. 在this上可能分派 onvalidstatechange。

给定 event 时，一个 permission element 的激活行为为：

  1. 断言：element 的[[Features]] 不为 null。

  2. 如果 element 的[[Features]] 为空，则返回。

  3. 如果 event.isTrusted 为 false，则返回。

  4. 如果 element.isValid 为 false，则返回。

  5. 令 descriptor 为为 element构建权限 描述符的结果。

  6. 请求使用由 descriptor 描述的强大功能的权限。

  7. 如果上一步被用户取消或关闭，则在 this 上分派 onpromptdismiss 并返回。

    [PERMISSIONS] 规范假定请求使用权限 总会成功。也就是说，它假定用户总会作出 选择，并且算法总会给出与该选择对应的 grant/deny 答案。但你无法强迫用户这样做。 一些用户代理可能一方面为明确 拒绝提供一种 UI 控件（例如“拒绝”按钮），另一方面为取消或关闭 请求对话框提供另一种控件（例如右上角的“X”按钮）。尽管底层规范中 没有明确的挂钩，我们仍在此区分这两种操作。

要为一个HTMLPermissionElement element 构建权限描述符：

[Permissions] 规范假定描述符描述的是 不带参数的单个权限（例如 enableHighAccuracy 的等效项）。 在此，我们假定一种表达能力更强的权限模型。 这需要解决——很可能应在上游 [Permissions] 中解决，并在此处作相应调整。

  1. 令 result 为一个新的PermissionDescriptor。

  2. 填充 result：

    • 包含 element 的[[Features]] 中包含的强大功能名称。

  3. 返回 result。

HTMLPermissionElement 的IntersectionObserver 回调实现 IntersectionObserverCallback 并运行以下步骤：

  1. 断言：IntersectionObserver 的root 是文档

  2. 令 entries 为第一个回调参数的值，即 交叉观察器条目 的列表。

  3. 断言：entries 不为空。

  4. 令 entry 为 entries 的最后一个项。

  5. 如果 entry.isVisible， 则：

    1. 使用intersection_occluded_or_distorted 移除阻止器。

    2. 使用intersection_out_of_viewport_or_clipped 移除阻止器。

  6. 否则：

    1. 如果 entry.intersectionRatio >= 1，则：

      1. 令 reason 为intersection_occluded_or_distorted。

    2. 否则：

      1. 令 reason 为intersection_out_of_viewport_or_clipped。

    3. 使用 reason添加临时 阻止器。

  7. 如果[[IntersectionRect]] 不等于 entry.intersectionRect， 则使用 intersection_changed 添加到期阻止器。

  8. 将[[IntersectionRect]] 设置为 entry.intersectionRect

  9. 在this上可能分派 onvalidstatechange。

是否需要定义 字典相等性？

要确定一个 element 的类型是否允许：

  1. 断言：element 的节点可导航对象的[[PermissionElements]] 包含 element。

  2. 令 count 为 0。

  3. 对于 element 的节点可导航对象的[[PermissionElements]] 中的每个 current：

    1. 如果 current 是 element，则中断。

    2. 如果 element.[[Features]] 与 current.[[Features]] 相等，则将 count 加 1。

  4. 返回 count 是否小于 3。

要为一个 document 重新检查类型许可性：

  1. 对于 document 的 [[PermissionElements]] 中的每个 current：

    1. 如果 current 的类型允许，则从 current 中使用 unsuccesful_registration 移除阻止器。

要为一个HTMLPermissionElement element 获取当前权限状态：

  1. 令 types 为 element 的内部[[Features]]。

  2. 如果 types 为 null 或 types 为空， 则返回prompt。

  3. 令 current 为granted。

  4. 对于 types 中的每个 type：

    1. 令 state 为针对 type获取当前权限 状态的结果。

    2. 假定以下顺序，令 current 为 current 和 state 中较小者： granted > prompt > denied。

  5. 返回 current。
