摘要

本注册表定义与 媒体源扩展™ 规范配合使用的字节流格式 [MEDIA-SOURCE].

本注册表是非规范性的。

1. 目的

本注册表旨在增强以下对象的实现和用户之间的互操作性： SourceBuffer 对象，其定义见 媒体源扩展™ 规范。具体而言，本注册表提供了以下手段：(1) 识别 并避免字节流格式之间的 MIME 类型冲突；(2) 披露 MSE 实现所接受的字节流格式的信息， 以促进互操作性。

2. 组织方式

注册表维护 MIME 类型/子类型对与字节流格式规范之间的映射。字节流格式规范描述了 以下对象所接受的字节流的结构和语义： SourceBuffer 对象， 该对象使用关联的 MIME 类型/子类型对创建。

本注册表不旨在包含有关字节流格式是否受知识产权主张限制的任何信息。实现者和用户 若打算实现或使用某个特定的字节流格式，建议就此事寻求适当的法律咨询。

3. 注册条目要求

要注册条目，请在以下位置提交议题： 媒体源扩展字节流格式注册表 GitHub 议题跟踪器 以便在将条目添加到注册表之前，对其进行讨论并评估其合规性。

媒体工作组在评估过程中，可以向工作组之外寻求专业意见， 例如向底层格式规范的编辑者或相关标准组寻求意见。 如果底层格式规范尚未公开， 则必须向工作组提供该规范以供评估。 要纳入该条目，媒体工作组内必须至少有一位 实现者对此感兴趣。 如果媒体工作组就接受该候选条目达成共识， 则由注册表编辑者或请求注册该候选条目的一方 发送拉取请求，注册满足 以下要求的候选条目：

  1. 每个条目必须包含一个唯一的 MIME 类型/子类型 对。如果字节流格式派生自现有文件格式，则应使用该文件格式通常使用的 MIME 类型/子类型 对。
  2. 每个条目必须包含一个 [[generate timestamps flag]] 值， SourceBuffer 在处理该字节流格式时必须使用该值。
  3. 每个条目必须包含一个指向公开可用的注册规范的链接。
  4. 每个条目的注册规范都必须符合以下章节列出的所有要求： 字节流格式一节 ，该节位于 媒体源扩展™ 规范 [MEDIA-SOURCE].
  5. 建议免费提供注册规范及其底层规范（如果无法通过在线方式提供，则可以收取合理的运输及处理费用）。

工作组达成共识后， 注册表编辑者将审阅并合并拉取请求。

现有条目发布后，可以通过与候选条目相同的流程进行更改。可能的更改包括修改指向公开规范的链接。

如果某个注册条目不满足上述强制要求，则可以将其从注册表中移除。除此之外，不得删除或弃用现有条目。
