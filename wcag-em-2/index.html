摘要

本文档介绍了一种分步评估数字产品对 《Web 内容无障碍指南》 （WCAG）2符合程度的方法。

它提供了与技术无关的指导，用于定义评估范围、探索目标产品、从产品中选择具有代表性的 样本集、评估选定的样本集并报告 评估结果。此过程适用于不同的评估情境，包括 自我评估和第三方评估。

本文档不定义特定功能的说明，因为 WCAG 成功标准和支持文档已涵盖这些内容。本文档 也不定义额外的 WCAG 2 要求，也不以任何方式取代或替代这些要求。

简介

本文档描述了一个用于全面评估数字产品的代表性样本是否符合《Web 内容无障碍指南》（WCAG） 2的过程。

在许多情况下都可能需要对数字产品进行无障碍评估，例如在发布、采购或重新设计产品之前，以及定期监测 产品随时间变化的无障碍表现。

多种因素可能会影响评估，包括：

  • 数字产品的类型（例如网站、移动应用程序、自助服务终端、文档），
  • 数字产品的规模、复杂性及其使用的技术（例如 HTML、 WAI-ARIA、PDF、EPUB），
  • 评估人员对产品设计和开发方式的了解程度，以及
  • 评估的主要目的（例如发布无障碍声明、规划 重新设计过程、开展研究）。

本文档考虑了这些因素，并着重说明了评估人员需要考虑的若干事项。它 为无障碍评估提供了一个通用框架，可作为路线图，帮助评估人员应用 良好实践、避免常见错误，并获得更具可比性的结果。

本文档不能取代在产品开发所有阶段开展质量保证的必要性。 它也不会以任何方式增加或更改规范性 WCAG 2 标准所定义的要求，也不提供逐项功能评估 Web 内容的说明。该 方法可以与满足 WCAG 2 成功标准的技术配合使用，例如WCAG 2.2 技术，但并不要求使用该 技术集或任何其他特定技术集。

目标受众

本方法适用于希望遵循通用方法来评估 数字产品代表性样本对 WCAG 2 符合程度的任何人。这包括：

  • 希望分析并报告数字产品代表性样本的无障碍符合程度， 以便向所有者提供信息的顾问，
  • 希望评估数字产品代表性样本， 以验证无障碍符合程度的无障碍评估服务提供商，
  • 希望评估其数字产品代表性样本的无障碍符合程度， 以便监测或改进产品的开发人员，
  • 希望了解其数字产品代表性样本无障碍符合程度的 产品所有者、采购方和供应商，
  • 希望确保满足质量和政策 要求的合规与质量保证经理，
  • 用于建立基准和比较无障碍符合程度随时间变化情况的 无障碍监测活动，
  • 希望探索无障碍符合实践的 无障碍研究人员和残障权益倡导者，
  • 希望教授评估数字产品代表性样本 无障碍性方法的无障碍培训人员和教育工作者，以及
  • 希望深入了解数字无障碍和 评估的内容作者、设计人员及其他人员。

与 WCAG 2 符合性声明的关系

WCAG 2.2 为单个 Web 页面（以及在某些情况下为 Web 页面集合）定义了符合性要求， 但没有描述如何评估整个网站。它还定义了如何作出可选的符合性声明，以涵盖单个 Web 页面、一系列 Web 页面（例如多页面表单）以及多个相关 Web 页面（例如 网站）。当符合性声明范围内的所有 Web 页面均已分别接受 评估，或通过确保每个页面满足全部符合性要求的过程创建时，此规则适用。

不能仅根据对部分选定 Web 页面和功能的评估， 就为整个网站作出 WCAG 2 符合性声明，因为这些网站始终可能存在 尚未识别的符合性错误。实际上，在使用本评估方法的大多数情况下，仅会选择数字产品中的一个样本进行评估。因此，在 大多数情况下，仅使用本方法并不能作出 WCAG 2 符合性声明。有关如何对使用本方法所得结果作出声明的指导， 请参阅步骤 5.3：提供评估声明（可选）。

使用本方法

本方法用于依据 WCAG 2 对数字产品进行全面评估。在评估 整个数字产品之前，通常最好先对目标产品中的不同样本进行初步评估， 以识别明显的无障碍障碍，并形成对 数字产品无障碍性的整体认识。

简易检查——Web 无障碍初步审查描述了一种与本 方法互为补充的初步评估方法。

所需专业知识

本方法的使用者应充分了解如何使用 WCAG 2 评估内容、无障碍设计、辅助技术，以及不同残障人士如何使用数字 产品。

这包括了解：

  • 技术，
  • 残障人士所遇到的无障碍障碍，
  • 残障人士使用的辅助技术和适应性方法，以及
  • 用于识别残障人士所遇障碍的评估技术、工具和方法。

特别是，假定本方法的使用者非常熟悉 背景阅读材料中列出的所有资源。

综合专业知识

本方法可以由具备上一节 （所需专业知识）中所述技能的单个评估人员执行，也可以由具备综合 专业知识的评估团队执行。

当单个评估人员不具备全部所需专业知识时， 有时有必要或有益地结合不同评估人员的专业知识。

使用综合专业知识评估 Web 无障碍进一步介绍了如何利用评审团队的综合专业知识。

让用户参与

让残障人士（他们并非经验丰富的评估人员，也不是评审团队成员）参与，可能有助于 识别仅依靠专家评估难以发现的其他无障碍障碍。 虽然使用本方法并不强制要求这样做，但强烈建议评估人员在评估过程中让 具有广泛能力差异的真实用户参与。

让用户参与 Web 无障碍 评估进一步介绍了如何让用户参与 Web 无障碍评估。

评估工具

本方法不依赖任何特定的无障碍评估工具、Web 浏览器或其他 软件工具。虽然大多数无障碍检查无法完全自动化，但评估工具可以 在评估过程中为评估人员提供重要帮助，并促进更有效的 评估。例如，一些无障碍评估工具可以扫描整个数字产品，帮助 识别相关样本以进行人工评估。工具还可以在人工 （由人执行的）无障碍检查评估过程中提供帮助。

选择 Web 无障碍评估 工具进一步介绍了如何使用工具。

适用范围

本方法旨在评估完整、自包含的数字产品，例如 网站。在步骤 1.1中，评估人员会准确界定评估范围。

产品封闭原则

完整的产品封闭至关重要，这意味着定义范围时应包括数字产品的所有视图、状态和 功能，而不排除任何特定部分。从范围中排除数字产品的特定部分 很可能会与 WCAG 2.2 关于完整页面和完整流程的符合性要求相冲突，或以其他方式扭曲评估 结果。

特定类型 数字产品的注意事项

本方法适用于多种数字产品。以下内容给出了 特定情况下的注意事项。

网站
网站的规模各不相同，可能只有一个页面，也可能包含数千甚至更多 页面。页面众多的网站可以使用抽样过程选择 具有代表性的样本集。对于页面较少的网站，可以评估 所有页面并跳过抽样过程。
Web 应用程序
Web 应用程序通常包含大量动态生成的内容和功能。 它们往往更复杂、更具交互性。因此，它们通常需要更多时间和 精力进行评估，并且通常需要更大的样本集。Web 应用程序的部分 示例包括基于 Web 的电子邮件客户端、文档编辑器、视频共享 平台、社交媒体网站和预订平台。
原生、混合和 跨平台应用程序
对于原生、混合和跨平台应用程序，无法生成 URL 列表作为 代表性样本集的基础。相反，可以通过 独特的屏幕截图和/或通往特定样本的路径描述来识别样本。
自助服务终端、 自助服务设备和机顶 盒的界面
当界面可以在浏览器中测试时，请参阅 Web 应用程序的注意事项。
当在硬件终端上运行界面时对其进行评估，通常无法 生成 URL 列表。可以通过独特的屏幕截图、照片和/或 通往特定样本的路径描述来识别样本。
文档
当评估目标是单个文档时，评估范围通常包括整个 文档或其特定部分，具体取决于文档的复杂性。请注意，文档样本可能没有可用的 URL。此时可以使用文档标题以及可能的文件名来 指定样本。
注
这并非详尽列表。

特定评估情境

本方法可应用于不同情况和情境。以下注意事项适用于 特定的评估情况和情境：

符合性的自我评估
内部评估人员以及参与开发过程的评估人员通常更容易接触 数字产品的开发人员和维护人员、开发与托管环境、 创作工具以及用于开发和维护的材料。特定使用场景、 设计分析、技术规范和文档以及测试资源可以使 评估更加有效，应尽可能加以利用。
第三方符合性评估
独立外部评估人员通常对数字产品的内部软件、区域和 功能了解较少，因为他们没有参与产品采购，也没有参与 数字产品的设计和开发过程。此类情况下的评估人员通常需要联系 产品所有者或开发人员，以获取使评估更加有效所需的信息。
开发期间的评估
尽管本方法主要用于评审已经 开发完成的数字产品，但在数字产品的整个设计和实现阶段评估无障碍性 对确保其未来符合要求至关重要。本方法提供的指导 在设计和开发过程的这些早期阶段也可能有用，但可能需要作出一定调整。 然而，需要注意的是，在这些 早期阶段进行的评估，即使只实施细微更改，也可能迅速过时。因此， 在这些阶段进行的评估不应用于对最终数字产品作出声明或符合性 声明。
评估第三方内容
数字产品无法控制第三方内容，例如社交媒体网站或 评论聚合器上的评论。WCAG 2 在部分符合 声明一节中对这类内容的符合性给出了具体注意事项。在这种情况下，评估人员需要确定此类内容是否 得到定期监测和修复（在两个工作日内），以及不符合要求的内容是否 在其出现的所有 Web 页面中被明确标识为不符合要求。
重新执行产品评估
依据本方法进行的评估可在短期后重新执行；例如，当 产品所有者或开发人员识别并修复问题之后，或定期重新执行以监测 进展。在这种情况下，可以使用包含以下内容的样本开展评估：
  • 前次评估中所用样本的子集，以 便于比较结果，以及
  • 替换前次评估中所用样本的一部分， 以改善视图覆盖范围。

除非数字产品发生重大变化，否则通常无需更改 所选样本的规模或抽样方法。新样本集中被替换的样本数量 通常约为初始样本集的一半，但当大多数样本 符合 WCAG 2 时，可以增加该比例。

大规模评估
对大量数字产品开展大规模评估——例如用于国家或国际 调查——通常主要使用自动化评估工具完成。只有相对较少的 视图会接受完整的人工检查。此类评估通常无法达到 本方法所针对的、每个产品符合性评审所需的定性深度。

评估过程

评估过程包含五个步骤。有时步骤顺序可能有所不同，具体取决于数字 产品的类型和评估目的。

这些步骤是：

  1. 定义评估范围
  2. 探索目标产品
  3. 选择具有代表性的样本集
  4. 评估选定的样本集
  5. 报告结果

评估人员可以从一个步骤进入下一个步骤，也可以在过程中发现 新信息时返回任何先前步骤。

步骤 1：定义评估范围

方法要求 1：根据方法要求 1.1、方法要求 1.2和方法要求 1.3 定义评估范围，并可选择根据方法要求 1.4进行定义。

通常，此步骤需要评估委托方（其可能是也可能不是产品所有者）参与， 以统一预期，并对产品进行初步探索。

步骤 1.1：定义数字产品的范围

方法要求 1.1：根据适用范围定义目标数字产品，从而可以明确判断每个视图是否属于 评估范围。

定义目标产品时，应考虑适用 范围中的注意事项，例如：

  • https://example-museum.org 上的所有内容。
  • 位于https://shop.example-museum.org 的“Example 博物馆商店”中的所有内容，但 临时艺术藏品除外

在此步骤中保持清晰明确、避免对哪些视图 属于评估范围产生任何疑问非常重要。建议在可能的情况下使用包括正则表达式和 Web 地址（URI）列表在内的形式化表示。

记录目标产品的任何特定方面以帮助 识别该产品也很重要。这包括：

  • 第三方内容和服务的使用，
  • 产品的移动版本和语言版本，以及
  • 产品的组成部分，尤其是那些可能不容易被识别为产品组成部分的内容—— 例如，具有不同 Web 地址但仍被视为 目标产品组成部分的网上商店，
  • 与特定 WCAG 成功标准相关的内容或功能，
  • 可能受其他指南约束的内容或功能。

步骤 1.2：定义符合性目标

方法要求 1.2：为评估选择目标 WCAG 2 符合级别（A、AA 或 AAA）。

注

WCAG 2 AA 级是普遍接受并推荐的目标。

注

超出数字产品的符合性目标进行评估通常很有用。例如， 产品可能满足更高符合级别中的某些要求。 记录这些信息有助于更有效地规划未来改进。

步骤 1.3：定义无障碍支持基线

方法要求 1.3：定义 数字产品所提供功能应获得无障碍支持的 Web 浏览器、辅助技术和其他用户代理。

尤其对于新技术而言，并不总能确保数字产品提供的每项无障碍 功能（例如媒体播放器中的“显示字幕”功能） 都受到操作系统、Web 浏览器、辅助技术和 其他用户代理的所有可能组合支持。WCAG 2 不预先规定必须 支持哪些功能与技术组合，因为这取决于产品的具体情境，包括其语言、 用于创建内容的技术以及当前可用的用户代理。理解 无障碍支持进一步介绍了 WCAG 2 中的无障碍 支持概念。

在此步骤中，评估人员确定产品预期能够配合使用的操作系统、Web 浏览器、辅助技术以及其他应用程序/用户代理的最低组合集合， 该集合应与上文链接的 WCAG 2 无障碍支持指导保持一致。 此步骤应与评估委托方协商完成，以确保对目标无障碍支持级别形成共同 预期。产品所有者和产品 开发人员也可能拥有一份产品设计时计划支持的组合列表，该列表 可以作为此步骤的起点。根据评估目的，可能 需要更新此列表。例如，为评估产品 与较新浏览器配合工作的情况，可能需要更新该列表。

注

对基线的初始定义不会限制评估人员以后使用 其他操作系统、Web 浏览器、辅助技术和其他用户代理。 例如，评估人员可能使用其他组合来评估 在评估过程早期未识别的内容。在这种情况下，基线将扩展， 以包括所使用的其他工具。

注

对于封闭网络中的某些产品，例如内部网产品，如果用户和 用于访问产品的计算机均已知，则该基线可以限制为 该封闭网络内使用的操作系统、应用程序、Web 浏览器和辅助 技术。然而，在大多数情况下，该基线最好更加广泛， 以涵盖任何适用的特定地理区域和语言社区中残障人士所使用的大多数 当前用户代理。

步骤 1.4：定义其他评估要求（可选）

方法要求 1.4：定义评估人员与评估委托方商定的任何 其他评估要求（可选）。

评估委托方可能需要超出评估目标产品对 WCAG 2 符合程度所需信息之外的其他信息。例如，评估 委托方可能关注：

  • 评估超出从目标数字产品中构成代表性样本集所需范围的 其他视图，
  • 报告问题的所有出现位置，而不仅仅是目标数字产品中 问题类型的代表性示例，
  • 分析与目标数字产品交互时的特定使用场景、情境和 用户群体，
  • 描述超出评估范围的、针对所遇问题的可能解决方案，
  • 让残障用户参与评估，以及
  • 遵循特定的文档或报告模板。

此类与评估人员商定的其他评估要求需要尽早澄清 并记录。这些要求也需要反映在最终报告中。例如， 后续可能需要其他要求来说明样本集选择 是如何进行的。

步骤 2：探索目标数字产品

方法要求 2：根据方法要求 2.1、方法要求 2.2、方法要求 2.3、方法要求 2.4和方法要求 2.5探索待评估的数字 产品。

在此步骤中，评估人员探索待评估的目标产品，以初步 了解产品及其用途、目的和功能。其中许多信息对评估人员而言不会 立即显现，尤其是对于开发团队外部的评估人员。在某些 情况下，也无法详尽识别和列出全部功能、视图类型以及 用于实现产品的技术。产品所有者和产品开发人员的参与可以帮助 评估人员更有效地进行探索。

注

在此步骤中进行初步的粗略检查，有助于识别 与后续详细评估相关的视图。例如，评估人员可能识别出似乎 缺少颜色对比度、文档结构或一致导航的视图，并将其记录下来，以便 后续进行更详细的评估。

注

要执行此步骤，评估人员能够访问产品的所有相关 部分至关重要。例如，可能需要创建账户并确保 产品配置具有代表性。当产品显示数据时，可能需要在开始评估前 预先填充真实数据。

步骤 2.1：识别数字产品的常见视图

方法要求 2.1：识别目标产品的 常见视图。

探索目标产品，以识别其常见视图，其中也可能包括视图的特定状态。 通常，这些视图会直接从目标产品的主要入口点链接（例如网站的主页 或应用程序的启动屏幕），并且经常从其他视图的页眉、导航和 页脚区域链接。此步骤的结果是目标产品所有常见页面或视图的 列表。

步骤 2.2：识别数字产品的基本功能

方法要求 2.2：识别目标产品的 基本功能初始列表。

探索目标产品，以识别其基本功能。虽然某些功能 很容易识别，但其他功能需要更有针对性地发现。例如， 识别网上商店中用于购买商品的功能，可能比识别 商家通过该商店销售商品的功能更容易。此步骤的结果是用户可以在产品上执行的 功能列表。该列表将在后续步骤中用于帮助选择 具有代表性的评估样本。

注

此步骤的目的不是详尽识别产品的所有功能， 而是确定对目标产品的用途和目标至关重要的功能。这 将为后续样本选择及其评估提供依据。其他功能也会 纳入评估，但会通过其他选择机制纳入。

示例 1：产品功能示例
  • 从网上商店选择和购买商品
  • 填写并提交调查表
  • 在产品上注册账户

步骤 2.3：识别样本类型的多样性

方法要求 2.3：识别 样本类型。

具有不同样式、布局、结构和功能的样本通常具有不同程度的无障碍 支持。它们通常由不同的模板和脚本生成，或由不同人员 创作。根据特定产品用户和情境，它们可能具有不同的外观、 不同的行为，并包含不同的内容。

在此步骤中，评估人员探索目标产品，以识别不同 类型的样本。此步骤的结果是对已识别内容类型的描述 列表，而不是具体样本实例。该列表将在 后续步骤中用于帮助选择具有代表性的评估样本集。

注

鼓励评估人员向评估委托方询问不同类型的 样本以及以前的评估，以确保不同类型的内容在评估中得到充分 体现。

示例 2：样本类型示例

评估人员可以查找的不同样本类型示例包括具有以下特征的样本：

  • 在样式、布局、结构、导航、交互和视觉设计方面有所不同，
  • 包括不同类型的内容，例如表单、表格、列表、标题、多媒体和 脚本，
  • 包括不同的功能组件，例如日期选择器、模态叠加层和 轮播组件，
  • 使用不同技术，例如 HTML、CSS、JavaScript、WAI-ARIA、PDF 和 EPUB
  • 来自产品的不同区域（例如主页、网上商店和其他 部门），包括任何应用程序，
  • 反映不同的编码风格和模板（如果评估人员已知），
  • 由不同人员、部门或其他实体创作（如果评估人员已知），
  • 根据用户、设备、浏览器、情境和设置改变外观和行为，
  • 包括动态内容、错误消息、对话框、弹出窗口和其他 交互。

步骤 2.4：识别所依赖的技术

方法要求 2.4：识别为提供产品而依赖的 技术。

在此步骤中，识别符合要求所依赖的技术。这可以包括 HTML、CSS、JavaScript、SVG、WAI-ARIA、PDF 和 EPUB 等技术。此步骤的结果 是一份根据 WCAG 2 所依赖技术的列表。该列表将在后续步骤中用于帮助选择 具有代表性的评估样本。

注

还鼓励识别符合要求所依赖的其他系统。例如：

  • 创作工具，例如内容管理系统
  • 设计系统
  • 前端框架和库
  • 原生平台和/或原生编程语言

鼓励尽可能详细，例如包括版本号 和配置信息。这可以提高评估效率。

步骤 2.5：识别其他相关样本

方法要求 2.5：识别 与残障人士以及数字产品无障碍性相关的 其他样本。

某些数字产品包含与残障人士和 数字产品无障碍性特别相关的样本。此步骤的结果是此类样本的列表，前提是 这些样本尚未在步骤 2.1：识别数字产品的常见视图中 被识别。

示例 3：其他相关样本

其他样本包括：

  • 说明数字产品的无障碍功能
  • 提供有关数字产品使用方式的信息和帮助
  • 说明设置、首选项、选项、快捷键和类似功能
  • 提供联系信息、操作指引和支持说明
  • 支持敏感或高风险功能，例如身份验证、管理个人 信息或金融交易。

步骤 3：选择具有代表性的样本集

方法要求 3：根据方法要求 3.1、方法要求 3.2和方法 要求 3.3，从数字产品中选择具有代表性的样本集。

选择能够代表待评估目标产品的样本集。这有助于确保 评估结果以合理的可信度反映数字产品的无障碍表现。

注

如果可行，建议评估整个数字产品。此时可以 跳过抽样过程。

还有其他一些特定情况，适合跳过抽样过程， 改为评估整个数字产品。这些情况包括数字产品：

  • 只有少量视图——例如某些原生应用程序或自助服务终端，以及
  • 无法有意义地拆分为多个视图——例如某些类型的文档。

跳过抽样过程时，在此评估过程的 后续步骤中将整个产品作为“选定的样本集”。

评估数字产品所需样本集的实际规模取决于许多 因素，包括以下因素：

  • 数字产品的规模——页面或视图更多的产品通常需要 更大的评估样本集。
  • 数字产品的年限——较旧的数字产品往往包含更多（通常不易 找到的）内容，其复杂性、一致性以及设计和开发 过程的水平各不相同，因此通常需要更大的样本集进行评估。
  • 数字产品的复杂性——复杂性越高，所需评估样本集越大； 请考虑以下因素：
    • 内容的交互程度——包含丰富交互内容的产品 需要更大的样本集，以覆盖样本提供的功能以及 单个样本可能具有的不同状态。
    • 内容的生成方式——内容由不同来源聚合 或在提供时（运行时）进行处理的产品，通常需要 更大的样本集，以覆盖可能生成的内容组合。
    • 内容的实现方式——提供不同 版本、根据用户及其首选项提供内容，或适应访问设备的产品 需要更大的样本集，以覆盖这些不同情况。
  • 产品的一致性——一致性越低，所需评估样本集越大； 请考虑以下因素：
    • 样本类型的多样性——样本类型更为多样的产品 （参见步骤 2.3：识别样本类型）需要更大的评估样本 集。
    • 功能的多样性——功能更加多样的数字产品 （参见步骤 2.2：识别数字产品的基本功能）， 尤其是包含不同类型应用程序的产品，需要更大的 评估样本集。
    • 技术的多样性——使用更多种类 技术的数字产品（参见步骤 2.4：识别所依赖的技术） 需要更大的评估样本集。
    • 编码风格的多样性——具有更多不同编码风格的产品 （通常来自不同的代码生成脚本、模板和 Web 页面 作者）需要更大的评估样本集。
  • 对开发过程的遵循程度——遵循程度越低，所需评估样本集越大； 请考虑以下因素：
    • 过程的形式化程度——具有形式化开发和 质量保证过程的产品，其样本的编码和质量往往更一致， 因而通常需要较小的评估样本集。
    • 开发人员培训——设计人员、开发人员和 内容作者定期接受培训的产品，往往具有更一致的无障碍 表现，因此通常需要较小的评估样本集。
    • 所使用的开发工具——使用一套一致工具（例如内容管理系统 （CMS））进行开发和维护的产品也往往 更加一致，并需要较小的评估样本集。
    • 作者数量——由较为固定的一组作者（包括内容编辑人员） 开发和维护的产品往往更加一致， 并需要较小的评估样本集。
  • 所需的可信度——对评估结果要求更高的可信度，通常 需要评估更大的样本集。
  • 先前评估结果的可用性——当评估人员可以访问先前评估结果， 包括人工和自动化无障碍测试结果时，可能只需较小的样本集。

此步骤中的选择最初依赖于步骤 2：探索目标数字产品中进行的探索。随着 评估人员进一步了解目标产品的具体实现方面，该选择还会在后续步骤 4：评估选定的样本集中不断 完善。

步骤 3.1：纳入结构化样本集

方法要求 3.1：选择 能够反映所有已识别的（1）常见视图、（2）基本功能、（3）样本类型、（4） 所依赖技术以及（5）其他相关样本的样本。

选择包含以下内容的样本集：

  1. 在步骤 2.1：识别数字产品的常见视图中识别的常见视图，
  2. 在步骤 2.5：识别其他相关样本中识别的相关样本， 以及
  3. 如果前述步骤中尚未体现，则加入具有以下特征的其他样本：
    1. 在步骤 2.2：识别数字产品的基本 功能中识别的基本功能，
    2. 在步骤 2.3：识别样本 类型中识别的不同样本类型，以及
    3. 使用步骤 2.4：识别 所依赖的技术中识别的技术的内容。
注

单个样本可以反映上述每项标准中的多个方面。例如， 单个样本可以同时代表特定设计布局、功能和 所使用的技术。此步骤的目的是体现数字产品中出现的不同类型 样本、功能和技术。谨慎选择 这些代表性实例，可以在保持整个数字产品适当代表性的同时， 显著缩小所需样本集规模。所需样本 实例的数量取决于上一节中说明的数字产品具体方面，即影响样本集规模的因素。

步骤 3.2：纳入随机选择的样本集

方法要求 3.2：选择一个 随机样本集，并将其纳入评估。

随机选择的样本集可作为指标，用于验证通过前述步骤选择的 结构化样本集是否足以代表网站提供的内容。 当两种选择方法的评估结果相互关联时，这是提高整体评估结果 可信度的重要步骤。

随机选择的样本数量应为通过前述步骤选择的 结构化样本集的 10%。例如，如果为数字产品选择的 结构化样本集包含 80 个样本，则随机样本集规模为 8 个样本（这些样本 会额外加入，因此总计为 88 个样本）。

执行此选择时，应从目标数字产品中随机选择尚未包含在 前述步骤所选结构化样本集中的唯一 样本。根据产品类型以及评估人员的访问权限， 可能需要使用不同技术进行选择。评估人员可以：

  • 使用遍历数字产品并给出随机选择 样本列表的工具，
  • 使用脚本生成数字产品上全部可用样本的列表，以供 选择，
  • 手动列出数字产品中的所有页面、视图或屏幕，并从该列表中 随机选择项目，以及
  • 使用服务器日志、爬虫、搜索引擎和其他创造性方法获取随机样本 集。

记录随机选择的样本，因为需要在步骤 4.3：比较结构化和随机样本集中将其与剩余的 结构化样本集进行比较。

注

尽管随机样本集无需依据严格的科学 标准进行选择，但选择范围需要覆盖数字产品的整个范围（数字 产品上的任何样本都可能被选中），并且单个样本的选择 不应遵循可预测的模式。记录生成随机样本集所用的方法 有助于确保结果的可靠性和可重复性。

注

如果随机样本集方法选中的视图与 样本集中已有视图完全相同，则应选择另一个视图。如果无法 找到新视图，则应视为此步骤已完成。

步骤 3.3：纳入完整流程

方法要求 3.3 将属于完整流程的所有 样本纳入 选定的样本集。

选定的样本集必须包括属于呈现完整流程的系列中的所有页面或视图。 当样本属于某个流程时，属于同一 流程的所有页面或视图均必须纳入。

使用以下步骤纳入必要样本：

  1. 对于通过步骤 3.1：纳入结构化样本 集和步骤 3.2：纳入随机选择的样本集选出的、属于某个流程的每个样本集， 找到该流程的起点（样本），并将其纳入 选定的样本。
  2. 对于每个流程起点，至少识别并记录完成该流程的默认 样本序列。纳入这些样本。
    注

    默认序列遵循标准使用场景，描述通过 完整流程的默认路径。它假定没有用户输入错误，也没有 选择其他选项。例如，对于网上商店应用程序，用户将 进入结账流程，确认默认付款选项，正确提供所有必需的付款 详细信息并完成购买，而不会更改 购物车内容、使用已存储用户配置文件、选择其他付款或 配送地址选项、提供错误输入等。

  3. 对于每个流程，识别并记录经常访问且对成功完成流程至关重要的 样本分支序列。纳入这些样本。
    注

    分支序列可以在重新进入流程默认分支的位置终止。 例如，添加新配送地址将被记录为一个关键 替代分支，该分支随后返回流程的默认分支。

注

在大多数情况下，需要记录并说明在序列中从 一个样本进入下一个样本以完成流程所需的操作，从而便于以后复现。 此类操作的示例可以是“填写姓名和地址，并选择‘提交’按钮”。 在大多数情况下，仅凭 Web 地址（URL）不足以识别完整 流程中的样本。清楚记录样本何时属于某个流程也很有帮助， 这样评估人员可以将精力集中在相关变化上，例如新增、 修改或变为可见的元素。

步骤 4：评估选定的样本集

方法要求 4：根据方法要求 4.1、方法要求 4.2和方法要求 4.3评估 选定的样本集。

在此步骤中，评估人员详细评估步骤 3：选择具有代表性的样本集中选择的所有样本，并将结构化样本集与随机 选择的样本集进行比较。评估依据五项 WCAG 2 符合性要求，并按照步骤 1.2：定义符合性目标中定义的目标 符合级别进行。

WCAG 2.2 的五项符合性要求是：

  1. 符合级别
  2. 完整页面
  3. 完整流程
  4. 仅使用具备无障碍支持的 技术使用方式
  5. 非干扰

以下各节进一步介绍了如何依据这些符合性要求进行评估。 WCAG 2 指导层次和理解 符合性提供了有关 WCAG 2 符合性要求的更多背景和指导， 这些内容超出了本文档的范围。

注

执行此步骤需要深入理解 WCAG 2 符合性要求 以及所需专业知识一节中描述的专业知识。

步骤 4.1：检查所有初始样本

方法要求 4.1：检查 每个不处于完整流程中或完整流程末尾的样本，是否在目标符合级别上符合五项 WCAG 2 符合性要求。

对于在步骤 3：选择具有代表性的样本集中选择的、并非 位于完整流程中或完整流程末尾的每个样本，应依据步骤 1.2： 定义符合性目标中定义的目标符合级别，检查其是否符合五项 WCAG 符合性要求。这包括样本的所有组件，但不激活 任何功能、不输入任何数据，也不以其他方式启动流程。此类功能和 交互，包括位于完整流程中或完整流程末尾的样本，将在 后续步骤中进行评估。

注

许多样本会包含页眉、导航栏、搜索表单等 重复出现的组件。尽管要求是检查完整页面，但通常无需 在每次出现时重新评估这些组件，除非它们的外观或行为有所不同，或者 在步骤 1.4：定义其他 评估要求（可选）中定义了其他评估要求。

WCAG 2 成功标准

通常可以通过多种方式确定是否满足 WCAG 2 成功标准。 W3C/WAI 提供了一组 （非规范性）WCAG 2.2 技术， 其中记录了满足特定 WCAG 2 成功标准的方法。它还包括已记录的 常见失败方式，即已知的内容未满足特定 WCAG 2 成功标准的方式。理解 WCAG 成功标准的技术进一步介绍了 WCAG 2 中 技术的概念。

评估人员可以使用此类已记录的指导来检查特定 Web 内容是否满足或 未满足 WCAG 2 成功标准。已记录的技术和失败方式也可以作为 评估报告中的有用背景信息。但是，并不要求使用 W3C/WAI 记录的特定技术和失败方式集合。实际上， 评估人员完全无需遵循任何技术和失败方式。评估人员可以使用 其他方法评估是否满足 WCAG 2 成功标准。例如， 评估人员可以使用满足充分技术 要求的特定测试说明和协议，这些说明和协议可以公开记录，也可以仅供 评估人员使用。有关技术使用的更多指导，请参阅前文链接的理解 WCAG 成功标准的技术。

注

每项 WCAG 2 成功标准均表述为“应用于特定 Web 内容时 结果为真或假的可测试陈述”。当呈现给用户的内容中 不存在与特定成功标准相关的内容时（例如 Web 页面中没有视频）， 则根据 WCAG 2，该成功标准视为“已满足”。评估报告可以选择明确指出 不存在相关内容的成功标准，例如标记为“未出现”。理解 符合性提供了更多背景和指导。

符合要求的替代版本

样本中的内容可能具有替代版本。例如，视频内容可以提供 带字幕和不带字幕的版本。在某些情况下，可以提供整个样本集 （或一系列样本）作为初始样本的替代版本。借助符合 WCAG 2 符合要求的 替代版本定义中所列要求的替代版本，可以实现 WCAG 2 符合性。例如， 包含无字幕视频内容的 Web 页面仍可通过提供 符合符合要求的替代版本条件的视频替代版本来满足 WCAG 2。理解 符合要求的替代版本进一步介绍了符合要求的替代版本， 这些内容超出了本文档的范围。

注

替代版本不被视为单独的样本，而是内容的 一部分。样本及其替代版本作为一个整体（完整页面）进行评估。

无障碍支持

样本中的内容需要以具备无障碍支持的方式提供 （直接提供或通过替代版本提供）。例如，视频字幕需要以 用户能够显示的方式提供。WCAG 2 对无障碍支持的定义 规定了使用Web 内容技术时 符合无障碍支持条件的具体要求。理解 具备无障碍支持的 Web 技术使用方式进一步介绍了无障碍 支持，这些内容超出了本文档的范围。但是，WCAG 2 并未规定数字产品在无障碍方面必须 支持的特定阈值或软件集合。 此类基线的定义取决于多个参数，包括数字产品的用途、目标 受众和语言。用于评估特定 数字产品的基线在步骤 1.3：定义无障碍支持 基线中定义。

非干扰

样本中的部分内容可能不符合 WCAG 2，但样本整体仍可能 符合 WCAG 2。例如，信息和功能可能通过尚未 被辅助技术广泛支持的Web 内容技术提供，或以辅助技术不支持的方式提供， 同时还提供一个具备无障碍支持的、符合要求的信息和 功能替代版本。在这种情况下，不符合要求的内容不得 对符合要求的内容产生负面干扰，从而使样本能够符合 WCAG 2。WCAG 2 关于非干扰的符合性要求规定了 内容符合非干扰条件的具体要求。理解 要求 5进一步介绍了非干扰，这些内容超出了 本文档的范围。

步骤 4.2：检查所有完整流程

方法要求 4.2：检查 属于完整流程的每个样本中的所有交互，是否在目标符合级别上符合五项 WCAG 2 符合性要求。

对于在步骤 3.3：纳入完整流程中识别的每个完整流程， 应遵循已识别的默认样本序列和分支样本序列，并按照步骤 4.1：检查所有初始样本对每个样本进行评估。但是，在这种情况下， 无需评估所有内容，只需评估流程中发生变化的内容。

功能、数据输入、通知和其他交互均属于此检查的一部分。具体而言， 它包括：

  • 与表单、输入元素、对话框和其他组件的交互，
  • 输入确认、错误消息以及其他用户交互反馈，以及
  • 使用不同设置、首选项、设备和交互参数时的行为。

步骤 4.3：比较结构化和随机样本集

方法要求 4.3：检查 随机选择样本集中的每个样本是否未显示结构化样本集中 未体现的内容类型和结果。

尽管结构化样本集和随机选择样本集之间 WCAG 2 成功标准的具体出现情况会有所不同，但随机选择的样本集不应显示结构化样本集中不存在的新 内容类型。此外，随机 选择样本集的评估结果不应显示结构化样本集中没有的新发现。如果 随机选择的样本集显示了新的内容类型或新的评估结果，则表明 结构化样本集不足以代表网站提供的内容。 在这种情况下，评估人员需要返回步骤 3：选择 具有代表性的样本集，以选择能够反映新识别内容类型和结果的其他样本。 还可能需要相应调整步骤 2：探索目标 数字产品的结果。重复此步骤，直到 结构化样本集能够充分代表数字产品提供的内容。

步骤 5：报告评估结果

方法要求 5：根据方法要求 5.1报告 评估结果，并可选择根据方法要求 5.2、方法要求 5.3、方法要求 5.4和方法要求 5.5进行报告。

尽管评估结果在过程结束时报告，但为确保结果可验证， 相关记录应贯穿整个评估过程。文档通常具有不同 的保密级别。例如，用于评估各项 要求的具体方法记录可能仅限评估人员查看，而有关这些检查结果的报告 通常会提供给评估委托方。产品所有者还可以选择 根据本方法公开发布有关评估结果的声明。

步骤 5.3：提供评估声明（可选）

方法要求 5.3：提供 描述符合性评估结果的声明（可选）。

  1. 不符合 WCAG 2 的数字产品区域；
  2. 不符合 WCAG 2 的原因：“第三方内容”或“缺乏 对相应语言的无障碍支持”。

步骤 5.4：提供汇总分数（可选）

方法要求 5.4：提供 汇总分数（可选）。

尽管汇总分数可以提供数值指标以帮助传达随时间变化的进展， 但目前尚不存在一种已知能够满足所需可靠性、准确性和 实用性的单一度量指标。事实上，汇总分数可能产生误导，并且无法提供足够的情境和 信息来理解数字产品的实际无障碍性。由于这一原因及其他原因， WCAG 2 没有提供评分方案。W3C Web 无障碍 度量研究报告进一步介绍了正在开展的研究、不同方法以及 评分指标的局限性，这些内容超出了本文档的范围。每当提供分数时， 都必须记录评分方法，并将其与报告一同提供给评估委托方，以 提高透明度和可重复性。

步骤 5.5：提供机器可读报告（可选）

方法要求 5.5：提供 评估结果的机器可读报告（可选）。

机器可读报告有助于创作工具、无障碍 评估工具和质量保证工具处理评估结果。评估与报告语言 （EARL）是一种专门为此目的设计的机器可读格式。建议 使用 EARL 提供机器可读报告。另请参阅 WCAG 2 中的理解 元数据，以进一步了解元数据的用途，包括 EARL 等机器可读 报告。

这包括主页、登录页面和其他入口点，以及在适用情况下的联系信息、 帮助、法律信息和类似视图，这些视图通常从所有其他视图链接 （通常从页眉、页脚或导航菜单链接）。

注

下文提供了视图的定义。

数字产品
由一个或多个相关视图组成的连贯集合，这些视图共同提供通用用途或功能
示例 4
网站、Web 应用程序、电子书、自助服务终端应用程序、移动应用程序和文档（PDF、Word、EPUB）
注

本方法重点关注完整、自包含的数字产品。数字 产品可以由较小的视图子集组成，每个子集均可被视为 独立产品。例如，一个数字产品可以包括网上商店、组织内各 部门的区域、博客区域以及其他区域，其中每个区域均可被视为 一个数字产品。

基本 功能
如果移除，将从根本上改变用户使用产品的方式或产品用途的功能
注

这包括产品用户为执行此功能而查阅的信息和完成的任务。

示例 5
基本功能的示例包括“从网上商店选择和购买商品”、 “填写并提交应用程序中提供的表单”以及“在 自助服务终端上注册账户”。
注

其他功能并未被排除在评估范围之外。“基本 功能”一词旨在帮助识别关键样本，并将其与其他样本一同纳入 评估。

评估人员
负责执行评估的个人、人员团队、组织、内部部门或其他实体
评估 委托方
委托进行评估的个人、人员团队、组织、内部部门或其他实体
注

在许多情况下，评估委托方可能是产品所有者或产品开发人员； 在其他情况下，也可能是采购方或无障碍监测调查 所有者等其他实体。

样本
被纳入样本集的视图
样本集
为评估而选择的样本列表
视图

Web 页面、文档、软件或视图，或者所评估的无障碍标准中定义的等效 符合性单元。
