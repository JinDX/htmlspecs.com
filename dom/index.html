1. 基础设施

本规范依赖于现行标准的基础设施标准。[INFRA]

本规范中使用的一些术语定义于 编码、 选择器、受信任类型、Web IDL、XML、 XML 中的命名空间 和 将样式表与 XML 文档关联。 [ENCODING] [SELECTORS4] [TRUSTED-TYPES] [WEBIDL] [XML] [XML-NAMES] [XML-STYLESHEET]

当需要扩展时，可以相应地更新 DOM 标准，或者可以编写一个新标准，该标准可以利用为 适用的规范 提供的可扩展性钩子。

1.1. 树

树 是一个有限的层次树结构。树的顺序是对树的先序、深度优先遍历。

一个 参与 树的对象具有一个父节点，其值可以是 null 或一个对象，并且具有 子节点，它们是由对象组成的 有序 集合。如果对象 A 的父节点是对象 B，则 A 是 B 的一个子节点。

如果一个对象的 父节点为 null，则该对象的根节点是其自身，否则 它的根节点就是 其 父节点的根节点。树的根节点是任何 参与该树且其父节点为 null 的对象。

如果对象A是对象B的子，或者对象A是对象C的子，而C是B的后代，则对象A被称为对象B的后代。

包含后代是指一个对象或其后代之一。

当且仅当B是A的后代时，称对象A为对象B的祖先。

包含祖先是指一个对象或其祖先之一。

当且仅当B和A共享相同的非空父节点时，称对象A为对象B的同胞。

包含同胞是指一个对象或其同胞之一。

如果A和B在同一个树中，并且A在树的顺序中位于B之前，则称对象A先于对象B。

如果A和B在同一个树中，并且A在树的顺序中位于B之后，则称对象A继于对象B。

一个对象的第一个子节点是其第一个子节点，如果它没有子节点，则为 null。

一个对象的最后一个子节点是其最后一个子节点，如果它没有子节点，则为 null。

一个对象的前一个兄弟节点是 其第一个位于其之前的 兄弟节点；如果没有 位于其之前的 兄弟节点，则为 null。

一个对象的后一个兄弟节点是其 第一个位于其之后的 兄弟节点；如果没有位于其之后的 兄弟节点，则为 null。

一个对象的索引是其先于的同胞的数量，如果没有，则为 0。

1.2. 有序集合

有序集合解析器接受一个字符串input，然后执行以下步骤：

  1. 令inputTokens为在 ASCII 空白字符处分割input的结果。

  2. 令tokens为一个新的有序集合。

  3. 对于 inputTokens 中的每个 token: 将 token 追加到 tokens。

  4. 返回tokens。

有序集合序列化器接受一个set，并返回使用U+0020 SPACE连接的set的串联结果。

1.3. 选择器

给定字符串 selectors 和 节点 node，作用域匹配选择器字符串 的步骤如下：

  1. 令 selector 为 解析选择器 selectors 的结果。 [SELECTORS4]

  2. 如果 selector 返回失败，则 抛出一个 "SyntaxError"DOMException。

  3. 返回 selector 与 node 的 根节点 通过 作用域根 node 进行 在树中匹配选择器 的结果。[SELECTORS4]。

不打算支持在选择器中使用命名空间，也不会添加此功能。

1.4. 名称验证

一个字符串是 一个有效的命名空间 前缀，如果其长度至少为 1，且 不包含ASCII 空白字符、U+0000 NULL、U+002F (/) 或 U+003E (>)。

一个字符串是 一个有效的 属性局部名称，如果其长度至少 为 1 且不包含ASCII 空白字符、U+0000 NULL、U+002F (/)、U+003D (=) 或 U+003E (>)。

一个字符串 name 是一个有效的元素局部名称，如果以下步骤返回 true：

  1. 如果 name 的长度为 0，则返回 false。

  2. 如果 name 的第 0 个码点是一个ASCII 字母：

    1. 如果 name 包含ASCII 空白字符、U+0000 NULL、U+002F (/) 或 U+003E (>)，则 返回 false。

    2. 返回 true。

  3. 如果 name 的第 0 个码点不是 U+003A (:)、U+005F (_) 或处于 U+0080 至 U+10FFFF（含端点）的范围内，则返回 false。

  4. 如果 name 后续的码点， 如果存在，不是ASCII 字母、ASCII 数字、 U+002D (-)、U+002E (.)、U+003A (:)、U+005F (_) 或 U+0080 至 U+10FFFF（含端点）范围内的码点， 则 返回 false。

  5. 返回 true。

此概念用于验证通过 DOM API 构造的元素的局部名称。其目的是允许使用 HTML 解析器能够构造的任何名称（第一个码点是一个ASCII 字母的分支），以及一些其他 可能的名称。对于这些额外的名称，由于历史 原因，ASCII 范围受到限制，但 ASCII 范围之外允许使用任何字符。

以下与 JavaScript 兼容的正则表达式实现了 有效的 元素局部名称： 

/^(?:[A-Za-z][^\0\t\n\f\r\u0020/>]*|[:_\u0080-\u{10FFFF}][A-Za-z0-9-.:_\u0080-\u{10FFFF}]*)$/u

一个字符串是一个 有效的文档类型名称 如果它不包含ASCII 空白字符、 U+0000 NULL 或 U+003E (>)。

空字符串是一个有效的文档类型名称。

给定一个 context，要验证并 提取 namespace 和 qualifiedName，执行 以下步骤：

  1. 如果 namespace 为空字符串，则将其设为 null。

  2. 令 prefix 为 null。

  3. 令 localName 为 qualifiedName。

  4. 如果 qualifiedName 包含 U+003A (:)：

    1. 将 prefix 设为 qualifiedName 中第一个 U+003A (:) 之前的部分。

    2. 将 localName 设为 qualifiedName 中第一个 U+003A (:) 之后的部分。

    3. 如果 prefix 不是一个有效的命名空间前缀，则抛出一个 "InvalidCharacterError" DOMException。

  5. 断言：prefix 要么为 null，要么是一个有效的命名空间前缀。

  6. 如果 context 为 "attribute"，且 localName 不是一个 有效的属性局部名称，则抛出一个 "InvalidCharacterError" DOMException。

  7. 如果 context 为 "element"，且 localName 不是一个 有效的元素局部名称，则抛出一个 "InvalidCharacterError" DOMException。

  8. 如果 prefix 不为 null 且 namespace 为 null，则抛出一个 "NamespaceError" DOMException。

  9. 如果 prefix 为 "xml"，且 namespace 不是 XML 命名空间，则抛出一个 "NamespaceError" DOMException。

  10. 如果 qualifiedName 或 prefix 为 "xmlns"，且 namespace 不是XMLNS 命名空间，则抛出一个 "NamespaceError" DOMException。

  11. 如果 namespace 是XMLNS 命名空间，而 qualifiedName 和 prefix 都不是 "xmlns"，则抛出一个 "NamespaceError" DOMException。

  12. 返回 (namespace, prefix, localName)。

过去，本规范中的多个 API 会对命名空间前缀、属性局部名称、 元素局部名称和文档类型名称执行更严格的验证。这些验证采用了与 多项 XML 相关规范一致的方式。（尽管并未执行这些规范中的 所有规则。）

事实证明，这给 Web 开发者带来了不便，尤其是因为某些 名称可以由 HTML 解析器创建，却无法通过 DOM API 创建。因此，验证规则已 放宽为仅包含上述规则。

2. 事件

2.1. “DOM 事件”简介

在整个 Web 平台中，事件会被分派给对象，以表示某个 事件的发生，例如网络活动或用户交互。这些对象实现了 EventTarget 接口，因此可以添加事件监听器，以观察 事件，方法是调用 addEventListener()： 

obj.addEventListener("load", imgFetched)

function imgFetched(ev) {
  // 非常成功
  …
}

事件 监听器可以通过 使用 removeEventListener() 方法并传入相同的参数来移除。

或者，事件监听器也可以通过将一个 AbortSignal 传递给 addEventListener() 并调用 abort() 方法（在 拥有该信号的控制器上）来移除。

事件本身也是对象，并且 实现了 Event 接口（或其 派生接口）。在上述示例中， ev 就是该事件。 ev 会 作为参数传递给 事件 监听器的回调 （通常是如上所示的 JavaScript 函数）。 事件 监听器依据 事件的 type 属性值 （上述示例中的 "load"）进行匹配。该 事件的 target 属性值返回 接收该事件的 分派目标对象 （即上面的 obj）。

尽管事件通常由用户代理 分派 以响应用户交互或某项任务的完成，但应用程序也可以自行分派 事件，即 通常所谓的合成事件： 

// 添加适当的事件监听器
obj.addEventListener("cat", function(e) { process(e.detail) })

// 创建并分派事件
var event = new CustomEvent("cat", {"detail":{"hazcheeseburger":true}})
obj.dispatchEvent(event)

除了发出信号外，事件 有时 还用于让应用程序控制某项操作接下来如何进行。例如，在表单提交过程中， 一个 事件的 type 属性值为 "submit"，该事件会被 分派。 如果调用这个 事件的 preventDefault() 方法， 表单提交就会终止。希望 借助事件 分派 （即应用程序自行分派的合成事件） 来使用此功能的应用程序，可以利用 dispatchEvent() 方法的返回值： 

if(obj.dispatchEvent(event)) {
  // 事件未被取消，是时候施展一些魔法了
  …
}

当一个事件被分派 给某个参与一棵树的对象时 （例如一个元素），它还可以 触达事件 监听器，即位于该对象的 祖先上的监听器。 具体而言，该对象的所有包含自身的祖先上的 事件 监听器，只要其capture 为 true，就会按照 树顺序被调用。接着， 如果事件的 bubbles 为 true，则该对象的所有 包含自身的祖先上的事件监听器，只要其capture 为 false， 就会按照相反的树顺序被调用。

下面通过一个示例来看看事件如何在树中工作： 

<!doctype html>
<html>
 <head>
  <title>乏味的示例</title>
 </head>
 <body>
  <p>你好，<span id=x>世界</span>!</p>
  <script>
   function test(e) {
     debug(e.target, e.currentTarget, e.eventPhase)
   }
   document.addEventListener("hey", test, {capture: true})
   document.body.addEventListener("hey", test)
   var ev = new Event("hey", {bubbles:true})
   document.getElementById("x").dispatchEvent(ev)
  </script>
 </body>
</html>

debug 函数将被调用两次。每次事件的 target 属性值都是 span 元素。第一次调用时， currentTarget 属性值是文档，第二次调用时则是 body 元素。 eventPhase 属性值从 CAPTURING_PHASE 变为 BUBBLING_PHASE。 如果为 span 元素注册了一个事件 监听器，那么 eventPhase 属性值将会 是 AT_TARGET。

2.2. 接口 Event

[Exposed=*]
interface Event {
  constructor(DOMString type, optional EventInit eventInitDict = {});

  readonly attribute DOMString type;
  readonly attribute EventTarget? target;
  readonly attribute EventTarget? srcElement; // 遗留
  readonly attribute EventTarget? currentTarget;
  sequence<EventTarget> composedPath();

  const unsigned short NONE = 0;
  const unsigned short CAPTURING_PHASE = 1;
  const unsigned short AT_TARGET = 2;
  const unsigned short BUBBLING_PHASE = 3;
  readonly attribute unsigned short eventPhase;

  undefined stopPropagation();
           attribute boolean cancelBubble; // .stopPropagation() 的遗留别名
  undefined stopImmediatePropagation();

  readonly attribute boolean bubbles;
  readonly attribute boolean cancelable;
           attribute boolean returnValue;  // 遗留
  undefined preventDefault();
  readonly attribute boolean defaultPrevented;
  readonly attribute boolean composed;

  [LegacyUnforgeable] readonly attribute boolean isTrusted;
  readonly attribute DOMHighResTimeStamp timeStamp;

  undefined initEvent(DOMString type, optional boolean bubbles = false, optional boolean cancelable = false); // 遗留
};

dictionary EventInit {
  boolean bubbles = false;
  boolean cancelable = false;
  boolean composed = false;
};

一个 Event 对象 简称为事件。它 用于 表示某件事情已经发生，例如图像已下载完成。

一个潜在事件 目标是 null 或一个 EventTarget 对象。

一个事件具有关联的 目标 （一个 潜在事件 目标）。除非另有说明，否则其值为 null。

一个事件具有关联的 relatedTarget（一个 潜在事件 目标）。除非另有说明，否则其值为 null。

其他规范使用 relatedTarget 来定义 relatedTarget 属性。[UIEVENTS]

一个事件具有关联的 触摸目标列表（一个包含零个或 多个潜在 事件目标的列表）。除非另有说明，否则它是 空列表。

触摸目标列表仅用于定义 TouchEvent 接口及相关接口。[TOUCH-EVENTS]

一个事件具有关联的 路径。一个 路径是一个由事件路径项组成的 列表。一个事件路径项是一个结构体， 由一个调用目标 （一个 EventTarget 对象）、一个 调用目标位于影子树中 （布尔值）、一个 经影子树调整的目标（一个 潜在事件 目标）、一个 relatedTarget（一个 潜在事件 目标）、一个 触摸目标列表（一个由 潜在事件 目标组成的列表）、一个 闭合树的根节点（布尔值）， 以及一个闭合树中的插槽（一个 布尔值）组成。一个路径最初是 空列表。

event = new Event(type [, eventInitDict])
返回一个新的 event，其 type 属性值被设置为 type。eventInitDict 参数 允许通过同名的对象成员来设置 bubbles 和 cancelable 属性。
event . type
返回 event 的类型，例如 "click"、"hashchange" 或 "submit"。
event . target
返回 event 被分派到的对象（即其 目标）。
event . currentTarget
返回其事件监听器的回调当前 正在被 调用的对象。
event . composedPath()
返回 event 的调用目标对象，这些对象位于其 路径中（监听器将在这些对象上 被调用），但不包括任何 节点，如果它们位于影子树中， 且其影子 根节点的 模式为 "closed"，并且无法从 event 的 currentTarget访问。
event . eventPhase
返回事件的 阶段，该阶段为以下值之一：NONE、 CAPTURING_PHASE、 AT_TARGET 和 BUBBLING_PHASE。
event . stopPropagation()
当事件在树中被分派时，调用此方法可阻止 event 到达当前对象以外的任何对象。
event . stopImmediatePropagation()
调用此方法可阻止 event 在当前监听器运行结束后 到达任何其他已注册的事件监听器，并且当事件 在树中被分派时，还会阻止 event 到达任何 其他对象。
event . bubbles
根据 event 的初始化方式返回 true 或 false。如果 event 按照相反的树顺序经过其目标的 祖先， 则返回 true；否则返回 false。
event . cancelable
根据 event 的初始化方式返回 true 或 false。其返回 值并不总是具有实际意义，但 true 可以表示 event 被分派期间所执行的操作的一部分可以通过调用 preventDefault() 方法来取消。
event . preventDefault()
如果在 cancelable 属性值为 true，且正在执行 event 的 passive 设置为 false 的监听器时调用此方法，则向 导致 event 被分派的操作发出信号，表示该操作需要被取消。
event . defaultPrevented
如果成功调用了 preventDefault() 以表示取消，则返回 true； 否则返回 false。
event . composed
根据 event 的初始化方式返回 true 或 false。如果 event 会调用位于 ShadowRoot 节点之外的监听器，且该节点是其 目标的根节点，则返回 true；否则返回 false。
event . isTrusted
如果 event 是由用户代理 分派的，则返回 true， 否则返回 false。
event . timeStamp
返回 event 的时间戳，以相对于 事件发生时刻测量的毫秒数表示。

type 属性必须返回其 初始化时的值。创建事件 时，必须将该属性初始化为空 字符串。

target 获取器步骤是返回this 的 目标。

srcElement 获取器步骤是返回 this 的目标。

currentTarget 属性必须返回其 初始化时的值。创建事件时，必须将该属性初始化为 null。

composedPath() 方法的步骤如下：

  1. 令 composedPath 为一个空列表。

  2. 令 path 为this 的路径。

  3. 如果 path 为空，则返回 composedPath。

  4. 令 currentTarget 为this 的 currentTarget 属性值。

  5. 断言：currentTarget 是一个 EventTarget 对象。

  6. 将 currentTarget 追加到 composedPath。

  7. 令 currentTargetIndex 为 0。

  8. 令 currentTargetHiddenSubtreeLevel 为 0。

  9. 令 index 为 path 的大小减去 1。

  10. 当 index 大于或等于 0 时：

    1. 如果 path[index] 的闭合树的根节点为 true，则将 currentTargetHiddenSubtreeLevel 增加 1。

    2. 如果 path[index] 的调用目标为 currentTarget，则将 currentTargetIndex 设为 index，并 跳出循环。

    3. 如果 path[index] 的闭合树中的插槽为 true，则将 currentTargetHiddenSubtreeLevel 减少 1。

    4. 将 index 减少 1。

  11. 令 currentHiddenLevel 和 maxHiddenLevel 均为 currentTargetHiddenSubtreeLevel。

  12. 将 index 设为 currentTargetIndex − 1。

  13. 当 index 大于或等于 0 时：

    1. 如果 path[index] 的闭合树的根节点为 true，则将 currentHiddenLevel 增加 1。

    2. 如果 currentHiddenLevel 小于或等于 maxHiddenLevel，则 将 path[index] 的 调用目标 前置到 composedPath。

    3. 如果 path[index] 的闭合树中的插槽为 true：

      1. 将 currentHiddenLevel 减少 1。

      2. 如果 currentHiddenLevel 小于 maxHiddenLevel，则将 maxHiddenLevel 设为 currentHiddenLevel。

    4. 将 index 减少 1。

  14. 将 currentHiddenLevel 和 maxHiddenLevel 均设为 currentTargetHiddenSubtreeLevel。

  15. 将 index 设为 currentTargetIndex + 1。

  16. 当 index 小于 path 的大小时：

    1. 如果 path[index] 的闭合树中的插槽为 true，则将 currentHiddenLevel 增加 1。

    2. 如果 currentHiddenLevel 小于或等于 maxHiddenLevel，则 将 path[index] 的调用目标 追加到 composedPath。

    3. 如果 path[index] 的闭合树的根节点为 true：

      1. 将 currentHiddenLevel 减少 1。

      2. 如果 currentHiddenLevel 小于 maxHiddenLevel，则将 maxHiddenLevel 设为 currentHiddenLevel。

    4. 将 index 增加 1。

  17. 返回 composedPath。

eventPhase 属性必须返回其 初始化时的值，该值必须是以下值之一：

NONE（数值 0）
当前未被分派的事件处于此阶段。
CAPTURING_PHASE（数值 1）
当一个事件被分派给一个参与 树的对象时，在该事件到达 其目标之前，将处于此 阶段。
AT_TARGET（数值 2）
当一个事件被分派时，在其 目标上将处于此阶段。
BUBBLING_PHASE（数值 3）
当一个事件被分派给一个参与 树的对象时，在该事件到达 其目标之后，将处于此阶段。

最初，必须将该属性初始化为 NONE。

每个事件都具有关联的 以下标志，这些标志最初均未设置：

  • 停止传播标志
  • 立即停止传播标志
  • 已取消标志
  • 处于被动监听器中标志
  • 组合标志
  • 已初始化标志
  • 分派标志

stopPropagation() 方法的步骤是设置 this 的停止传播 标志。

cancelBubble 获取器步骤是：如果 this 的停止传播 标志已设置，则返回 true；否则返回 false。

cancelBubble 设置器步骤是：如果给定值为 true，则设置this 的停止传播标志； 否则不执行任何操作。

stopImmediatePropagation() 方法的步骤 是设置 this 的停止传播 标志以及this 的 立即停止传播标志。

bubbles 和 cancelable 属性必须返回其 初始化时的值。

给定一个事件 event，要设置已取消 标志，如果 event 的 cancelable 属性值为 true，且 event 的 处于被动 监听器中标志未设置，则设置 event 的已取消标志； 否则不执行任何操作。

returnValue 获取器步骤是：如果 this 的已取消标志已设置， 则返回 false；否则返回 true。

returnValue 设置器步骤是：如果给定值为 false，则使用this 设置已取消标志； 否则不执行任何操作。

preventDefault() 方法的步骤是 使用this 设置已取消 标志。

在某些情况下，调用 preventDefault() 不会产生 任何效果。鼓励用户代理在开发者控制台中记录确切原因，以帮助 调试。

defaultPrevented 获取器步骤是：如果 this 的已取消标志已设置， 则返回 true；否则返回 false。

composed 获取器步骤是：如果 this 的组合标志已设置， 则返回 true；否则返回 false。

isTrusted 属性必须返回其 初始化时的值。创建事件 时，必须将该属性初始化为 false。

isTrusted 是一个用于指示 事件是否由用户代理分派 （而不是通过调用 dispatchEvent()）的便捷属性。 唯一的遗留例外是 click()， 它会使 用户代理分派一个事件，其 isTrusted 属性被初始化为 false。

timeStamp 属性必须返回其 初始化时的值。

要使用 type、bubbles 和 cancelable 初始化一个 event，请 运行以下步骤：

  1. 设置 event 的已初始化标志。

  2. 取消设置 event 的停止传播标志、 立即停止传播标志和已取消标志。

  3. 将 event 的 isTrusted 属性设为 false。

  4. 将 event 的目标设为 null。

  5. 将 event 的 type 属性设为 type。

  6. 将 event 的 bubbles 属性设为 bubbles。

  7. 将 event 的 cancelable 属性设为 cancelable。

initEvent(type, bubbles, cancelable) 方法的步骤如下：

  1. 如果this 的分派标志已设置，则返回。

  2. 使用 type、bubbles 和 cancelable 初始化this。

initEvent() 与事件 构造函数的功能重复，并且 无法设置 composed。 为了兼容遗留内容，必须支持它。

2.3. 对 Window 接口的传统扩展

partial interface Window {
  [Replaceable] readonly attribute (Event or undefined) event; // legacy
};

每个 Window 对象都有一个关联的 当前事件（未定义或一个 Event 对象）。除非另有说明，否则它是未定义的。

event 的 getter 步骤是返回 this 的 当前事件。

强烈建议 Web 开发者依赖传递给事件监听器的 Event 对象，因为这将产生更具可移植性的代码。此属性在 workers 或 worklets 中不可用，并且对于在 shadow trees 中分派的事件是不准确的。

2.4. 接口 CustomEvent

[Exposed=*]
interface CustomEvent : Event {
  constructor(DOMString type, optional CustomEventInit eventInitDict = {});

  readonly attribute any detail;

  undefined initCustomEvent(DOMString type, optional boolean bubbles = false, optional boolean cancelable = false, optional any detail = null); // legacy
};

dictionary CustomEventInit : EventInit {
  any detail = null;
};

事件 使用 CustomEvent 接口可以用于携带自定义数据。

event = new CustomEvent(type [, eventInitDict])
其工作方式类似于 Event 的构造函数，但 eventInitDict 参数现在还允许设置 detail 属性。
event . detail
返回创建 event 时的任何自定义数据。 通常用于合成事件。

detail 属性必须返回它初始化时的值。

initCustomEvent(type, bubbles, cancelable, detail) 方法的步骤如下：

  1. 如果 this 的 dispatch flag 已设置，则返回。

  2. 初始化 this ，包括 type、bubbles 和 cancelable。

  3. 将 this 的 detail 属性设置为 detail。

2.5. 构造事件

规范可以为全部或部分 事件定义事件 构造步骤。该算法会接收一个 事件 event 和一个 EventInit eventInitDict，如内部事件创建步骤中所述。

此构造可供 Event 子类使用，这些子类的 结构比其初始化字典成员与 IDL 属性之间简单的一对一映射 更为复杂。

当调用 Event 接口或继承自 Event 接口的接口的 构造函数时， 给定参数 type 和 eventInitDict，必须运行以下步骤：

  1. 令 event 为使用此接口、null、当前时间和 eventInitDict 运行内部事件 创建步骤的 结果。

  2. 将 event 的 type 属性初始化为 type。

  3. 返回 event。

要 使用 eventInterface 创建事件， 其中 eventInterface 必须是 Event 或 继承自该接口的 接口，并且可以选择性地给定一个领域 realm，运行以下步骤：

  1. 如果未给定 realm，则将其设为 null。

  2. 令 dictionary 为将 JavaScript 值 undefined 转换 为 eventInterface 的构造函数所接受的字典类型的结果。 （此字典类型可以是 EventInit 或继承自它的 字典。）

    如果成员是必需的，则此方法不起作用；请参阅 whatwg/dom#600。

  3. 令 event 为使用 eventInterface、realm、 事件所表示的发生时刻以及 dictionary 运行内部事件 创建步骤的结果。

    在 macOS 中，可以通过 NSEvent 对象的 timestamp 属性获取输入操作的发生时刻。

  4. 将 event 的 isTrusted 属性初始化为 true。

  5. 返回 event。

创建事件旨在供其他需要 分别创建和分派事件，而不是直接 触发事件的规范使用。它 确保事件的属性被初始化为 正确的默认值。

给定 eventInterface、 realm、time 和 dictionary，内部 事件创建步骤如下：

  1. 令 event 为使用 eventInterface 创建新对象的结果。如果 realm 不为 null，则使用该领域；否则使用 Web IDL 中定义的默认行为。

    截至撰写本文时，Web IDL 尚未定义任何默认行为； 请参阅 whatwg/webidl#135。

  2. 设置 event 的已初始化标志。

  3. 将 event 的 timeStamp 属性初始化为根据 time 和 event 的 相关全局对象计算得到的相对高精度粗略 时间。

  4. 对于 dictionary 中的每个 member → value： 如果 event 具有一个属性，且该属性的 标识符为 member，则 将该属性初始化为 value。

  5. 使用 event 和 dictionary 运行事件构造步骤。

  6. 返回 event。

2.6. 定义事件接口

通常，在定义一个继承自Event的新接口时，请务必征求WHATWG或W3C WebApps WG社区的反馈。

CustomEvent接口可以作为起点。然而，不要引入任何init*Event()方法，因为它们与构造函数是冗余的。继承自Event接口的接口中如果包含此类方法，也只是出于历史原因。

2.7. 接口 EventTarget

[Exposed=*]
interface EventTarget {
  constructor();

  undefined addEventListener(DOMString type, EventListener? callback, optional (AddEventListenerOptions or boolean) options = {});
  undefined removeEventListener(DOMString type, EventListener? callback, optional (EventListenerOptions or boolean) options = {});
  boolean dispatchEvent(Event event);
};

callback interface EventListener {
  undefined handleEvent(Event event);
};

dictionary EventListenerOptions {
  boolean capture = false;
};

dictionary AddEventListenerOptions : EventListenerOptions {
  boolean passive;
  boolean once = false;
  AbortSignal signal;
};

一个 EventTarget 对象表示一个目标，当某件事情发生时，可以将事件分派 给该目标。

每个 EventTarget 对象都具有关联的事件监听器列表（一个包含零个或 多个事件 监听器的列表）。它最初是空列表。

一个事件监听器 可用于观察特定的 事件，并由以下部分组成：

  • 类型（一个字符串）
  • 回调（null 或一个 EventListener 对象）
  • 捕获（一个布尔值，最初为 false）
  • 被动（null 或一个布尔值，最初为 null）
  • 单次（一个布尔值，最初为 false）
  • 信号（null 或一个 AbortSignal 对象）
  • 已移除（用于记录状态的布尔值，最初为 false）

尽管回调是一个 EventListener 对象，但如上所示，事件监听器是一个更广泛的概念。

每个 EventTarget 对象还具有关联的获取父节点算法， 该算法接收一个事件 event，并返回一个 EventTarget 对象。除非 另有规定，否则返回 null。

节点、 影子根节点和 文档会重写 获取父节点算法。

每个 EventTarget 对象都可以具有关联的 激活行为算法。该 激活行为算法接收一个事件，如 分派 算法中所述。

这是因为用户代理会针对某些 EventTarget 对象（例如 area 元素）执行某些操作，以响应合成的 MouseEvent 事件，其 type 属性为 click。出于 Web 兼容性考虑，无法将其 移除，因此它如今已成为定义某个对象激活行为的正式方式。[HTML]

每个具有 EventTarget 激活行为的对象，还可以 同时具有（而非仅有其中之一）遗留预激活行为算法 和遗留已取消激活行为 算法。

这些算法仅适用于复选框和单选按钮 input 元素， 不得用于其他任何用途。[HTML]

target = new EventTarget();

创建一个新的 EventTarget 对象，开发者可以使用该对象分派和 监听事件。

target . addEventListener(type, callback [, options])

为 type 属性值为 type 的事件追加一个事件监听器。 callback 参数设置在事件被分派时将调用的 回调。

options 参数设置监听器专用的选项。为兼容性考虑，该参数可以是一个 布尔值，在这种情况下，该方法的行为与将该值指定为 options 的 capture 时完全相同。

当 options 的 capture 设置为 true 时，会阻止 回调在事件的 eventPhase 属性值为 BUBBLING_PHASE 时被调用。 当其为 false（或不存在）时， 回调不会在事件的 eventPhase 属性值为 CAPTURING_PHASE 时被调用。 无论哪种情况，只要 事件的 eventPhase 属性值为 AT_TARGET，回调都会被调用。

当 options 的 passive 设置为 true 时，表示 回调不会通过调用 preventDefault() 来取消事件。 这用于启用 § 2.8 观察事件监听器中所述的性能优化。

当 options 的 once 设置为 true 时，表示 回调只会被调用一次，之后 事件监听器将 被移除。

如果为 options 的 signal 传入一个 AbortSignal， 则事件监听器将在信号被中止时移除。

该事件监听器会被追加到 target 的 事件监听器列表中；如果已有相同的 类型、 回调和 捕获值，则不会追加。

target . removeEventListener(type, callback [, options])

从 target 的 事件监听器列表中移除具有相同 type、callback 和 options 的事件监听器。

target . dispatchEvent(event)

将合成事件 event 分派给 target，并且如果 event 的 cancelable 属性值为 false，或者其 preventDefault() 方法未被调用，则返回 true；否则返回 false。

要展平 options，运行以下 步骤：

  1. 如果 options 是一个布尔值，则返回 options。

  2. 返回 options["capture"]。

要进一步展平 options，运行以下 步骤：

  1. 令 capture 为展平 options 的结果。

  2. 令 once 为 false。

  3. 令 passive 和 signal 为 null。

  4. 如果 options 是一个字典：

    1. 将 once 设为 options["once"]。

    2. 如果 options["passive"] 存在，则将 passive 设为 options["passive"]。

    3. 如果 options["signal"] 存在，则将 signal 设为 options["signal"]。

  5. 返回 capture、passive、once 和 signal。

new EventTarget() 构造函数的步骤是不执行任何操作。

由于其他地方规定的默认值，返回的 EventTarget 的 获取父节点算法 将返回 null，并且它不会具有 激活行为、遗留预激活行为 或遗留已取消激活行为。

将来我们可以允许自定义获取父节点算法。如果这 很有用，请支持议题 #583。目前，所有 由作者创建的 EventTarget 对象 都不参与树结构。

给定事件类型 type 和一个 EventTarget eventTarget，默认被动 值按以下方式确定：

  1. 如果以下条件全部为 true，则返回 true：

    • type 是 "touchstart"、"touchmove"、 "wheel" 或 "mousewheel" 之一。[TOUCH-EVENTS] [UIEVENTS]

    • eventTarget 是一个 Window 对象，或者是一个节点，其节点文档 为 eventTarget，或者是一个节点，其节点 文档的文档元素 为 eventTarget，或者是一个节点，其节点 文档的 body 元素为 eventTarget。[HTML]

  2. 返回 false。

要添加事件 监听器，给定一个 EventTarget 对象 eventTarget 和一个事件监听器 listener，运行以下步骤：

  1. 如果 eventTarget 是一个 ServiceWorkerGlobalScope 对象，且其 服务工作线程的 脚本资源的 曾被求值标志已设置，并且 listener 的 类型 与任意 服务工作线程事件的 type 属性值匹配，则应向控制台报告一条警告，指出这 可能无法得到 预期结果。[SERVICE-WORKERS]

  2. 如果 listener 的信号不为 null，且已被 中止，则返回。

  3. 如果 listener 的回调为 null，则返回。

  4. 如果 listener 的被动值为 null，则将其设为 根据 listener 的类型和 eventTarget 确定的默认 被动值。

  5. 如果 eventTarget 的事件监听器列表不包含一个 事件监听器，其类型为 listener 的 类型， 回调为 listener 的 回调，且捕获值为 listener 的捕获值，则将 listener 追加 到 eventTarget 的事件 监听器列表。

  6. 如果 listener 的信号不为 null，则 向其添加以下 中止步骤：

    1. 使用 eventTarget 和 listener 移除事件监听器。

添加事件监听器概念的存在是为了确保事件处理器使用 相同的代码路径。[HTML]

addEventListener(type, callback, options) 方法的步骤如下：

  1. 令 capture、passive、once 和 signal 为 进一步展平 options 的结果。

  2. 使用this 和一个事件监听器，添加事件 监听器，其 类型 为 type，回调为 callback，捕获值为 capture， 被动值为 passive，单次值 为 once，且信号为 signal。

要移除事件 监听器，给定一个 EventTarget 对象 eventTarget 和一个事件监听器 listener，运行以下步骤：

  1. 如果 eventTarget 是一个 ServiceWorkerGlobalScope 对象，且其 服务工作线程的 待处理事件类型集合 包含 listener 的类型，则应向控制台报告一条警告， 指出这可能无法得到预期结果。[SERVICE-WORKERS]

  2. 将 listener 的已移除设为 true，并 从 eventTarget 的移除 listener，即从其 事件监听器列表中移除。

HTML 需要此算法来定义事件处理器。[HTML]

要移除所有 事件监听器，给定一个 EventTarget 对象 eventTarget：对于 eventTarget 的 事件监听器列表中的每个 listener： 使用 eventTarget 和 listener 移除事件监听器。

HTML 需要此算法来定义 document.open()。[HTML]

removeEventListener(type, callback, options) 方法的步骤如下：

  1. 令 capture 为展平 options 的结果。

  2. 如果this 的事件 监听器列表 包含一个 事件监听器，其类型为 type， 回调为 callback，且 捕获值为 capture，则 使用this 和该事件监听器 移除事件监听器。

事件监听器列表不会包含多个具有相同 type、callback 和 capture 的事件监听器，因为添加事件监听器 算法会阻止这种情况。

dispatchEvent(event) 方法的步骤 如下：

  1. 如果 event 的分派标志已设置，或者其已初始化标志未 设置，则抛出一个 "InvalidStateError" DOMException。

  2. 将 event 的 isTrusted 属性初始化为 false。

  3. 返回将 event 分派给this 的结果。

2.8. 观察事件监听器

一般来说，开发者不会期望事件监听器的存在是可观察的。 事件监听器的影响由其回调决定。也就是说， 开发者添加一个无操作的事件监听器时不会期望它有任何副作用。

遗憾的是，某些事件 API 的设计使得要高效实现它们， 就必须观察事件监听器。这可能使监听器的存在 变得可观察， 因为即使是空监听器，也可能对应用程序的行为产生显著的性能影响。 例如，可用于阻止异步滚动的触摸事件和滚轮事件。在某些情况下， 可以通过将事件标记为cancelable， 但仅在存在 至少一个非passive 监听器时才这样做。例如， 非passive TouchEvent 监听器必须阻止滚动，但如果所有 监听器都是 passive， 则可以允许滚动开始 并行进行，方法是使 TouchEvent 不可取消（因此对 preventDefault() 的调用会被忽略）。因此，分派事件的代码能够观察到 非passive 监听器的缺失，并据此清除正在分派的事件的 cancelable 属性。

理想情况下，任何新的事件API都应定义为不需要此属性。（请使用whatwg/dom进行讨论。）

要获取遗留的Service Worker获取事件侦听器回调，给定一个ServiceWorkerGlobalScopeglobal，请运行以下步骤。这些步骤将返回一个EventListener对象的列表。

  1. 令 callbacks 为 « »。

  2. 对于每一个 listener 属于 global 的 事件监听器列表：如果 listener 的 类型为 "fetch" 并且 listener 的 回调 不为 null， 则将 listener 的 回调添加到 callbacks。

  3. 返回 callbacks。

2.9. 分发事件

要向一个 事件 event 的 一个 EventTarget 对象 target 分派事件，并可选地提供 legacy target override flag 和 legacyOutputDidListenersThrowFlag：

  1. 设置 event 的分派标志。

  2. 如果未给定 legacy target override flag，则令 targetOverride 为 target；否则为 target 的关联的 Document。 [HTML]

    legacy target override flag 仅由 HTML 使用，且仅当 target 是一个 Window 对象时使用。

  3. 令 activationTarget 为 null。

  4. 令 relatedTarget 为以 target 为参照，对 event 的 relatedTarget 进行重定向的结果。

  5. 令 clearTargets 为 false。

  6. 如果 target 不等于 relatedTarget，或者 target 是 event 的 relatedTarget：

    1. 令 touchTargets 为一个新的列表。

    2. 对于 event 的触摸目标列表中的每个 touchTarget：将以 target 为参照 重定向 touchTarget 的结果追加到 touchTargets。

    3. 使用 event、target、 targetOverride、relatedTarget、touchTargets 和 false 追加到事件路径。

    4. 如果 event 是一个 MouseEvent 对象， 且 event 的 type 属性为 "click"，则令 isActivationEvent 为 true；否则为 false。

    5. 如果 isActivationEvent 为 true，且 target 具有 激活行为，则将 activationTarget 设为 target。

    6. 如果 target 是一个可插槽化对象 且已被分配，则令 slottable 为 target； 否则为 null。

    7. 令 slotInClosedTree 为 false。

    8. 令 parent 为使用 event 调用 target 的获取 父节点 算法的结果。

    9. 当 parent 不为 null 时：

      1. 如果 slottable 不为 null：

        1. 断言：parent 是一个插槽。

        2. 将 slottable 设为 null。

        3. 如果 parent 的根节点是一个影子根节点，且其 模式为 "closed"， 则将 slotInClosedTree 设为 true。

      2. 如果 parent 是一个可插槽化对象且已被分配，则 将 slottable 设为 parent。

      3. 令 relatedTarget 为以 parent 为参照，对 event 的 relatedTarget 进行重定向的结果。

      4. 令 touchTargets 为一个新的列表。

      5. 对于 event 的 触摸目标列表中的每个 touchTarget： 将以 parent 为参照，对 touchTarget 进行重定向 的结果追加到 touchTargets。

      6. 如果 parent 是一个 Window 对象，或者 parent 是一个节点， 且 target 的根节点是 parent 的包含影子树且包含自身的 祖先：

        1. 如果 isActivationEvent 为 true，event 的 bubbles 属性为 true，activationTarget 为 null，且 parent 具有 激活 行为，则将 activationTarget 设为 parent。

        2. 使用 event、parent、null、 relatedTarget、touchTargets 和 slotInClosedTree 追加到事件路径。

      7. 否则，如果 parent 为 relatedTarget，则将 parent 设为 null。

      8. 否则：

        1. 将 target 设为 parent。

        2. 如果 isActivationEvent 为 true，activationTarget 为 null，且 target 具有激活 行为，则将 activationTarget 设为 target。

        3. 使用 event、parent、 target、relatedTarget、touchTargets 和 slotInClosedTree 追加到事件路径。

      9. 如果 parent 不为 null，则将 parent 设为 使用 event 调用 parent 的获取父节点算法的结果。

      10. 将 slotInClosedTree 设为 false。

    10. 令 clearTargetsItem 为 event 的 路径中， 经影子树调整的目标不为 null 的最后一个事件路径项。

    11. 如果 clearTargetsItem 的经影子树调整的目标、 clearTargetsItem 的relatedTarget，或 clearTargetsItem 的触摸 目标列表中的一个 EventTarget 对象是一个节点， 且其根节点是一个影子根节点：则将 clearTargets 设为 true。

    12. 如果 activationTarget 不为 null，且 activationTarget 具有 遗留预激活 行为，则运行 activationTarget 的 遗留预激活 行为。

    13. 按照相反顺序，遍历 event 的路径中的每个 item：

      1. 如果 item 的经影子树调整的目标 不为 null，则 将 event 的 eventPhase 属性设为 AT_TARGET。

      2. 否则，将 event 的 eventPhase 属性设为 CAPTURING_PHASE。

      3. 使用 item、event、"capturing"， 以及给定的 legacyOutputDidListenersThrowFlag（如果提供）， 执行调用。

    14. 对于 event 的路径中的每个 item：

      1. 如果 item 的经影子树调整的目标 不为 null，则 将 event 的 eventPhase 属性设为 AT_TARGET。

      2. 否则：

        1. 如果 event 的 bubbles 属性为 false，则 继续。

        2. 将 event 的 eventPhase 属性设为 BUBBLING_PHASE。

      3. 使用 item、event、"bubbling"， 以及给定的 legacyOutputDidListenersThrowFlag（如果提供）， 执行调用。

  7. 将 event 的 eventPhase 属性设为 NONE。

  8. 将 event 的 currentTarget 属性设为 null。

  9. 将 event 的路径设为空列表。

  10. 取消设置 event 的分派标志、停止传播标志 和 立即停止传播标志。

  11. 如果 clearTargets 为 true：

    1. 将 event 的目标设为 null。

    2. 将 event 的relatedTarget 设为 null。

    3. 将 event 的触摸目标列表设为空列表。

  12. 如果 activationTarget 不为 null：

    1. 如果 event 的已取消标志未设置，则使用 event 运行 activationTarget 的激活行为。

    2. 否则，如果 activationTarget 具有 遗留已取消激活 行为，则运行 activationTarget 的遗留已取消激活 行为。

  13. 如果 event 的已取消标志已设置，则返回 false；否则返回 true。

要追加到 事件路径，给定一个 事件 event、 一个 EventTarget 对象 invocationTarget、一个 潜在 事件目标 shadowAdjustedTarget、一个潜在事件目标 relatedTarget、一个由潜在事件目标组成的列表 touchTargets，以及一个布尔值 slotInClosedTree：

  1. 令 invocationTargetInShadowTree 为 false。

  2. 如果 invocationTarget 是一个节点，且其根节点是一个 影子 根节点，则将 invocationTargetInShadowTree 设为 true。

  3. 令 rootOfClosedTree 为 false。

  4. 如果 invocationTarget 是一个影子根节点，且其模式 为 "closed"，则将 rootOfClosedTree 设为 true。

  5. 向 event 的路径中追加一个新的事件路径项，其 调用目标为 invocationTarget， 调用目标位于影子树中 为 invocationTargetInShadowTree， 经影子树调整的目标为 shadowAdjustedTarget， relatedTarget 为 relatedTarget， 触摸目标列表为 touchTargets， 闭合树的根节点为 rootOfClosedTree，且 闭合树中的插槽为 slotInClosedTree。

要调用，给定一个事件路径项 pathItem、一个事件 event、一个字符串 phase，以及可选的 legacyOutputDidListenersThrowFlag：

  1. 令 targetItem 为 pathItem。

  2. 当 targetItem 的经影子树调整的目标为 null 时：将 targetItem 设为 event 的 路径中位于 targetItem 之前的事件路径项。

  3. 将 event 的目标设为 targetItem 的 经影子树调整的目标。

  4. 将 event 的relatedTarget 设为 pathItem 的 relatedTarget。

  5. 将 event 的触摸目标列表设为 pathItem 的 触摸目标列表。

  6. 如果 event 的停止传播标志已设置，则返回。

  7. 将 event 的 currentTarget 属性初始化为 pathItem 的 调用目标。

  8. 令 listeners 为 event 的 currentTarget 属性值的事件监听器列表的克隆。

    这可以避免在此之后添加的事件监听器被 执行。请注意，由于已移除字段的存在，移除操作仍然有效。

  9. 令 invocationTargetInShadowTree 为 pathItem 的 调用目标位于影子树中。

  10. 令 found 为使用 event、 listeners、phase、invocationTargetInShadowTree 和 可选的 legacyOutputDidListenersThrowFlag 运行内部调用的结果。

  11. 如果 found 为 false，且 event 的 isTrusted 属性为 true：

    1. 令 originalEventType 为 event 的 type 属性值。

    2. 如果 event 的 type 属性值与下表第一列中的任一字符串匹配， 则将 event 的 type 属性值设为 同一行第二列中的字符串；否则返回。

      事件类型 遗留事件类型
      "animationend" "webkitAnimationEnd"
      "animationiteration" "webkitAnimationIteration"
      "animationstart" "webkitAnimationStart"
      "transitionend" "webkitTransitionEnd"

    3. 使用 event、listeners、phase、 invocationTargetInShadowTree 和 可选的 legacyOutputDidListenersThrowFlag 执行内部调用。

    4. 将 event 的 type 属性值设为 originalEventType。

要内部调用，给定一个 事件 event、一个由 事件 监听器组成的列表 listeners、一个 字符串 phase、一个布尔值 invocationTargetInShadowTree，以及可选的 legacyOutputDidListenersThrowFlag：

  1. 令 found 为 false。

  2. 对于 listeners 中每个 listener，其 已移除值为 false：

    1. 如果 event 的 type 属性值不等于 listener 的 类型，则继续。

    2. 将 found 设为 true。

    3. 如果 phase 为 "capturing"，且 listener 的 捕获值为 false，则继续。

    4. 如果 phase 为 "bubbling"，且 listener 的 捕获值为 true，则继续。

    5. 如果 listener 的单次值为 true，则 使用 event 的 currentTarget 属性值和 listener 移除事件监听器。

    6. 令 targetGlobal 为 event 的 currentTarget 的 节点文档的相关全局对象，如果 event 的 currentTarget 是一个节点； 否则为 event 的 currentTarget 的 相关全局对象。

    7. 令 listenerGlobal 为 listener 的 回调的关联领域的全局对象。

    8. 如果 targetGlobal 或 listenerGlobal 是一个 Window 对象，且其 关联的 Document 不是完全活动的，则 继续。

    9. 令 currentEvent 为 undefined。

    10. 如果 listenerGlobal 是一个 Window 对象：

      1. 将 currentEvent 设为 listenerGlobal 的 当前事件。

      2. 如果 invocationTargetInShadowTree 为 false，则将 listenerGlobal 的当前事件设为 event。

    11. 如果 listener 的被动值为 true，则设置 event 的处于被动监听器中标志。

    12. 如果 listenerGlobal 是一个 Window 对象，则 使用 event 和 listener 记录事件 监听器的计时信息。
