2. 术语

与坐标轴和尺寸相关的一些关键术语 定义于 CSS 书写模式 3 § 6 抽象盒术语中。

尺寸
一维或二维度量： 块尺寸和/或行内尺寸； 或者是宽度和/或高度。
内部尺寸
一个盒的 内容盒尺寸。
外部尺寸
一个盒的 外边距盒尺寸。
确定尺寸
无需执行布局即可确定的尺寸； 即，一个 <length>、 一段文本的度量值（不考虑换行）、 初始包含块的尺寸， 或者一个 <percentage> 或其他公式 （例如非替换块的“拉伸适应”尺寸计算 [CSS2]）， 且该公式仅相对于确定尺寸进行解析。

此外，绝对定位元素的包含块尺寸相对于该元素始终是 确定的。

不确定尺寸
不是确定尺寸的尺寸。 不确定的可用空间本质上是 无限的。

注： 内在尺寸计算关键字，例如 max-content，是不确定的， 即使无需对子元素进行布局即可确定它们， 例如由于尺寸遏制或没有子元素。

可用 空间
表示盒被布局到其中的空间的尺寸， 由 该盒所参与的格式化上下文的规则确定。 盒的可用空间通常 要么是其包含块的度量值（如果它是确定的）， 要么是无限尺寸（当它是不确定的时）。 可用空间也可以是 最小内容 约束或 最大内容 约束， 从而强制布局到其中的盒在该约束下进行布局。

拉伸适应
对给定尺寸进行的拉伸适应 是该尺寸 减去盒在给定维度上的计算外边距（不折叠，并将 auto 视为零）、 边框和内边距 （从而使外部尺寸完全适合）， 并将结果下限限定为零 （从而使内部尺寸不会为负）。

注：这是 CSS2.1§10.3.3 中用于计算正常流中 非替换块的 auto 宽度的公式。

回退尺寸
某些尺寸算法无法很好地处理无限尺寸。 在这些情况下，将改用回退尺寸。 除非另有规定， 它是初始包含块的尺寸。

2.1. 自动盒尺寸

CSS 中有四种自动确定的尺寸 （即根据上下文由 auto 尺寸规则得到的尺寸）：

拉伸适应尺寸
拉伸适应行内 尺寸
拉伸适应块 尺寸
如果一个盒的外部尺寸在给定轴上填满 可用空间， 该盒所占据的尺寸； 换言之，如果可用空间是确定的，则为对该空间进行的拉伸 适应。 如果可用空间是不确定的，则未定义。

注： 对于行内 轴，这在 CSS2.1§10.3.5 中称为“可用宽度”， 并按 CSS2.1§10.3.3 中的规则计算。

注： 涉及此尺寸的计算需要 为可用空间 是不确定时 指定回退行为（如果这种情况可能发生）。

最大内容尺寸
当给定无限可用空间时，盒在给定轴上的“理想”尺寸。 通常，这是盒在该轴上仍能包住其内容时所能采用的最小尺寸， 即在避免溢出的同时尽量减少未填充空间。
最大内容行内尺寸

盒在行内轴上的“理想”尺寸。 通常，如果盒中的软换行机会一个也不采用， 则这是它在包住其内容的同时所能采用的最窄行内尺寸。 （参见 § 5 内在尺寸确定。）

注： 这在 CSS2.1§10.3.5 中称为“首选宽度”， 在 CSS2.1§17.5.2.2 中称为“最大单元格宽度”。

最大内容块尺寸

盒在块轴上的“理想”尺寸。 通常是内容布局后的块 尺寸。

如果理想的最大内容 尺寸小于最小内容尺寸 （例如由于使用了负外边距）， 则实际的最大内容尺寸以下限最小内容尺寸为准。

最小内容尺寸
名义上，这是盒所能采用的最小尺寸， 且不会导致通过选择更大的尺寸即可避免的溢出。 形式上，它是在最小内容约束下确定尺寸时盒的尺寸， 参见 § 5 内在尺寸确定。
最小内容行内尺寸

最小内容 尺寸在行内轴上的值。 通常，如果采用盒中的所有软换行机会， 则这是恰好能包住其内容的行内 尺寸。

注： 这在 CSS2.1§10.3.5 中称为“首选最小宽度”， 在 CSS2.1§17.5.2.2 中称为“最小内容宽度”。

最小内容块尺寸

最小内容 尺寸在块轴上的值。 对于块容器、表格和行内 盒， 它等价于最大内容块尺寸。

适应内容尺寸
适应内容行内 尺寸
适应内容块 尺寸
如果给定轴上的可用空间 是确定的， 则等于 clamp(最小内容尺寸, 拉伸适应尺寸, 最大内容尺寸) （即 max(最小内容尺寸, min(最大内容尺寸, 拉伸适应尺寸))）。 在最小内容约束下确定尺寸时， 等于最小内容尺寸。 否则，等于该轴上的最大内容尺寸。

注： 这在 CSS2.1§10.3.5 和 CSS 多列布局 § 3.4 中称为“收缩适应”宽度。

内在尺寸
最大内容尺寸或最小内容尺寸， 即主要由内容尺寸产生的尺寸。 （该术语的某些用法也可能指 主要由这两种尺寸之一派生出的尺寸。）

替换元素通常根据其自然尺寸派生其内在尺寸。

以下示例将适应内容尺寸计算 应用于内部 <div> 的宽度， 并将其放置在尺寸不同的包含块中：

  • 在最窄的包含块（2ch）中， 盒采用其最小内容尺寸——为了 完整包含其全部内容而溢出包含块， 此时内容已尽可能窄地换行。

  • 在中等宽度的包含块（9ch）中， 盒采用其拉伸适应尺寸——恰好填满包含块， 同时其内容换行以适应盒内空间。

  • 在最宽的包含块（16ch）中， 盒采用其最大内容尺寸——小于包含块， 但恰好包住其未换行的内容。

<!DOCTYPE html>
<style>div > div { width: fit-content; }</style>
<div style="width: 2ch;">
  <div>abc def ehg</div>
</div>
<div style="width: 9ch;">
  <div>abc def ehg</div>
</div>
<div style="width: 16ch;">
  <div>abc def ehg</div>
</div>

如果在这里用 min-width 或 max-width 属性代替 width， 则会将这些相同的尺寸分别应用为最小宽度或最大宽度， 从而约束首选宽度以确定 使用宽度。 参见 § 3 指定盒尺寸和 § 3.2 尺寸 值：<length-percentage>、auto | none、stretch、min-content、max-content 和 fit-content 值。

2.2. 内在尺寸贡献

最大内容贡献
一个盒为其包含块的最大内容尺寸所贡献的尺寸。
最小内容贡献
一个盒为其包含块的最小内容尺寸所贡献的尺寸。
内在尺寸 贡献
最大内容贡献、最小内容贡献， 或以类似方式计算的基于内容的尺寸贡献。

内在尺寸贡献基于盒的外部尺寸； 为此，auto 外边距被视为零。

如果理想的最大内容贡献小于最小内容 贡献 （例如由于使用负外边距）， 则实际的最大内容贡献以下限 最小内容贡献为准。

2.3. 内在尺寸约束

最大内容 约束
由盒的包含块施加的尺寸约束， 它使该盒产生其最大内容贡献。
最小内容 约束
由盒的包含块施加的尺寸约束， 它使该盒产生其最小内容贡献。
首选宽高 比
盒固有的宽度:高度比， 它会影响各种尺寸算法， 使其在遵守其他尺寸输入的前提下尽可能生成与该宽高比一致的尺寸。 除非另有规定， 如果盒具有自然宽高比， 则盒的首选宽高比就是该自然宽高比， 并应用于其内容盒。 大多数盒都没有首选宽高比。

3. 指定盒尺寸

3.1. 尺寸属性

本节定义尺寸属性， 它们指定所应用盒的首选、 最小和最大尺寸。 它们可能的值在下一节中定义： § 3.2 尺寸值：<length-percentage>、auto | none、stretch、min-content、 max-content 和 fit-content 值。

流相对变体（inline-size、block-size 等） 使用元素自身的书写模式进行映射， 并按 [CSS-LOGICAL-1] 中的定义 与其物理对应项（width、height 等） 交互。 另见 CSS 书写模式 3 § 6 抽象盒术语。

在 CSS 中，虽然最小和最大尺寸 都会约束使用尺寸， 但最小尺寸约束始终是最强约束。 此外，内部尺寸始终以下限零为准。

.box {

stretch

5.1. 内在尺寸

盒在每个轴上的最小内容尺寸 是这样一种情况下它所具有的尺寸： 将其视为一个浮动，并在该轴上给予 auto 首选尺寸 （且该轴上没有最小或最大尺寸）， 并且其包含块在该轴上的尺寸为零。 （换言之，这是按“收缩适应”确定尺寸时所具有的最小尺寸。）

盒在每个轴上的最大内容尺寸 是这样一种情况下它所具有的尺寸： 将其视为一个浮动，并在该轴上给予 auto 首选尺寸 （且该轴上没有最小或最大尺寸）， 并且其包含块在该轴上的尺寸为无限。 （换言之，这是按“收缩适应”确定尺寸时所具有的最大尺寸。）

最小内容尺寸和最大内容尺寸 统称为 内在尺寸。

注： 当盒具有首选宽高比时， 另一维度上的尺寸约束会传递过来， 并可能影响当前所考虑维度上的 auto 尺寸。 参见 CSS2§10。

本规范未定义如何确定浮动的尺寸。 请参见 [CSS2]。 不过，没有自然尺寸的 替换元素的内在尺寸 定义如下：

UA 可以对表单控件的 最小内容和最大内容尺寸 强制设置最小值 （例如容纳一个零宽字符所需的尺寸， 或触摸目标的最小可用尺寸）， 以确保为插入符留出足够空间， 并以其他方式维持表单控件的可用性。

注： 这可能会扩展到 iframe 或其他包含内容的替换元素 （参见讨论）， 但文本输入是一个重要用例； 而且由于其位于文档内部， 它带来的额外复杂性最少。

5.2.1. 百分比尺寸盒的内在贡献

有时，百分比尺寸盒的包含 块尺寸 依赖于该盒自身的内在尺寸贡献， 从而形成循环依赖。 在计算这种盒的内在尺寸贡献时 （包括任何基于内容的自动最小尺寸计算）， 相对于与内在尺寸贡献相同轴上的尺寸 进行解析的百分比值 （即循环百分比尺寸） 会采用特殊方式进行解析：

  1. 如果盒是非替换的， 则任何最大尺寸属性或首选尺寸属性 （width/max-width/height/max-height） 如果指定为一个包含百分比的表达式 （例如 10% 或 calc(10px + 0%)）， 且该百分比是循环的， 则整个值 仅在计算盒的内在尺寸贡献时 被视为该属性的初始值。 例如，对于指定了 width: calc(20px + 50%) 的盒， 其最大内容贡献会按其 width 为 auto 的方式计算。 （不过，在盒本身的实际尺寸计算过程中， 仍会照常考虑该百分比；见下文。）
  2. 同样，如果盒是替换的， 则任何最大尺寸属性或首选尺寸属性 如果指定为一个包含百分比的表达式， 且该百分比是循环的， 则整个值 仅在计算盒的最大内容贡献时 被视为该属性的初始值。
  3. 如果盒是替换的， 则任何最大尺寸属性或首选尺寸属性 （width/max-width/height/max-height） 的值中的循环百分比， 在计算相应轴上的最小内容贡献时， 相对于零进行解析。 （有关这适用于 HTML 中哪些元素的列表，请参见 § 5.2.2 可压缩的替换元素。） 如果盒还具有首选宽高比， 则此最小内容贡献以下限 从另一轴通过首选宽高比传递而来的任何 <length-percentage> 最小尺寸为准——其中任何此类百分比都相对于零解析。

    我们是否应该在 传递百分比之前，先让它们相对于其包含块而不是零进行解析？参见 讨论。

    UA 还可以基于 UI 考虑进一步限制最小内容贡献的下限， 例如确保某些 UI 元素保持可见 （例如 select 上的下拉箭头）。

    注： 与往常一样，最小内容 贡献 也会以其自身轴上的最小尺寸作为下限。

    此规则也适用于计算 基于内容的自动最小尺寸 或其相应的尺寸贡献， 从而得到一个确定的“指定尺寸建议”。

  4. 对于最小尺寸 属性， 以及外边距和内边距 （以及沟槽）， 在确定内在尺寸贡献时， 循环百分比相对于零进行解析。

然后，除非另有规定， 在计算包含块的内容的使用尺寸和位置时：

  • 如果循环依赖是由于 包含块上块轴上的某个尺寸（但不是最小尺寸）引入的 （即在大多数布局模式中，是 block-size 或 max-block-size， 或在弹性 布局中是 flex-basis）， 并使其依赖于其内容的尺寸， 则盒的百分比不会被解析，而是表现为 auto。

    注： 网格项在两个 轴上、 弹性项在主轴上， 以及弹性项的子元素在两个轴上， 在这种情况下仍允许百分比进行解析。

  • 否则，百分比相对于包含块的尺寸进行解析。 （包含块的尺寸不会根据盒最终所得的尺寸重新解析； 因此内容可能会溢出或不足以填满包含块。）

注： 这些规则规定了此前未定义的循环情况行为， 对应于 CSS2§10.2、 CSS2§8.3 和 CSS2§8.4。 另请注意，对于 CSS2 中未描述的布局模式 （例如弹性布局）， CSS2§10.5 中的行为已由各自的规范取代。

例如，在以下标记中： 
<article style="width: min-content">
  <aside style="width: 50%;">
  LOOOOOOOOOOOOOOOOOOOONG
  </aside>
</article>

在计算外部 <article> 的宽度时， 内部 <aside> 表现为 width: auto， 因此 <article> 将自身宽度设置为该长单词的宽度。 不过，由于 <article> 的宽度并不依赖“真实”布局， 因此在解析 <aside> 时，它被视为确定的， 而 <aside> 的宽度解析为 <article> 宽度的一半。

在此示例中， 
<article style="height:auto">
  <aside style="height: 50%;">
    <div class=block style="height: 150px;"></div>
  </aside>
  <section style="height: 30px;"></section>
</article>

由于块级元素上的百分比块尺寸 （在此例中为 height） 被定义为在基于内容确定尺寸的包含块中不进行解析， 因此 <aside> 上的百分比高度会被忽略， 即其行为与指定 auto 完全相同。

当 min-height 是内在尺寸时， 仍允许百分比相对于确定的 height 进行解析 仍是一个未决问题。 （CSS2 有一条关于“高度依赖于内容”的一般性陈述， 从技术上讲这里确实如此， 尽管 CSS2 当时还没有用于 min-height 的基于内容的关键字。 由于这是新增行为，我们认为可以采用不同的行为。）

以下示例说明块轴百分比如何相对于尺寸依赖其内容的包含块进行解析。

<article style="height:100px; min-height: min-content;">
  <aside style="height: 50%;">
    <div style="height: 150px;"></div>
  </aside>
  <section style="height: 30px;"></section>
</article>

<article> 的初始高度按指定为 100px， 这会使 <aside> 在解析其百分比时高度为 50px。 然而，我们必须计算 min-height， 方法是用它替换 height。 这会使 <aside> 上的百分比表现为 auto， 因此 <aside> 最终高度为 150px。 内容总高度因此为 180px。 这大于指定的 100px 高度， 所以 <article> 会调整为 180px 高。

然后，由于该百分比最初能够相对于（100px）高度进行解析， 现在它会相对于 180px 高度进行解析， 因此 <aside> 最终高度为 90px。

<article style="height:auto; min-height: min-content;">
  <aside style="height: 50%;">
    <div class=block style="height: 150px;"></div>
  </aside>
  <section style="height: 30px;"></section>
</article>

在这种情况下，<aside> 上的百分比通常不会解析， 因为包含块的高度是 auto （因此依赖于其内容的尺寸）。 相反，它会表现为 auto， 使 <aside> 的高度为 150px， 并使 <article> 的初始高度为 180px。 min-height 不会改变这一点； height: min-content; 的行为类似于 height: auto;， 并产生相同的尺寸。 

<article style="height:100px; min-height: min-content;">
  <aside style="height: 200%;">
    <div style="height: 150px;"></div>
  </aside>
  <section style="height: 30px;"></section>
</article>

这是第一个代码块的变体， 并遵循类似的过程； <aside> 最初希望计算为 200px 高 （即 100px 包含块高度的 200%）。 当我们计算 min-height 的影响时， 该百分比表现为 auto， 使其高度变为 150px， 并使包含块总的 min-content 高度 为 180px。 由于这大于 100px， <article> 被限制为 180px， 随后百分比相对于这个新高度进行解析， <aside> 最终高度为 360px， 并溢出 <article>

5.2.2. 可压缩的替换元素

除了 HTML§14.4 [HTML] 中列出的替换元素之外， 以下 HTML 元素在用于上述百分比尺寸替换元素 规则时， 也被视为替换 元素， 当其 width/height 或 max-width/max-height 使用循环百分比尺寸表示时， 可以压缩其最小内容贡献：

  • input 的任何 type ，只要它不是“类似按钮”的； 这可能因 UA 而异。

    如果某个类型在特定 UA 中的显示方式类似于 button 元素， 即其中可以包含实际决定元素布局的内容， 则该类型在该 UA 中就是“类似按钮”的。 在大多数 UA 中，"button"、"reset"、"submit" 和 "color" 类型类似按钮； 在某些 UA 中，"file" 类型也部分类似按钮， 因为它显示为文本输入（可收缩） 和按钮（类似按钮，因此不可收缩）的组合。

  • select、 textarea、 progress、 meter、 marquee。

在 问题 6348 中跟踪将此行为应用于 max-width/height 的 Web 兼容性和实现进展。[问题 #6348]

隐私注意事项

为了支持自动布局， CSS 会调整盒的尺寸以适应其内容。 结合各种 [DOM] 和 [CSSOM] API， 这些 API 可以将盒的尺寸返回给脚本， 这可能会暴露有关这些内容的信息。 不过，通过检查 DOM 中的内容， 可以比通过盒尺寸间接获取更直接、更容易地获得这些信息。 无法检查其内容的容器 （例如跨源 iframe） 也不会向外部页面暴露尺寸信息， 除非替换元素（例如图像） 暴露其自然尺寸和/或宽高比。
