摘要

本 CSS 模块提出了控制动画图像渲染的机制。

CSS 是一种用于描述结构化文档（如 HTML 和 XML）在屏幕、纸张等上的渲染的语言。

1. 引言

本节为非规范性内容。

动画图像（由 [GIF]、[PNG]、[WebP] 等支持）在 Web 上 得到广泛使用。 默认情况下，用户代理会自动播放这些图像， 这可能会让用户感到不适， 尤其是在单个页面包含多张图像的使用场景中（例如图像画廊）， 并且违反了 WCAG 2.2 §  成功 标准 2.2.2 暂停、停止、隐藏。 目前， 网站作者无法对此进行控制。

因此，用户希望能够控制此类动画。 然而，由于使用方式多种多样， 存在广泛的使用场景以及不同的预期用户界面和用户 体验， 因此，将其作为自动或可选择启用的用户代理功能并 不足够。

为了向用户提供最佳体验， 网站需要控制播放体验， 并针对动画图像的不同用途分别进行控制。

本规范提出一个 CSS 属性（image-animation） 和一个伪类（:animated-image）， 使作者能够控制动画， 并将这种控制及其希望关联的任何用户界面 应用于相关元素。

有关动机和所考虑替代方案的进一步探讨， 另请参阅单独维护的 说明文档 和有关此主题的演示文稿。

本规范中的任何内容均不妨碍用户代理向用户提供 全局控制图像动画的设置， 例如，将所有动画图像转换为静态图像的选项。

2. 控制图像动画：image-animation 属性

名称： image-animation
值： normal | paused | stopped | running
初始值： normal
适用于： 声明式 图像
继承： 是
百分比： 不适用
计算值： 与指定值相同
规范顺序： 按照语法
动画类型： 离散

此属性允许作者控制 动画图像是 以动画状态显示 还是暂停。

当一个元素包含多个声明式图像时， （例如具有多个背景图像或边框图像的元素， 或者宿主语言中表示图像的替换元素， 同时还通过 CSS 关联了一个或多个图像）， 该元素上此属性的计算值会影响所有这些图像。

注：因此，无法暂停 同一元素中部分图像的动画， 同时让该元素的其他图像继续播放动画。

对于非动画图像， 此属性的不同值均不起作用。 此属性也不会影响视频或程序化图像。

当此属性应用于根元素时， 其对背景图像的影响会传播至画布 背景。

注：由于历史原因， background 属性不仅会从根元素传播， 还会从 HTML body 元素传播。 然而，像 image-animation 这样的新属性仅 从根元素传播。 将其设置在 body 元素上不会使其传播， 即使 background 就是在该元素上设置的。

normal
动画 图像的动画正常运行， 具体行为由图像格式和宿主语言决定。

此外， 所有具有相同绝对 URL、 相同图像数据， 且 image-animation 计算值为 normal 的 动画图像 必须作为一组，按照同一时间线同步渲染， 该时间线从组中最早添加图像的时间开始。

注：上述要求基于 [HTML] 中定义的渲染 预期，见HTML § 15.4.2 图像。 由于 [HTML] 通常不 要求用户代理以任何特定方式呈现文档， 因此也没有规范性地要求上述行为。 而本规范对此提出了要求。

stopped
动画图像 将被当作静态 图像进行渲染： 用户代理不得运行其中包含的任何动画。 如果图像包含封面 帧， 用户代理必须使用该帧； 否则，必须按照动画初始状态下 的图像进行显示。
paused
用户代理不得运行动画 图像中 包含的动画， 并且必须继续显示该值开始生效时 图像所呈现的状态， 从而有效地暂停动画。

如果在应用此值之前 动画尚未播放， 则其行为与 stopped 相同。

running
与 normal 一样， 动画 图像的动画正常运行， 具体行为由图像格式和宿主语言决定。

但是， 动画时间线的作用域限定于各个元素： 对于单个元素的所有图像， 如果其 image-animation 计算值为 running， 则具有相同绝对 URL 和相同图像数据的任何动画图像 必须作为一组，按照同一时间线同步渲染， 且该时间线与其他元素中图像的时间线不同。

如果在计算值为 running 时向元素添加图像， 则时间线从组中最早添加图像的时间开始。

如果元素先前被设置为 display: none，随后被创建或变为可见， 并且图像已添加，同时 image-animation 已设置为 running， 则时间线从元素被纳入布局时开始。

如果将此属性从其他值切换为 running， 则会设置该时间线的起点， 使动画从切换时所显示的状态 继续播放。

作者可以使用此属性来抑制非必要的图像动画， 以响应用户通过 prefers-reduced-motion 媒体特性表达的偏好。 在此示例中，基于 CSS 的图像被设为静态， 而 img 元素则保持动画播放。 
:root { /* 通过继承传播到整个文档 */
  image-animation: paused;
}
img {
  image-animation: normal;
}
某个 HTML 页面包含多个 img 元素， 它们显示同一图像的不同实例 （具有相同的绝对 URL 和相同的图像数据）， 且均设置了 image-animation: normal 样式。

其中一个元素的 image-animation 属性 被临时切换为 paused， 从而停止其图像的动画。 其他图像不受影响， 它们的动画继续播放。

随后，处于 image-animation 属性值为 paused 的元素 被更改为 running。 此时，该图像恢复播放动画， 而不考虑其他图像在其时间线上已播放到什么位置， 因而不再保持同步。

再往后，该元素的 image-animation 属性 被更改为 normal。 此时，该图像的动画会立即恢复 与其他实例的同步状态。

image-animation 属性不仅影响光栅图像 格式， 还会影响矢量图像， 包括 SVG（参见 [SVG2]）。 但是，这仅适用于作为图像加载的独立 SVG 资源， 不包括 直接内联在 HTML 文档中的 svg 元素。 （不过，如果将此属性设置在 svg 元素上， 该属性仍会被继承， 并影响通过 SVG image 元素加载的任何动画 声明式图像。）

3. 区分动画图像：:animated-image 伪类

:animated-image 伪类匹配表示声明式图像 且已加载动画图像 的元素。 要使 animated-image 伪类匹配， 图像不仅必须采用支持动画的格式， 而且还必须确实是动画图像。

对于不表示声明式图像的元素， animated-image 伪类永远不会匹配。

作者可以使用此伪类 有选择地提供某种用户界面， 使用户能够播放已暂停的图像。

在这个简单的示例中， 能够播放动画的图像最初处于暂停状态， 并对其应用滤镜， 使其看起来暗淡且呈灰色。 当鼠标悬停在图像上或图像获得焦点时， 滤镜会被移除， 并允许图像播放动画。

img:animated-image {
  image-animation: paused;
  filter: grayscale(10%) contrast(50%) brightness(80%);
}
img:animated-image:hover,
img:animated-image:focus {
  filter: none;
  image-animation: running;
}
对于构建用户界面以控制图像动画的作者而言， 考虑键盘用户的需求 十分重要， 并应避免使交互仅依赖鼠标操作。
在上述示例中， 不仅可以通过将鼠标悬停在图像上 触发播放，还可以通过使图像获得焦点来触发。 为了使其功能完整， 需要使能够播放动画的图像可获得焦点。 可以通过类似 以下代码片段的方式实现。 
function setImageFocusability(event) {
  var img = event.target;
  if (img.matches(":animated-image") {
    img.tabIndex = 0;
  } else {
    img.removeAttribute("tabindex");
  }
}
document.querySelectorAll("img").forEach( (i) => {
  setImageFocusability({target: i });
  i.addEventListener('load', setImageFocusability);
  i.addEventListener('error', setImageFocusability);
});

:animated-image 是否匹配 不受图像当前播放状态的影响， 也不受 image-animation 属性值的影响。 但是，如果某项用户代理设置已在全局禁用图像动画， 则在该设置启用时， 此类用户代理可以将原本能够播放动画但动画被抑制的图像 视为静态图像， 并使其不匹配 :animated-image。

提供全局禁用图像动画设置的用户代理 面临可用性与隐私之间的权衡。 由于 :animated-image 的主要作用是使作者 能够仅针对可播放动画的图像 提供图像动画的用户界面控件， 因此，当动画被抑制时， :animated-image 不匹配 这些图像最符合作者的需求。 然而，这可能被用作指纹识别途径： 通过加载已知能够播放动画的图像， 并检查 :animated-image 是否匹配， 就可以判断该设置是否已启用。 反过来， 如果通过使 :animated-image 即使在用户代理设置抑制动画时 仍匹配可播放动画的图像来缓解这一问题， 虽然可以保护隐私， 但作者引入的图像动画控制界面元素 可能会显示在没有动画可控制的图像上。

4. 术语

静态图像
预期仅显示单个帧 作为最终观看体验的图像。

JPEG 图像属于静态 图像。

动画图像
预期将多个帧 依次显示为最终观看体验的一部分的图像， 这些帧可以循环播放，但不一定必须循环。

动画 PNG 图像， 或动画 [GIF] 图像 都属于动画 图像。

支持渐进式渲染或多遍加载 并不意味着图像符合动画图像的定义。

声明式 图像
宿主语言中的替换元素， 表示静态图像 或动画图像， 但不包括视频或程序化 图像； 或者通过 CSS 插入文档渲染结果中的图像。

HTML 的 img [HTML] 元素， 包括嵌套在 picture 元素中的情况； HTML 的 object [HTML] 元素，在其 表示图像时； 或者 image [SVG2] 元素， 都属于声明式 图像， 通过 background-image 或 border-image 等属性插入的图像， 或通过 content 属性插入的图像也是如此。

当 HTML video 元素表示其海报帧时（且仅在此时）， 该元素 被视为声明式图像。

视频
宿主语言中表示动态图像的替换元素， 通常伴有声音，但不一定必须有声音， 通常提供交互式控件，但不一定必须提供 （用于播放、暂停、跳转播放位置、控制音量、全屏显示等）， 也可能附带隐藏式字幕或字幕，但并非必需。

注：从概念角度来看，如果仅 根据文件格式判断， 视频和动画图像存在相当程度的 重叠， 原则上也不一定能够区分二者。 此处的区别基于作者的意图， 并通过文档中所选用的元素来体现。

HTML 的 video [HTML] 元素表示 视频。

假设用户代理支持以下两种用法， 同一个 video/mp4 文件 如果通过 video 元素呈现，则会被视为视频； 如果将其用作 CSS background-image，则会被视为声明式 图像。
程序化 图像
通过宿主语言的 API 以编程方式创建的图像， 而不是从外部资源加载的图像。

HTML 的 canvas [HTML] 元素表示 程序化 图像。

封面帧
某些动画图像 格式允许 图像创建者 指定一张静态图像， 本文档将其称为封面帧， 用于在动画未运行时显示， 并且不同于动画的初始状态。

5. 无障碍注意事项

本节为非规范性内容。
  • 本规范引入的特性使作者能够 解决原本可能违反 WCAG 2.2 §  成功 标准 2.2.2 暂停、停止、隐藏的问题。
  • 网页已经可以包含动画图像， 并且已经要求提供适当的 alt 文本。 为适应动画的暂停和恢复，无须也不预期进行任何更改。 例如， “被坠落铁砧压扁的卡通郊狼”、 “可爱的跳舞仓鼠”、 “正在施工”、 或“旋转的加载指示器” 等描述，无论动画是否正在运行， 都同样恰当且形象。
  • 目前，屏幕阅读器通常不会选择以不同方式朗读动画图像 和非动画图像， 尽管在认为有必要时，可以扩展无障碍树以公开此信息。 同样，也不预期它们会以不同方式朗读暂停或播放中的图像， 尽管在认为有必要时，也可以扩展无障碍树以公开此信息。
  • 正如§ 3 区分动画图像： :animated-image 伪类中所讨论的， 构建用于控制图像动画的用户界面的作者 需要采取常规的预防措施， 以构建无障碍的用户界面。 由于无法直接通过 CSS 使元素可获得焦点， 因此，正确的键盘导航还需要设置元素属性。 另一种解决方案， 可以替代或补充让作者在 匹配 :animated-image 伪类的元素上 自行构建用户界面， 即允许作者指示用户代理 在适当情况下自行提供用户界面。

    例如，可以为 image-animation 属性 定义一个额外的 controlled 值。 当指定此值时， 图像动画最初不会运行， 就像指定了 paused 一样。 此外， 如果底层元素表示图像 （即这不是通过 CSS 加载的图像）， 并且该图像确实是动画图像， 则用户代理会提供某种用户界面，允许用户 播放和暂停动画， 并且还会使该元素可获得焦点。

    如有必要，可以在本规范的后续版本中加入此功能。 但是， 目前尚不确定作者是否会广泛使用此功能， 因为他们通常更倾向于设计 专门适合自己网站的用户界面控件。 因此，本规范选择 暂缓解决此方案的复杂问题， 直到确认作者确有需求。

6. 隐私 注意事项

本节为非规范性内容。

image-animation 属性允许跨源控制图像 动画， 而不会泄露图像实际上是否能够播放动画的任何信息。 计算值不会根据此信息发生变化。 running 值对动画图像 和静态图像 产生的效果在视觉上有所不同， 但页面本身无法观察到这些差异。

然而，:animated-image 伪类确实会泄露 元素所表示的声明式 图像是动画图像还是静态图像， 而页面原本无法跨源获知这一信息。 可以通过 CORS 对此加以限制， 但本规范选择不施加此类限制， 原因如下：

  • 此信息所能带来的额外收获并不多。

    • 目标 URL 是否存在图像 可能泄露有关用户的重要信息 （例如用户是否已登录某个特定域名）， 但这些信息已经可以通过图像尺寸获知， 而图像是否能够播放动画并不会显著增加这种风险。

    • 在实践中，网站极不可能被设计成 从同一 URL 同时提供静态图像和动画图像， 并根据某些依赖用户的私人信息 来选择提供哪一种，从而导致这些信息泄露。

  • 视频已经会共享类似的信息： HTML video 元素即使对于跨源视频也会公开时长。 静态图像可以说是时长为 0 的动画图像的一种特殊情况， 因此公开这一信息具有类似性质。

  • 目前有一项允许在 <video> 元素中使用图像的提案。 如果实现，这意味着情况将不仅仅是类似， 而且图像是否为动画图像本来就能够跨源获知。

此外，如果用户代理提供抑制图像动画的设置， 该设置与 :animated-image 伪类之间的交互 可能成为指纹识别信息的来源， 如相应章节所述。

一致性

文档约定

一致性要求通过结合 描述性断言和 RFC 2119 术语来表达。关键字“MUST”、 “MUST NOT”、“REQUIRED”、“SHALL”、“SHALL NOT”、“SHOULD”、“SHOULD NOT”、 “RECOMMENDED”、“MAY”和“OPTIONAL”在本文档的规范性部分中 应按照 RFC 2119 中的描述进行解释。 但为了便于阅读，本规范中的这些词语 并非全部使用大写字母。

除明确标记为非规范性的章节、 示例和注释外，本规范中的所有文本均具有规范性。[RFC2119]

本规范中的示例以“例如”一词引入， 或者通过 class="example" 与规范性文本区分开来， 如下所示：

这是一个资料性示例。

资料性注释以“注”字开头，并通过 class="note" 与规范性文本区分开来，如下所示：

注：这是一条资料性注释。

特别提示是采用特殊样式以引起注意的规范性章节， 通过 <strong class="advisement"> 与其他规范性文本区分开来，如下 所示： 用户代理必须提供无障碍替代方案。

一致性类别

本规范的一致性 针对三个一致性类别定义：

样式表
CSS 样式表。
渲染器
一种用户代理， 负责解释样式表的语义并渲染 使用这些样式表的文档。
创作工具
一种用户代理， 用于编写样式表。

如果样式表中使用本模块定义的语法的所有声明 均符合通用 CSS 语法以及本模块定义的各项 特性的独立语法， 则该样式表符合本规范。

如果渲染器除了按照 相关规范的定义解释样式表外，还能够通过正确解析 本规范定义的所有特性 并据此渲染文档，则该渲染器符合本规范。 但是，如果用户代理因设备限制 而无法正确渲染文档， 并不意味着该用户代理不符合规范。（例如，不要求用户代理 在单色显示器上渲染颜色。）

如果创作工具编写的样式表 在语法上符合通用 CSS 语法 以及本模块中各项特性的独立语法， 并满足本模块所述的样式表其他所有一致性要求， 则该创作工具符合本规范。

部分实现

为了使作者能够利用向前兼容的解析规则 指定回退值，CSS 渲染器必须 将其无法提供可用支持级别的任何 @ 规则、属性、属性值、关键字 以及其他语法结构视为无效（并适当地 忽略）。特别是，用户代理不得在单个 多值属性声明中选择性地忽略不受支持的分量值， 而接受受支持的值：如果任何值被视为无效 （不受支持的值必须如此），CSS 要求忽略整个 声明。

不稳定和专有特性的实现

为了避免与未来稳定的 CSS 特性发生冲突， CSS 工作组建议在实现 CSS 的 不稳定特性和专有扩展时遵循最佳实践。

非实验性实现

一旦规范达到候选推荐标准阶段， 就可以进行非实验性实现，实现者应该 对于能够证明已按照规范正确实现的任何候选推荐标准级别特性， 发布不带前缀的实现。

为了建立并维护 CSS 在不同 实现之间的互操作性，CSS 工作组要求非实验性 CSS 渲染器在发布任何 CSS 特性的不带前缀实现之前， 向 W3C 提交实现报告（必要时还应提交 该实现报告所使用的测试用例）。 提交给 W3C 的测试用例须经 CSS 工作组审查和修正。

有关提交测试用例和实现报告的更多信息， 可在 CSS 工作组网站上找到： https://www.w3.org/Style/CSS/Test/。 如有疑问，请联系 public-css-testsuite@w3.org 邮件列表。
