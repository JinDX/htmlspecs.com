摘要

本模块扩展了 CSS 尺寸属性，增加了表示基于内容的“内在”尺寸 和基于上下文的“外在”尺寸的关键字，使 CSS 能够更轻松地描述适应其内容或 适应特定布局上下文的框。本规范是相对于 CSS 尺寸第 3 级的增量规范。

CSS 是一种用于描述结构化文档 （例如 HTML 和 XML） 在屏幕、纸张等媒介上的渲染方式的语言。

3.2. 新的尺寸值：contain、fit-content() 和 calc-size() 值

CSS 尺寸 3 § 3.2 尺寸值： <length-percentage>、auto | none、min-content、max-content 和 fit-content() 值

第 4 级增加了在 尺寸属性中使用 contain、fit-content() 和 calc-size() 值的能力， 从而将 <box-size> 产生式扩展如下：

<box-size> = <length-percentage> | stretch | contain | min-content | max-content | fit-content | fit-content() | calc-size()
名称： width, height, min-width, min-height, max-width, max-height
新值： contain | fit-content(<length-percentage [0,∞]>)
fit-content(<length-percentage [0,∞]>)
使用 fit-content 公式， 但将可用空间替换为指定的参数， 即 min(max-content, max(min-content, <length-percentage>))， 其中 <length-percentage> 参数的解析方式 与独立出现的 <length-percentage> 值完全相同。

负的 <length-percentage> 值无效。

4. 纵横比

图像通常具有自然纵横比， CSS 布局算法会在调整元素大小时 尝试保持这一纵横比。

aspect-ratio 属性允许为非替换元素 指定这种行为， 并可更改替换元素的有效纵横比。

我们仍在完善 本节的细节。 如果这里指定的任何行为 会导致具有替换元素且具有首选纵横比的元素， 与在 CSS2、 弹性布局和 网格布局 规范共同要求下（不应用本规范时）的行为不同， 那么这是一个错误，应报告给 CSSWG。 这里有一份尚未关闭的 aspect-ratio 议题列表。

4.2. 首选纵横比对自动尺寸的影响

当一个框具有首选纵横比时， 它的自动尺寸 的计算方式与一个在该轴上没有自然尺寸、但具有自然纵横比的替换元素相同， 例如参见 CSS2 § 10 和 CSS 弹性框模型第 1 级 § 9.2。 首选尺寸计算 依赖此纵横比的轴 称为比率依赖轴， 如果其输入尺寸也是确定的， 则所得尺寸是确定的。 相反的轴（比率依赖轴的尺寸依赖于它） 称为比率确定轴。

注： 首选纵横比 只有在框的至少一个尺寸 是自动的时才会产生影响。 如果 width 和 height 都不是自动尺寸， 则它不会影响其首选 尺寸。

当我们把所有 尺寸信息移到这里， 而不是强行塞进 2.1 时， 核心原则就只是： 比率确定轴中解析后的首选尺寸 （在应用 min/max 之前） 会通过该比率传递。 min/max 约束随后再进行传递， 然后分别应用到各个轴，而不再考虑纵横比。

4.4. 最小/最大尺寸传递

任一轴 （origin 轴）中的尺寸约束 会通过首选纵横比传递， 并按如下方式应用于另一轴（destination 轴）中任何不确定的 最小、最大或首选尺寸：

  • 首先，任何确定的最小尺寸 都会从 origin 轴转换并传递 到 destination 轴。 此传递后的最小值受 destination 轴中任何确定的首选或最大尺寸 的上限限制。

  • 然后，任何确定的最大尺寸 都会从 origin 轴转换并传递 到 destination。 此传递后的最大值受 destination 轴中任何确定的首选或最小尺寸 的下限限制， 以及传递后的最小值（如果有）的下限限制。

注： 因此，任何确定的尺寸都完全不受 传递约束的影响； 传递后的最小值永远不会使元素超过确定的首选/最大尺寸， 传递后的最大值也不会使元素违反其首选/最小尺寸。

注： 基本原则是，尺寸约束 通过纵横比传递到另一侧， 在不违反受影响轴上任何显式指定尺寸的前提下， 尽可能保持纵横比。 （这也是形成 CSS2 第 10.4 节约束表内容的原则。）

在以下示例中： 
<div id=container style="height: 100px; float: left;">
  <div id=item style="height: 100%; aspect-ratio: 1/1;">content</div>
</div>

由于 #item 的高度是相对于确定容器解析的百分比， 因此无论是其内在尺寸贡献还是最终布局， 该项目的宽度都会解析为 100px， 所以容器的宽度也会确定为 100px。

<div id=container style="height: auto; float: left;">
  <div id=item style="height: 100%; aspect-ratio: 1/1;">content</div>
</div>

5.2.1. 上次记忆的尺寸

尺寸包含对于确保页面能够高效渲染非常有价值， 它限制了因元素渲染发生变化 而可能触发的布局工作范围。 然而，它对作者也有很强的限制， 要求作者正确预测元素的尺寸； 如果这个猜测不正确， 即使只差一点， 也可能导致难看的滚动条或内容被意外隐藏。

contain-intrinsic-size 的 auto 关键字提供了一种折中方案： 如果一个元素曾经不受尺寸包含约束， 此值会使元素记住其尺寸 （由布局按正常方式计算）； 随后，如果元素之后获得尺寸包含， 它就会使用记住的尺寸， 从而既获得尺寸包含的性能优势， 又很可能能根据其内容准确确定尺寸。

只有能够作为 ResizeObserver 目标的元素才能具有上次 记忆的尺寸。

元素的上次记忆的尺寸 按如下方式确定：

  • 在确定并传递 ResizeObserver 事件时， 如果一个元素在 contain-intrinsic-size 属性中具有 auto 关键字， 能够作为 ResizeObserver 目标， 但没有尺寸包含， 则将其主框当前的内部尺寸 记录为其上次 记忆的尺寸。

  • 在确定并传递 ResizeObserver 事件时， 如果一个元素具有上次记忆的尺寸， 但其 contain-intrinsic-size 属性中没有 auto 关键字， 则移除其上次记忆的尺寸。

注： 上次记忆的尺寸是附加在 元素上的状态， 而不是附加在该元素生成的某个特定框上。 只要元素在 contain-intrinsic-size 属性中保留 auto 关键字， 即使经历诸如切换到/从 display: none 这样的变化， 它仍会记住其上次记忆的尺寸。

5.2.2. 与 overflow: auto 的交互

contain-intrinsic-size 属性提供了对 作者预期元素内容大小的估计， 但这个估计不是真实内容， 也不代表需要向用户显示任何东西。 因此，具有 overflow: auto 的元素不得因为 contain-intrinsic-size 而生成滚动条。

但是，如果 contain-intrinsic-size 表明一个足够大的尺寸， 使得元素若实际包含该尺寸的内容时会生成滚动条， 那么应当按照这种假设内容， 将元素的尺寸确定为仿佛它生成了这些滚动条。

在以下示例代码中： 
div {
  width: max-content;
  contain-intrinsic-size: 100px 100px;
  overflow: auto;
}

元素最终的宽度为 100px，高度为 100px： contain-intrinsic-size 提供了 max-content 宽度， 以及高度。

如果元素随后具有高度为 150px 的内容， 它会显示垂直滚动条； 如果滚动条不是叠加式的， 它会占用这 100px 宽度中的一部分， 从而为内容流动留下更小的空间 （通常大约为 84px）。 （参见 CSS 溢出 3 § 4 滚动条与布局。）

即使现在可用于内容的水平空间少于 100px， 也不会仅仅因为 contain-intrinsic-size 指示了 100px 的宽度就生成水平滚动条； 只有当实际内容 包含不可断开的部分 且其宽度大于剩余空间时，才会发生这种情况。

相比之下，在以下示例代码中： 
div {
  width: max-content;
  contain-intrinsic-size: 100px 100px;
  height: 50px;
  overflow: auto;
}

元素具有固定的 50px 高度， 但 contain-intrinsic-size 指示了 100px 的“估计内容高度”。 因此，元素假定在填充实际内容时 它将需要一个垂直滚动条， 从而得到一个略大于 100px 的 max-content 宽度 （通常大约为 116px）， 以容纳由 contain-intrinsic-size 估计的 100px max-content 宽度， 以及垂直滚动条的宽度（通常大约为 16px）。

但是，即使元素基于需要滚动条的假设预留了空间， 它也不会真的生成滚动条， 除非实际内容发生溢出： 如果最终包含的内容高度低于 50px， 则完全不会生成垂直滚动条， 但元素仍然会有 116px 宽。

一些替换元素可以包含“普通”的流式内容， 例如 HTML iframe。 出于隐私和安全原因， 默认情况下，这些元素 不会向外部页面暴露任何有关其内部内容尺寸的信息， 而是仅使用一个静态的、预先确定的内在尺寸， 并使其内容可滚动。 frame-sizing 属性 允许这些元素选择暴露其实际内容尺寸， 该尺寸称为其内部布局内在尺寸。 各值含义如下：

content-height
content-block-size
content-inline-size

当嵌入文档具有以下 HTML 时： 
<meta name="responsive-embedded-sizing">
<div style="height: 500px"></div>

并且嵌入它的文档具有以下 CSS：

iframe {
  frame-sizing: content-height;
}

iframe 的高度最初会是默认的 iframe 高度（通常为 150px）， 但在 iframe 的文档加载后会更新为 500px。

此外， 内部文档可以调用 window.requestResize() 以在之后更新其内部布局内在尺寸。

5.3.1. HTML iframe 详细信息

在 HTML 中，只有 iframe 元素可以具有内部布局内在尺寸， 并且只有当 iframe 的嵌入文档以适当方式选择启用时才可以。

HTML Document 对象 关联有一个响应式嵌入尺寸标志， 其初始状态为未设置。 在文档初始解析期间， 根据以下哪种情况最先发生， 将其设置为 true 或 false：

  • 如果遇到 <meta name=responsive-embedded-sizing> 元素， 则将其设置为 true。

  • 如果 body 元素被打开（显式或隐式）， 或由解析器插入文档， 则将其设置为 false。

一旦设置为 true 或 false， 在该 Document 的整个生命周期内，该标志的值都不会再次更改。

注： 目前，HTML meta 元素出现在 HTML 文档的 head 中， 是嵌入文档在 HTML 中选择启用此功能的唯一方式。 这意味着 iframe 中的 SVG 文档无法这样做。

注： 由于 HTML 解析器的一些特殊行为， meta 元素在技术上可以出现在 head 和 body 元素之间， 并会被重新设为 head 的子元素。 对于 <meta name=responsive-embedded-sizing> 元素来说，这仍然是有效位置， 因为此时 body 尚未被打开。 请注意，大多数 HTML 元素都会隐式打开一个 body 元素， 即使 body 起始标签并不存在； 如果文档完全缺少这样的元素， 则会自动生成并插入一个空元素。

内部布局内在尺寸首先根据 嵌入文档在触发 DOMContentLoaded 事件之后的第一次布局结果来设置， 并在 load 事件于 Window 上触发时再次设置。 嵌入文档后续的内容、样式或布局变化 不会自动影响内部布局内在 尺寸， 但请参见 requestResize()。

嵌入文档还可以具有一个锁定的嵌入 ICB 尺寸， 其初始值为 null。 如果文档在执行布局时，其响应式嵌入尺寸标志为 true， 且其锁定的嵌入 ICB 尺寸为 null， 则会将其当前初始包含块尺寸记录为其锁定的嵌入 ICB 尺寸。 在后续布局中， 它会使用其锁定的嵌入 ICB 尺寸， 而不是按正常方式计算其初始包含块尺寸。

注： 这种对 ICB 的冻结 降低了出现布局循环的可能性 （例如 iframe 文档的尺寸略大于其 ICB， 然后父 iframe 调整尺寸以匹配， 下一次布局又使其略大于 ICB， 如此无限循环）。

我们是否需要提供一种方式 强制 iframe 忘记其锁定的嵌入 ICB 尺寸？ 也许可以关闭再重新开启 frame-sizing？

导航 iframe 的文档 会使它忘记其锁定的嵌入 ICB 尺寸。 只要新文档的响应式嵌入尺寸标志尚未设置， 它就不会忘记其内部布局内在尺寸。 一旦标志被设置（无论为 true 还是 false）， 内部布局内在尺寸就会被遗忘； 如果标志被设置为 true， 则两者之后都会按正常方式重新计算。

5.5. 将 Min-Content 尺寸贡献归零：min-intrinsic-sizing 属性

名称： min-intrinsic-sizing
值： legacy | zero-if-scroll || zero-if-extrinsic
初始值： legacy
适用于： 除行内 框之外的所有元素
继承： 否
百分比： 不适用
计算值： 按指定值
规范顺序： 依语法而定
动画类型： 离散

此属性非常 需要重新斟酌名称。

此属性定义非替换框的min-content 贡献 是否会在特定情况下被“压缩”。 各值含义如下：

legacy
框的min-content 贡献 按正常方式处理。
zero-if-scroll
如果框在该轴上是滚动 容器， 则框的min-content 贡献 会被“压缩”。
zero-if-extrinsic
如果框具有一个外在的 首选或最大尺寸， 则框的min-content 贡献 会被“压缩”。

注： 这是大多数替换元素的默认行为。

以下规则会使所有滚动 容器 在向上传递其尺寸贡献时 基本忽略其内容 （除非它们明确请求了基于内容的尺寸）： 
*, ::before, ::after { min-intrinsic-sizing: zero-if-scroll; }

如果滚动容器包含表格或很长的不可断开文本行等大型项目， 这可以防止它把祖先元素的尺寸撑大。 同时，它允许非滚动容器的框 继续影响其祖先的min-content 尺寸。

注： zero-if-scroll 的行为本来会是更好的 默认值， 但由于 Web 兼容性问题，它不能作为初始值。:(

“压缩后”的min-content 贡献 通过假装框为空来计算， 但在考虑由显式的 min-content、max-content 和 fit-content 值 对尺寸属性施加的尺寸约束时除外。

5.6. 新的列尺寸值：stretch、min-content、max-content、fit-content 和 fit-content() 值

名称： column-width
新值： <box-size>
计算值： 按指定值，其中 <length-percentage> 值会被计算
动画类型： 按计算值类型

当作为 column-width 的值使用时， 这些新关键字指定最佳列宽：

stretch
将最佳列宽指定为多列容器的stretch-fit 行内尺寸。
min-content
将最佳列宽指定为多列容器内容的min-content 行内尺寸。
max-content
将最佳列宽指定为多列容器内容的max-content 行内尺寸。
fit-content
将最佳列宽指定为 min(max-content 行内尺寸, max(min-content 行内尺寸, stretch-fit 行内尺寸))。
fit-content(<length-percentage>)

6.1. Contain-fit 尺寸确定：在保持纵横比的同时拉伸

Contain-fit 尺寸确定本质上应用 stretch-fit 尺寸确定， 但会减小框在一个轴上的尺寸， 以保持框的首选纵横比， 类似于 contain 关键字在 object-fit 和 background-size 属性中的行为。

首先，确定一个目标矩形：

  1. 初始目标矩形的尺寸为框的包含块尺寸， 任何不确定尺寸都假定为无穷大。 如果两个维度都是不确定的， 则初始目标矩形被设置为 与该框在进行stretch-fit 尺寸确定时的外边缘相匹配。
  2. 接下来，如果框具有非 none 的 max-width 或 max-height， 则目标矩形在受影响维度上会被限制为 小于或等于框的外边距框的“最大尺寸”， 即如果框按其 max-width/height 进行尺寸确定时， 其外边距框所具有的尺寸。 （请注意，与正常的框尺寸确定 规则一致， 此“最大尺寸”的下限受到框的 min-width/min-height 的影响。）
  3. 最后，目标矩形会在一个维度上缩小 到使其与框的首选纵横比匹配所需的最小程度。

每个维度上的 contain-fit 尺寸 是将框通过 stretch-fit 方式适配到目标矩形后得到的尺寸。

    此外，任一轴中的尺寸约束 （origin 轴） 会通过首选纵横比 按如下方式传递到另一轴（destination 轴）：

    • 首先，任何确定的最小 尺寸都会从 origin 轴转换并传递 到 destination 轴。 此传递后的最小值受 destination 轴中任何确定的首选或最大 尺寸的上限限制。

    • 然后，任何确定的最大 尺寸都会从 origin 轴转换并传递 到 destination。 此传递后的最大值受 destination 轴中任何确定的首选或最小 尺寸的下限限制， 以及传递后的最小值（如果有）的下限限制。

    对于外边距折叠（CSS 2 § 8.3.1 折叠外边距）， 如果块轴是比率依赖轴， 则不认为它具有计算后的 block-size 值 auto。
